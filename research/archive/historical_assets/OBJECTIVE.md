# OBJECTIVE.md — LoveBrain 斗兽场目标书 v1.4

## v1.4 变更（2026-10-23，配套 AGENTS v1.4 + rubric v0.5）

- **成本 / 时延 / 污染 / 可维护性恢复为并列门禁**：v1.2/v1.3 时期"成本只记账不进门"
  的历史选择保留在本文件作为沿革，但本轮用户明确"回复更好 + 污染更少 + 更省 token +
  等待更短 + 维护更容易"五个目标共同判决；均分微升但严重问题/污染/成本明显增加
  **不算整体更好**（协议 §6 + fair_baseline §5）。
- **协议变更 ≠ 候选收益**：任何 rubric 修订（如 v0.5 note_lcs max(len) + 0.6 阈值 + 短文本
  豁免）必须单独版本化并用旧答卷离线重评；不得据程序分自然抬升宣布候选改进。
- **首选与备选分审落到指标**：主槽合格率、至少一个合格候选比例、含严重问题备选比例
  三个数字独立报告，一个好备选不能掩盖坏首选。

## 总目标（v1.3 重申 + v1.4 并列门禁）

**在代表性的连续聊天题库上，训练出优于 LoveBrain 原版内置 harness 的新 harness。**

- **参赛对象**：一个完整 harness 版本——提示词＋知识库＋记忆存取＋检索＋意图处理＋
  上下文组织＋调用策略。不是"某个 API"，也不是"某句提示词"。
- **API 的角色**：dsf 端点（`http://127.0.0.1:17770/v1`，model `dsf`）是各 harness
  共用的模型服务。同批比较固定端点/model/采样；**换更强模型不算 harness 进步**。
- **评估对象**：最终回复质量与后续行为（用户只关心这个）。
- **训练对象**：harness 的组织逻辑——记忆怎么存、怎么取、意图怎么处理、输入怎么组织。
  机制 >>> prompt 措辞；但提示词也是 harness 的一部分，允许改，只是不许当唯一手段。
- **知识库的定位**：它是 harness 的内部组织方式，**不是独立评估对象**；KB 内部分析仅用于
  失败归因诊断（rubric §4）。
- **意图**：部分题目带用户意图（调情/邀约/安抚/收尾……），回复必须与意图对齐（C10）。

### 优化责任（v1.3 新增，不可回避）

在**模型/采样、题面、评分口径固定且调用正常**的有效答卷上，
**质量缺陷一律归 harness 待解决**：不得以"API 不行"搪塞，不得偷偷换强模型冒充进步。
传输中断、超时、预算/账本异常等**工程事故另立账目**，不计入回复质量，也不当借口。

### 主线（唯一）

```text
原版 LoveBrain 基线评测 → 连续题找低分故障族 → 修改 harness 机制
  → 同题/同评分/同模型 新旧同场比较 → 证明整体优于原版且无明显退化
  → 扩题并用独立题验收泛化
```

首批 24 位只是启动这条循环的 pilot；题库目标仍是几百个请求位组成的多条连续生活故事。

一句话：在事实与意图不失真的前提下，帮助用户以自己的表达方式，生成适合当前关系和当下情境、
愿意实际发送的话；同时正确维护后续会用到的状态，并把成本控制在预算内。

四个独立验收的产物（v1.2 起输出契约可由候选重定义，唯一硬约束：可发送候选总数 ≥8）：
①候选话术（默认 4 风格，可扩）②方向建议（默认 4 条，可扩）③analysis 与记忆变更 ④下一轮实际行为。

## 首战故障族（按用户痛感排序）

1. **三元组混淆**（F1）：《她》《我》《想法》分不清；"军师：我想回复…"被当成她的话。
2. **调情缺失**（F4.1/F4.3）：回复单调平淡，无推拉张力，四风格趋同。
3. **记忆机制**（F3/F5.1）：N=2 截断 vs 完整交流单元/检索式记忆的对照实验。
4. **话题污染**（F2）：旧话题无依据侵入新话题。

## 成长阶梯（v1.4 并列门禁）

- **幼体**：层 1 门禁全过，A 线开发集均分 ≥ 6.0
- **成体**：开发集 ≥ 8.0 且已知故障回归全过，盲评对基线净胜
- **怪物**：选择集盲评显著优势 + B 线封存验收 ≥ 8.0 + pass³（关键题连跑 3 次全过）+ **记忆污染率 ≤ 10%**（stale 探针，v1.2 新增，阈值 pilot 封板时复核）
- **终态**：用户小范围实测愿意真实发送；题库与指标开源

**v1.4 补充**：阶梯不覆盖严重退化。任一档晋级同时须满足：
- 严重错误（错人 / 编造已发生 / 明确禁止的私有信息泄漏 / 已取消事项复活）不增加；
- 全链 token 与 p95 时延不显著劣化（预登记可接受幅度，未预登记默认"不劣化"）；
- 主槽合格率不被"多产出备选"稀释（好备选不能掩盖坏主槽）。
某项收益换某项代价 → 报告交易，交用户裁定，不自动冠军。

## 关键边界

- 永远保守/永远"慢慢来"的系统同样失分（应主动场景不主动 = 缺陷）。
- 「推荐」是选择结果不是第五种风格；多样性只在合格候选上计算。
- 模拟"她"的积极回应当不得真实恋爱效果。
- 网页 judge 投喂合规：禁止 GT/隐私出站。

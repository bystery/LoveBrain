# 端到端分段计时：接入正式链路的现状与待你批准的一件事

2026-10-25。能力件：`arena/lb_stream_timing.py`；离线验证：`tools/test_stream_timing.py` **15/15 PASS，real_model_calls=0**；
执行器回归：`tools/exam_interleave_plan.py --all` **13 项全 PASS**（改动未破坏冻结链路）。
本文件只讲测量，不讲候选好坏；真实分段数字**尚未产生**，不能拿能力当提速证据。

## 1. 记了哪些段（口径与你的表一致）

| 段 | 含义 | 关键口径 |
|---|---|---|
| `pre_request_ms` | turn_start → 请求真正发出 | 取状态、装配、序列化、必要 IPC；冷启动单列，不藏在总耗时里 |
| `headers_ms` | 请求发出 → 收到 HTTP 头 | **不是**首 token，也不是纯模型排队 |
| `first_content_ms` | → 第一个**非空文本 delta** | role-only delta、心跳（`:` 行）、空行都不算首内容（已写成测试） |
| `first_preview_ms` | → 缓冲区里第一次出现完整的 recommended 字符串字面量 | 增量扫描，不 eval、不修补、不猜缺失括号；转义按 JSON 还原 |
| `first_usable_ms` | → 该文本**经消费校验判为可发送** | 没有验证器时诚实退回 `completion_ms` 并标 `requires_full_payload=true` |
| `last_content_ms` / `completion_ms` | 最后内容 / 响应读完 | 末尾结算不混作"还在产出" |
| `all_ready_ms` | 全部可发选项解析+规范化完成 | 完整答卷端到端 |
| `persisted_ms` | 状态与审计落盘完成 | 与"可显示"解耦时两个都记，不掩盖失败 |
| 一致性自检 | `StreamTimer.sanity()` | 段间单调、无负值；违反就报问题而不是悄悄丢弃 |

## 2. 落盘位置（一处最小改动，不重建平台）

`arena/lb_gateway.py` 的成功记录新增一个 `timing` 字段（无测量时为 `null`），
分段随之进入每位的 `calls.json`；出站请求体仍然只能由 `api_candidate.build_request_body` 构造，
`stream=true` 在白名单内，越界通道照旧直接 `BoundaryViolation`。

## 3. 需要你批准的一件事（我不擅自扩白名单）

流式要在最后一个分片拿 `usage`，OpenAI 兼容口径需要多发一个 **`stream_options`**。
它**不在** `REQUEST_BODY_ALLOWED_KEYS` 里，测试已确认：手工塞进去会被构造侧当场拒绝。

| 选择 | 得到什么 | 代价 |
|---|---|---|
| A 扩白名单加 `stream_options` | 同一批里同时拿到分段等待**和**真实 usage（费用列完整） | "实际 API 配置"变更，必须版本化；与已付费的 144 次非流式结果**不能合并成同一张性能表**，只能作为新的配置身份另列 |
| B 不扩，流式不发 `stream_options` | 分段等待能测，边界零改动 | 该批 usage 缺失 ⇒ 费用列只能记 `unavailable_in_stream`，**不许填 0、不许用字符估**，等于该批不能当费用可比批用 |
| C 不流式（现状） | 与前 144 次完全同配置、可比 | **永远拿不到** first_content / first_usable；"用户等多个字才能发第一条"这一核心体验问题只能继续空着 |

我的建议是 **A**：这条指标本身就是你要的"首个可发送回复"，非流式测不出来；
但 A 必须同时宣布"流式批次是新的 API 配置身份"，正式对照要两臂都在同配置下重跑，
不与旧批数字拼接。B 可作为一次性的纯等待探针（少量调用），C 保持默认不变。

## 4. 仍然没有的东西（不假装）

- 144 次已付费答卷**无法**回溯出分段：当时只有整体完成耗时。历史结论里的等待仍是完成耗时口径。
- 真实超时率与崩溃率需要长尾与畸形响应；夹具只证明"消费器不崩"，不是发生率。
- 尾延迟成因（排队/推理/传输）在没有分段证据前**不猜**——v5 的 p95 +26.95% 至今只是观测值。
- 语义/口味可用率（W 列）等你的 16 组标定回收；AI 不代投。

## 5. 现在能不能跑正式对照

技术上一句 `--stream-timing` 就绪（适配器与记录字段都在），
但按 §3 需要先定 A/B/C；同时按评估基准工作包，事实分级、信息不足、归属三个评审维度
还没过自检线（83.3% / 62.5–87.5% / 33–50%）。这两件事都不解决就跑 192 次，
只会再次得到"资源数字硬、质量判决虚"的结果。

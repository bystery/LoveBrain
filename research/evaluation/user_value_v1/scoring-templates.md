## 0. 评审代理通用约束（每个评审任务的前置指令，v1.1 版）

1. 你只收到：匿名输出（标签 A/B 或单提交）、原始聊天记录、用户目标、冻结的案例约束与锚点规则。你不知道也不得推测输出来自哪个臂；猜测即判分无效。臂映射总账（`anon-map.json`，`ledger_only:true`）评审侧禁读。
2. **必引原文要求（全模板通用）**：每个判定必须引用输出原文一句话作理由（指出哪句话满足/违反了哪条约束）；无引用的判分无效。
3. 只输出 JSON，不输出其他文字。
4. **unjudgeable 规则（全模板通用）**：无法判分（语义不确定、约束与输出对不上、输出为空或跑题）→ 写 `unjudgeable: true` 并给原因；unjudgeable 同时退出分子与分母并单列；禁止把无法判分强行算对或算错。
5. 逐条核对冻结约束，禁止凭整体印象打分。
6. 你是原生子代理代理评委，判分对象是文本，不是真人调查；判分结果带 `judge_identity`。
7. **【v1.1 新增】多候选读取义务**：评审 M1/M3/M5 时必须读取提交中的**全部可发送候选**——多通道形态读取 `response.recommended` + 全部风格槽（非空）+ 全部 `directions`（非空）；单通道形态只有 1 条候选，如实标注 `candidate_count:1`。候选清单与总数随判分落盘（`candidate_inventory`）。包裹格式差异不参与评判；缺少协议字段不得算"回复不自然"（沿用 v1.0 §1.6）。
8. **【v1.1 新增】反重复计分**：同一处错误只判一次；跨指标引用同一判定时写 `same_verdict_ref` 指向首次判定落盘记录，并标注"同源判定"。不得把同一错误在 M3 严重错误族、M5 备选严重错误率、M4 关系分寸 0 分中重复计为独立新证据（用户纠偏决策（2026-11-13） §五.4：不拿同一错误重复计算多个优势）。
9. **【v1.1 新增】防长度/数量偏**：不得因回复更长、候选更多、姿态更主动而偏好任何一方；比较裁决的决定理由若仅为长度或数量差异 → 改判平局（rubric_v0_6_draft §6 防长度偏、rubric v0.5 "回复长短不是独立扣分项" 沿用）。

## 1. M1 长程事实正确使用

评审指令要点：对照冻结 `must_use_facts` 逐条核对**每个可发送候选**（§0.7）。判三件事：该用的事实用没用、用得对不对、归没归对人。角色混淆（把事实归错人、归错时间、把对方的事说成自己的）计 `used_wrongly`。已发生动作的虚构判罚归 M3 严重错误族（此处发现时只引用、不改判，`same_verdict_ref` 留痕）。

每事实每候选终值枚举：`used_correctly`（正确使用了该事实且归属正确）/ `used_wrongly`（引用了该事实但内容错误或归属错误）/ `not_used` / `unjudgeable`。

```json
{
  "case_id": "uv1-E1-003",
  "output_label": "A",
  "candidate_inventory": {"candidate_count": 5, "slots": ["recommended", "style:gentle", "style:humor", "direction:1", "direction:2"]},
  "candidates": [
    {
      "slot": "recommended",
      "is_primary": true,
      "per_fact": [
        {"fact_ref": "TPL：E340_T10_A00", "fact": "TPL：汇演定在 11 月 29 日周日", "verdict": "used_correctly", "quote": "TPL：输出原句"}
      ],
      "fact_qualified": true
    },
    {"slot": "style:humor", "is_primary": false, "per_fact": ["…同结构…"], "fact_qualified": false}
  ],
  "at_least_one_qualified": true,
  "irrelevant_misuse": [
    {"fact": "TPL：对方养的猫叫毛毛", "quote": "TPL：输出原句", "from_current_message": null}
  ],
  "unjudgeable": false,
  "unjudgeable_reason": null,
  "reason_quote": "TPL：题级主判理由引用的输出原句",
  "judge_identity": "TPL：原生子代理实例标识"
}
```

统计规则（三项分列，禁止混用；rubric v0.5 §4"一个好备选不能掩盖坏首选"）：

1. **首选事实级正确使用率**（主判，延续 v1.0 口径保证对称重评可比）= 首选 `used_correctly` 数 / (应使用事实总数 − unjudgeable 数)，事实级聚合；应使用事实以登记表 `must_use_facts` 为基线（预登记 31 条），评审可校正"该轮确实需要使用"属性、校正须留痕。
2. **首选题级合格率**（v1.1 新增）= 首选对全部应使用事实零 `used_wrongly` 的题数 / 适用题数。
3. **至少一条合格候选率**（v1.1 新增）= 存在 ≥1 条事实合格候选（含首选）的题数 / 适用题数。合格候选 = 该候选全部应使用事实零 `used_wrongly`。

辅助指标（不进主比率）：题级全对率；`irrelevant_misuse` 次数跨输出累计单列（含程序化层 `from_current_message=true` 标记，交语义层裁决，沿用 v1.0）。

**必引原文要求**：每条 `per_fact` 判定必须带输出原句 `quote`；题级 `reason_quote` 必引；候选判 `fact_qualified=false` 时必须指出具体错在哪个事实哪一句。

**平局与不可判规则**：unjudgeable 事实同时退出分子与分母并单列（沿用 v1.0）；候选整体空输出/跑题 → 该候选退出指标 2/3 的分母并单列；比较层两臂同率 → 记 `tie`，不硬分胜负，不制造"微弱优势"。

**与 v1.0（E1）的差异清单**：
| # | v1.0 | v1.1 |
|---|---|---|
| 1 | 只评主建议（recommended） | 评全部可发送候选（recommended+风格槽+directions） |
| 2 | 只有事实级主比率 + 题级全对率辅助 | 新增首选题级合格率、至少一条合格候选率，三项分列 |
| 3 | 角色混淆未显式定义 | 角色混淆显式并入 `used_wrongly` |
| 4 | 虚构已发生动作在 E1/E3 边界模糊 | 明确移交 M3 严重错误族，此处同源引用 |

## 2. M2 纠正与旧事抑制双成功（M-PAIR 采纳）

评审指令要点：每个适用题实例化 **M-PAIR 记忆双门**——recall 门（记住最新）与 suppress 门（不错误复活已取消）。**只有双门同时通过才得分，`pair_score = min(recall, suppress) ∈ {0,1}`，任一门失败即 0 分，不作半分**——两种失败都是能力缺陷而非程度差异（rubric_v0_6_draft §1）。

**明示采纳声明（用户纠偏决策（2026-11-13） §三 M2 原文）**：M-PAIR 双成功思路来自既有草案 `rubric_v0_6_draft.md` §1，本次作为 v1.1 新版标准**明示采纳**；v1.0 E2 未采用该结构与命名，不得宣称旧版已实现。

**门定义（映射冻结登记表字段，不新增金标字段）**：
- recall 门 = 输出（首选）正确使用 `latest_valid_state.fact`；
- suppress 门 = 输出（首选）不含 `latest_valid_state.invalidated[]` 中任何已作废信息（含旧事实诱饵），且不复活已取消/已完成事项（`closed_or_pending` 场景）；
- "suppress 语境必须与旧事无关"的题级核对归激活检查表（protocol-v1.1-addendum.md §5 条件②），评审侧只判输出是否复活，不判题面好坏。

```json
{
  "case_id": "uv1-E2-007",
  "output_label": "B",
  "pair_id": "uv1-E2-007",
  "recall_gate": {"passed": true, "quote": "TPL：使用最新状态的原句"},
  "suppress_gate": {
    "passed": false,
    "violations": [
      {"invalidated_fact": "TPL：观影时间=周六晚", "quote": "TPL：复活旧事实的原句"}
    ]
  },
  "pair_score": 0,
  "unjudgeable": false,
  "unjudgeable_reason": null,
  "reason_quote": "TPL：主判理由引用的输出原句",
  "judge_identity": "TPL：原生子代理实例标识"
}
```

统计规则：**主判 = 首选 `pair_score==1` 的题数 / 适用题数**（题级）。适用测试 = 题面确有状态更新且两臂均完成生成（沿用 v1.0）。uv1-E2-001 的 `latest_valid_state.fact` 以 episode feedback 口径登记，评审可校正、校正须留痕（notes §7.5，沿用 v1.0）。**分门结果（recall 通过率、suppress 通过率）分别单列作诊断，不得替代 pair_score 作主判**——防 v0.6 根因复现（纯否定式 suppress 单独计分会把"毫无记忆"评成满分）。备选候选的复活判罚由 M3 错误族④捕获（供 M5 备选严重错误率引用，同源判定）；M2 主判只评首选。

**有效性自检（联动 addendum §4，批量前必须通过）**：无记忆负对照 → recall FAIL → pair 0；全量复述（无差别历史注入）负对照 → suppress FAIL → pair 0；正确记住并抑制的方法 → pair 满分。三类必须分离；不分离即量尺无效，停止批量。

**必引原文要求**：recall 门判定必须引用使用最新状态的原句；suppress 门失败必须引用复活旧事实的原句；双通过时 suppress 门引用逐条诱饵核对说明 + recall 原句；`reason_quote` 必引。

**平局与不可判规则**：`latest_valid_state` 为 null 或语义无法定 → 该题 M2 `unjudgeable`，退出分子分母单列；输出空/跑题 → 同上；比较层两臂 pair 全通过率相同 → 记 `tie`，不硬分胜负。

**与 v1.0（E2）的差异清单**：
| # | v1.0 | v1.1 |
|---|---|---|
| 1 | 单一布尔 `test_pass`（latest 用对 且 无作废复现），分门结果不落盘 | 显式双门结构 `pair_score=min(recall,suppress)`，分门判定逐一落盘、可诊断失败类型 |
| 2 | "双成功"未命名结构、无采纳声明 | 明示采纳 M-PAIR（rubric_v0_6_draft §1），注明非旧版已实现 |
| 3 | 无负对照有效性自检 | 新增三类候选分离自检，不分离停止批量 |
| 4 | 备选候选不评（无复活扫描） | 首选归 M2；备选复活由 M3 错误族④捕获、M5 备选严重错误率引用 |
| 5 | suppress 仅核对 `invalidated` 列表 | 语义不变（仍以冻结 `invalidated[]` + 已取消/完成事项为准），语境无关性核对归激活检查表，不新增金标字段 |

## 3. M3 未确认事实与隐私边界

评审指令要点：对**每个可发送候选**（§0.7）逐主张核对；**评审单位 = 主张 × 输出位置**（JUDGE_MANUAL_V1_1 §1）。每条主张按四轴记录，按组合规则定判——**核心是区分"玩笑/新提议"与"声称已发生"**：只有把未证当已证才是问题。

**四条独立轴**（JUDGE_MANUAL_V1_1 §2 沿用）：
- **A 陈述类型**：`事实`（已发生/已有/已约定/可核验现场）｜`类指常识`｜`新提议`（未来动作、邀请、我来办）｜`玩笑/夸张/反问/隐喻`｜`观点/倾向/感受`｜`疑问`｜`不确定表达`（承认没准、要去查）
- **B 证据状态**（相对当时可见输入）：`支持`｜`冲突`（写清是哪条）｜`未提供`｜`不适用`（提议/玩笑/疑问本不需要既成证据）
- **C 陈述姿态**：`确定`｜`有条件`｜`试探`｜`承认未知`
- **D 影响严重度**：`关键`（会误导实际安排、替人决定、把别人的话当她的、否认可核验既有约定）｜`次要`（夸张、玩笑、风格化补白）｜`无`

**组合规则（判定关键，MANUAL v1.1 §2 原文沿用）**：
1. 类型=事实 且 姿态=确定 且 证据=未提供/冲突 ⇒ **无据断言**，严重度按会不会造成行动误解判关键/次要——主要问题形态。
2. 类型=事实/常识 且 证据=未提供 但 姿态=有条件或承认未知 ⇒ **合格处理**，不记缺陷。
3. 类型=新提议/玩笑/观点/疑问 ⇒ 证据列填 `不适用`，**不因"历史没说过"判编造**；只在冒称已发生/已同意/已拥有时改判事实类。
4. 类指常识被说成这一次的现场结论 ⇒ 无据断言；以常识口气给出且不构成安排依据 ⇒ 次要，不清零该候选。
5. 未定事项以玩笑/新提议口气带过 = 合格；坐实成已发生 = `unknown_as_certain`。
6. 输入未给 ≠ 现实为假：不许因后面剧情恰好如此追认前面的自信说法，也不许把"我记得不是"当有出处发正。

**严重错误族（M3 口径，供 M5 备选严重错误率引用）**：
| 族 | 定义 | 来源 |
|---|---|---|
| ① `fabricated_action` | 冒称已发生：编造已发生安排/动作（未订票说"票我订好了"） | v1.0 类型枚举沿用 |
| ② `unknown_as_certain` | 未定坐实：把未确定写成已确定/已发生（关键级才入族；次要级记录不判死） | v1.0 沿用 + MANUAL 组合规则 |
| ③ `private_leak` | 私密泄漏：泄露用户私人备注 | v1.0 沿用 |
| ④ `revived_cancelled` | 已取消/已完成事项复活（首选判定归 M2 suppress 门；备选由本指标扫描捕获，`same_verdict_ref` 引用） | rubric v0.5 严重错误族 |
| ⑤ `claimed_relationship_assert` | 替用户声称已发生的关系状态（替用户表白、替用户承诺已发生） | MANUAL v1.1 归属四问 |

**合格处理（不记缺陷，MANUAL v1.1 §1/§3 沿用）**：新提议/玩笑/观点/疑问（证据不适用）；有条件/承认未知姿态；情绪承接不因没追问资料判不合格；不要求医疗/结果性保证，不把"我不确定"写成缺陷；轻松认领被评价、反问、就事论事、玩笑带过均合法；转述不要求逐句口头澄清，禁止的是把传递人当来源、把她没说的意愿当已同意。合法 `no_reply` 不算缺陷。

```json
{
  "case_id": "uv1-E3-005",
  "output_label": "A",
  "candidate_inventory": {"candidate_count": 3, "slots": ["recommended", "style:playful", "direction:1"]},
  "candidates": [
    {
      "slot": "recommended",
      "is_primary": true,
      "claims": [
        {
          "quote": "TPL：票我已经订好了",
          "axis_type": "fact",
          "axis_evidence": "conflict",
          "axis_stance": "certain",
          "axis_severity": "critical",
          "error_family": "fabricated_action",
          "constraint_ref": "TPL：must_not_assert[0]=已订票"
        },
        {
          "quote": "TPL：要不周六我带你去后摇现场？",
          "axis_type": "proposal",
          "axis_evidence": "not_applicable",
          "axis_stance": "tentative",
          "axis_severity": "none",
          "error_family": null,
          "constraint_ref": null
        }
      ],
      "severe_error_family_hit": true,
      "candidate_severe_clean": false
    }
  ],
  "test_pass": false,
  "unjudgeable": false,
  "unjudgeable_reason": null,
  "reason_quote": "TPL：主判理由引用的输出原句",
  "judge_identity": "TPL：原生子代理实例标识"
}
```

统计规则：① **首选通过率**（主判）= 首选零严重错误族命中的题数 / 适用题数；② **备选严重错误率**（v1.1 新增，越低越好，单列）= 存在含严重错误备选的题数 / 适用题数（rubric v0.5 §4 `backup_with_severe_error`）；③ **全组零严重错误率**（v1.1 新增，辅助）= 全部可发送候选均零严重错误的题数 / 适用题数。次要级问题逐条记录、不计入严重错误族、不清零候选；`test_pass` = 该候选零严重错误族命中（主判按首选）。每题 `must_not_assert` 仍为判定依据基线；程序化词表（`score_e123.py` 的 FABRICATED_ACTION_LEXICON、private_leak 词表、unknowns 探测词）继续承担初筛，语义终判按本模板四轴（"关键词法只用于初筛，语义判定以人工或校准评委为准"，rubric v0.5 §3 沿用；词表增删按 protocol-FROZEN.md §8.3 对全体比较臂对称重算）。

**必引原文要求**：每条命中必须 `quote` 输出原句 + `constraint_ref` 指出违反哪条约束；四轴每轴的取值须能在原句中找到对应措辞依据；"合格处理"的抽查记录同样引用原句。

**平局与不可判规则**：单条主张语义无法定 → 该主张 `unjudgeable`（该主张退出该候选统计，不牵连整候选）；候选空/跑题 → 候选 unjudgeable 退出②③分母；某候选缺金标（`must_not_assert` 为空的题）→ 该题 M3 UNRATED，不记满分（gold 缺席诚实登记，rubric v0.5 §2 沿用）；比较层两臂首选通过率相同 → 记 `tie`。

| # | v1.0 | v1.1 |
|---|---|---|
| 1 | 只评主建议 | 评全部可发送候选；新增备选严重错误率、全组零严重错误率 |
| 2 | 类型词表逐条命中即记错误 | 四轴主张级组合判定；词表降为初筛；评审单位=主张×输出位置 |
| 3 | 未写玩笑/新提议豁免，存在误杀风险 | 明确：新提议/玩笑/疑问证据不适用，只有把未证当已证才是问题（区分玩笑/新提议与声称已发生） |

## 4. M4 情境与关系目标（三维 0–3 分开评）

评审指令要点：对**首选**评三个独立维度——**意图达成、关系分寸、自然度**——各 0–3 四档。**分开评、分开落盘、分开报，禁止合并为单一锚点或单一通过率**（用户纠偏决策（2026-11-13） M4）；**平淡合格与优秀必须区分**（项目执行原则 11.4、原则 12：修 v1.0 E4 0–2 全满分封顶）。

**评审自由度硬约束（MANUAL v1.1 §4 沿用）**：评审必须给出"这一位允许的动作范围 + 至少两种不同措辞的合格例"，不写唯一标准答案；情绪承接位（她在说"我怕/我累"）准确承接即可，不因没追问资料、没做确认判不合格；不要求医疗/结果性保证，不把"不保证"当缺陷；个人口味列留空，AI 不代填愿发。

### 4.1 意图达成（intent，0–3）

| 锚点 | 定义 | 示例句（TPL，目标="安慰她加班很累"） |
|---|---|---|
| 3 | 优秀：动作到位且出彩——自然、有巧思地完成目标动作 | "这么晚还在改方案啊，先去洗把脸，回来我陪你骂甲方 😤" |
| 2 | 平淡合格：完成目标动作，但平 | "辛苦了，早点休息。" |
| 1 | 回避：安全但回避了当前该做的动作（要反撩只道谢、要推进却完全躲开张力） | 目标"接住她的委屈" → "嗯，加班确实常见。" |
| 0 | 意图错位/答非所问 | 目标"安慰" → "你们公司 KPI 怎么算的？" |

**反向禁止**：不得因"更主动/更长/有钩子/有邀约"加分；不得因推拉、锋芒、留白、玩笑扣分（MANUAL v1.1 §4 原文）。

### 4.2 关系分寸（boundary，0–3）

| 锚点 | 定义 | 示例句（TPL，关系=暧昧初期、目标"轻松暧昧、暂不表白"） |
|---|---|---|
| 3 | 分寸拿捏精准：贴合当前阶段且进退自然（轻推不表白、冷战后修复先递台阶不逼回应） | "下周日呀～你周六先忙，电影院我们到时候一起挑 😄" |
| 2 | 分寸守住：不越界不冷淡，中规中矩 | "好呀，那就下周日。" |
| 1 | 分寸不适：过近或过冷于当前阶段，需改才妥 | 暧昧初期 → "周六啊，我异地也要赶过来陪你。"（过近） |
| 0 | 实质越界：泄露私密/替用户承诺/声称已发生关系状态 | "我跟你老实说，我喜欢你很久了。"（同时进 M3 错误族③，`same_verdict_ref` 同源引用） |

**反向禁止**：不因"更暧昧"加分，不因保守扣分；分寸以冻结 `user_goal_tone` 与 `public_vs_private_context` 为判定依据。

### 4.3 自然度（naturalness，0–3）

| 锚点 | 定义 | 示例句（TPL） |
|---|---|---|
| 3 | 像真人随手打的话，可直接发 | "下周日呀～你周六先忙，电影院我们到时候一起挑，我负责带上好心情 😄" |
| 2 | 自然合格：平淡，可直接发 | "好呀，那就下周日，电影院到时候再定。" |
| 1 | 有 AI 腔/模板感，需修改才想发 | "好的，我已了解你的新安排，我们下周日去看电影。" |
| 0 | 明显机器味/人格错位，不可发 | "根据我们的对话历史，您的计划已更新至下周日。" |

注：E5 的 1–5 自然度是本维之外的**独立口径**（见 §6），两者分开落盘、不合并、不互相顶替。

## 5. M5 完整多候选价值

评审指令要点：**必须读取 `recommended` + 全部风格槽（非空）+ 全部 `directions`（非空）**，先落盘 `candidate_inventory`；主建议 = 输出第一条（事先固定，沿用 v1.0 §1.6）。**候选多本身不加分，有区别且可用才加分**（用户纠偏决策（2026-11-13） §三）。

**"可用"（usable）定义**——语义合格，不要求出彩：① 零严重错误族命中（M3 口径）；② 应使用事实零 `used_wrongly`（M1 口径）；③ 适用题上最新状态用对（M2 recall 门）。全部**引用已落盘的同源判定**（`same_verdict_ref`），M5 不重评语义；某候选缺对应判定 → 先补该候选的 M1/M3 判定再统计（补判留痕），补判失败 → 该候选退出可用率分母并单列。

**六个子指标**：

| # | 子指标 | 分子 / 分母 | 说明 |
|---|---|---|---|
| 1 | 首选可用率 | 首选可用的题数 / 适用题数 | 两臂分别报 |
| 2 | 至少一条可用率 | 存在 ≥1 条可用候选（含首选）的题数 / 适用题数 | 机制臂侧；单通道臂此值 ≡ 首选可用率，如实标注 |
| 3 | 有效方向覆盖 | 有效方向槽数 / 非空方向槽数 | 有效 = 非空、方向与当前话题相关且彼此可辨、零严重错误；空槽记"该位本轮不交付"单列，不算不合格（rubric v0.5 §4 合法 null 条款） |
| 4 | 候选重复率 | 重复候选对数 / 两两对数 | 重复 = 两两 LCS 子串占比 > 0.6（分母 max(len)，<10 字豁免——rubric v0.5 §2 style_diversity 冻结阈值沿用）；越低越好 |
| 5 | 备选严重错误率 | 存在含严重错误备选的题数 / 适用题数 | 引用 M3 统计②，越低越好 |
| 6 | 整组盲评偏好（v1.1 新增） | 机制臂组胜 / (机制臂组胜 + 基线臂组胜) | 见下 |

**整组盲评偏好规则**：组级匿名 A/B——机制臂**整组候选** vs 基线臂**整组**（基线单条回复即一组一条；双方各自真实候选集合，候选数不齐不罚）。判定基准 = 哪一组更能帮用户"找到真正想发送的那条"（有真实可用的区别化选项、无严重错误污染、不必大海捞针）。裁决五选一：`A / B / tie / both_unqualified / insufficient_info`。**不得因选项更多或更长偏好一方**（§0.9）；决定理由仅为数量/长度差异 → 改判 `tie`。被偏好组必须引用其中具体候选原句；`tie` 引双方各一句；`both_unqualified` 必须引用双方缺陷句。匿名轮换沿用 pair_tag 奇偶规则；组级匿名文件按 `scorers/e5-anon` 同规则另建，评审侧无臂字段。统计：`tie / both_unqualified / insufficient_info` 全部单列、不计入分母。**代理评委声明**：这是原生子代理代理偏好，不是真人用户调查。

## 6. E5 盲评回复偏好/自然度与可发送性代理评分（更名）

**更名声明**：v1.0 "E5 自然、好发" → v1.1 **"E5 盲评回复偏好/自然度与可发送性代理评分"**。理由：整组盲评偏好升入 M5 后，本模块收敛为**回复级（首选对首选）**代理评分；新名称如实描述三部分内容，避免与 M4 自然度（0–3）、M5 组级偏好混淆。case_id 前缀 `uv1-E5-` 冻结不变；登记表 pair_tag 奇偶轮换与 `scorers/e5-anon/` 匿名机制原样沿用。

一次评审任务包含三个部分，分别输出 JSON。评审输入：原始聊天、用户目标、匿名 A/B 两份**主建议纯文本**（多通道与单通道同口径提取，包裹差异不参与评判；缺少协议字段不算"回复不自然"，沿用 v1.0）。臂映射按线区分：H 线 pair 奇数 → A=CURRENT、B=DIRECT，偶数 → A=DIRECT、B=CURRENT；N 线 pair 奇数 → A=L、B=B1，偶数 → A=B1、B=L。两线裁决与统计**完全分开**，禁止相加（protocol-FROZEN.md §3 沿用）。

**第一部分：回复级 A/B 偏好裁决（升级为五选一）**。裁决枚举：`A / B / tie / both_unqualified / insufficient_info`。`tie` 定义沿用 v1.0：两者难分高下（都愿发且无实质差别，或都不愿发）。`both_unqualified`：双方均不愿发且各有明确缺陷——必须引用双方缺陷句各一句。`insufficient_info`：信息不足无法比较——必须说明缺什么。偏好 A/B 时必须引用被偏好输出原句。

```json
{
  "case_id": "uv1-E5-004",
  "preference": "A",
  "winner_label": "A",
  "decisive_dimension": "TPL：naturalness | goal_fit | would_send 之一",
  "reason_quote": "TPL：被偏好输出原句（tie 双方各一句；both_unqualified 引双方缺陷句）",
  "judge_identity": "TPL：原生子代理实例标识"
}
```

统计规则（每条结果线单独计算）：偏好胜率 = 机制臂赢 / (机制臂赢 + 基线臂赢)；**`tie`、`both_unqualified`、`insufficient_info` 全部单列、不计入分母**，结果表单报"平局 n / 双不合格 n / 信息不足 n"。H 线机制臂=CURRENT、基线臂=DIRECT；N 线机制臂=L、基线臂=B1。防长度/数量偏按 §0.9。

**第二部分：单输出自然度（1–5 锚点，v1.0 原样沿用）**。五档定义、示例句与套话冻结清单（`作为一个AI/语言模型`、`我理解您的感受`、`希望这能帮到你`、`感谢你的分享`、`值得注意的是`、`请问还有什么可以帮您`、连续 ≥3 个同款表情堆砌）均沿用 v1.0 §5 第二部分，一字不改；套话率 = 命中输出的占比，辅助指标。

**第三部分：可发送性代理分（0–3 四档，v1.1 新增；rubric v0.5 层 2 四档沿用）**。

| 分 | 定义 |
|---|---|
| 3 | 愿意直接发送 |
| 2 | 基本可发 |
| 1 | 需明显修改 |
| 0 | 不能发送 |

统计：可发送性 ≥2 率（基本可发及以上）新增辅助指标。**口径区分**：可发送性是**代理评分**（代理评委的发送意愿），M5"可用"是语义合格判定（M1/M2/M3 口径）——两者独立落盘，不互相顶替、不合并计算。

```json
{
  "case_id": "uv1-E5-004",
  "output_label": "A",
```

## 7. 复评、程序化—语义交接与分歧解决（v1.1 版）

### 7.0 程序化核对层 → 语义评审层交接（v1.0 §6.0 沿用 + v1.1 扩展）

`score_e123.py`（`python -I`，确定性）继续承担 M1/M2/M3 程序化初筛；三类交接规则（正面命中可计、负面零命中须语义确认、uncertain/unjudgeable/false_positive_suspects/irrelevant_misuse 全量交接）按 v1.0 §6.0 原文沿用。**v1.1 新增交接项**：① M3 四轴组合规则适用争议（某主张该判事实类还是玩笑类）全量交语义仲裁；② M2 分门判定争议（recall/suppress 任一门语义存疑）交第三评委；③ M5 `candidate_inventory` 与同源判定引用的完整性由执行侧脚本核对（缺判定 → 触发补判，不算评审失败）。

### 7.1 复评抽样（沿用）

每指标按 case_id 升序每 5 题取第 1 题（≡1 mod 5，n=12 时 25% ≥ 20%），不足 20% 用 ≡2 mod 5 补足；由不同实例的第二独立评审代理执行同一模板。复评覆盖 M1–M5 与 E5 全部语义判分、H/N 两线；程序化判分本身不复评（争议项已全量进交接）。

### 7.2 一致即终判；分歧仲裁（v1.0 §6.2 沿用 + v1.1 扩展）

一致即终判。M1–M3 先跑程序化约束核对（主判），仍分歧交第三个独立评审终裁，三方各不相同 → 该事实/该主张/该题 `unjudgeable`。**v1.1 新增**：M2 双门中一门一致、一门分歧 → 仅分歧门交第三评委终裁，`pair_score` 按终裁重算；M4 三维逐维仲裁（一维分歧不牵连另两维）；M5 组级裁决与 E5 五选一裁决由第三评委终裁。该指标分歧率 ≥30% → 该项结果标注"不确定比例"，不硬给高精度结论。被仲裁推翻的判分记**误报**，单列计数（不进正确数、不进错误数、只进可靠性说明）。

**批量前门禁**：M-PAIR 负对照有效性自检（本文件 §2、addendum §4）与考题激活检查表（addendum §5）通过后才允许批量评分；自检失败回到模板修正并重新小样本验证，禁止带病批量。

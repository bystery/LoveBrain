## 3. 对称重评条款（核心条款）

1. **v1.1 生效后，所有比较臂按新规则重评**：H 线四臂（DIRECT/COT/LEGACY/CURRENT，冻结 48 真实题 turn + E5 12 对）与 N 线三臂（B1/L/B0）的全部已有判分，凡要进入 v1.1 口径的结果表，一律按 `scoring-templates-v1.1.md` 重评。**重评使用与 v1.0 相同的原始输出落盘（outputs、calls.json、匿名文件），不重新生成**（H 线"不重新生成"条款沿用 protocol-FROZEN.md §3）。
2. **对称性铁律**：同一修正应用于**全体比较臂**——不得只重评机制臂、不得只重评基线臂、不得对某臂用 v1.0 而对另一臂用 v1.1 混算。重评与原评使用同一种原生子代理能力；评审代理隔离规则（protocol §5）原样适用。
3. **v1.0 数据原样保留，不删除**：v1.0 的 judgments、scores、summary 全部留档，v1.1 重评结果落盘为**新的文件集**（judgments-v1.1、scores-v1.1、summary-v1.1），不覆盖、不改写 v1.0 文件。
4. **新旧口径并列报告，禁止纵向比**：报告中新旧口径各一张表并排；**禁止拿 v1.1 尺子的分数与 v1.0 尺子的分数纵向相减或画"连续提升"图**（rubric v0.5 §8"协议变更不算候选收益，只算尺子校准"、rubric_v0_6_draft §6"收紧尺子会让基线整体下移，这是量尺修复的正常结果，不是候选退化，禁止拿新尺子的低分与旧尺子的高分纵向比"）。跨口径对比只允许定性描述并显式标注。
5. **一次全量对称重算**：v1.1 重评属"评分规则变更"的一次性全量对称重算（protocol-FROZEN.md §8.3 精神沿用）；保留变更记录（日期、变更描述、影响指标、重评前后数值）。此后若再发现程序化错误或词表增删，按 protocol-FROZEN.md §8.3 仅有的一次全量对称重算机会执行，不得反复。

## 4. 评分器验证方案（先验证，后批量；用户纠偏决策（2026-11-13）§五 原文钉死）

**批量评分开始前，必须先用小样本验证评分器有区分度。** 验证运行（负对照臂）结果**只用于验证量尺，落盘留档，不进任何成绩分母**（同 `pilot-` 规则）。

### 4.1 三个必过验证（每个用冻结集中对应指标的案例，每对照 ≥5 题）

| # | 验证 | 对照构造 | 预期 | 判定 |
|---|---|---|---|---|
| V1 | 无记忆负对照应无法完成远距记忆任务 | 无历史臂（B0 形态：仅当前消息+用户目标，protocol §2）跑 M1/M2 适用题 | M1 首选合格率显著低、M2 recall 门 FAIL → pair 0 | 与机制臂分离成立 |
| V2 | 无差别历史注入应犯旧事实污染 | 全量历史平铺、不筛选不抑制（在 B1 基础上显式指令"把所有历史都用上"的负对照提示）跑 M2 适用题 | suppress 门 FAIL（复活 invalidated 诱饵/已取消事项）→ pair 0 | 与机制臂分离成立 |
| V3 | 正确方法应获双成功分 | 机制臂（L/CURRENT）跑同批题 | M-PAIR pair 满分、M1/M3 正常 | 与两个负对照分离成立 |

### 4.2 通过标准与失败处理

1. **有效性自检（rubric_v0_6_draft §1/§7 沿用）**：无记忆负对照、全量复述负对照、正确方法三类必须在 M2 pair_score 与 M1 上**落在不同分数**；机制臂与最差负对照的分离度不足（< 20 个百分点量级）→ 判定 M-PAIR/量尺未起效，**回到模板修正并重新小样本验证，不得批量**。
2. **饱和检查（项目执行原则 12）**：验证中若某指标双方满分 → 先查题目是否过易、评分是否封顶、重要历史是否就在普通窗口里（联动 §5 激活检查表），修题面判定或规则后再验；无区分度 ≠ 自动判机制无效，也 ≠ 自动判有优势。
3. **假满分检查**：`must_use_facts` 或 `must_not_assert` 为空的题在依赖金标的指标上一律 UNRATED，不记满分（gold 缺席诚实登记，rubric v0.5 §2 沿用）。
4. **泄漏口径（用户纠偏决策（2026-11-13）§五.2 原文）**：合法机制检索后注入历史事实是能力效果，不属于答案泄漏；提前注入金标或未来事件才算泄漏。检索内容出现在输入属机制可见性差异，报告时记录输入可见性，不把"看到更多输入"错说成"机制更强"（项目执行原则 14）。
5. 语义评分引用输出真实原文，不以关键词 miss 直接当错，不预设复核后 LoveBrain 必然翻正（用户纠偏决策（2026-11-13）§五.3）。

## 5. 考题激活检查表（每题落盘，逐题核对）

**目的**：确认每题真的有故障条件、真正激活所测能力（用户纠偏决策（2026-11-13）§四“重点挑早期事实离开简单窗口、历史纠正与冲突、转述未定、关系意图依赖细节的案例"；项目执行原则 10“题目里没有实际触发条件，就不能根据平局得出机制无效"）。

对冻结 60 题（E4 12 题生成回填后同步过表）逐题核对以下四条，按其主指标核对对应条件，落盘 `activation-checklist.jsonl`（每行：case_id、主指标、命中条件、核对依据 quote/字段、结论）：

| 条件 | 内容 | 核对依据（冻结字段，不新增金标） |
|---|---|---|
| ① 早期事实离开简单窗口 | 关键事实建立距本轮足够远、且当前消息未复述该事实——仅凭最近几轮/当前消息答不出 | `must_use_facts[].建立来源（距本轮距离）`（登记表逐条已记距离）；对照 E1 冻结要求"中间插入 ≥3 轮无关闲聊" |
| ② 历史纠正与冲突 | 存在状态变更 + 被作废信息/旧事实诱饵；suppression 语境与旧事无关（rubric_v0_6_draft §1 `context_must_be:"irrelevant"` 的题级核对落在此处） | `latest_valid_state.{supersedes, invalidated[]}` |
| ③ 转述未定 | 存在未确认事项/转述来源/未定承诺，可被坐实 | `must_not_assert`（unknowns 映射）、题面来源故事 |
| ④ 关系意图依赖细节 | `user_goal_tone` 的达成依赖历史中的关系阶段/私人备注细节，仅凭当前消息无法判定语气 | `user_goal_tone` + `public_vs_private_context` + 历史指针 |

1. **判定**：该题在其主指标上至少命中对应故障条件 1 条 → 记 `activated`；一条未命中 → 记 `low_activation` 并写明原因。
2. **处理纪律**：低激活题**不删除、不替换**（冻结集纪律，protocol §8.4），其结果照常进表并**单列标记**；优势结论不得仅依赖低激活题支撑的分子。全部 60 行 checklist 落盘作为冻结集有效性证据。
3. **饱和联动**：批量评分中某指标出现双方满分 → 先回到本表核对激活与题目难度（§4.2.2），再谈结论。
4. E4 12 题（`synthetic_native` 占位）生成回填后，按本表逐题核对并落盘，作为其 `pending_generation` 升格登记的一部分。

## 6. 两类实验分开（用户纠偏决策（2026-11-13）§四 沿用并成文）

1. **产品整体对比**：完整产品 vs 普通基线，**保留双方各自真实候选集合与正常生成流程**——LoveBrain 保留全部候选（recommended+风格槽+directions），普通 AI 按正常方式生成，**不强制两边候选数量相同**（项目执行原则 3）。普通 AI 不人为剥夺历史信息：至少一个强对照（B1）能获得相同原始聊天历史和用户目标（B1 不削弱条款，protocol §2.1 冻结沿用）。
2. **单机制消融**：只切换单机制（如取消 recap、关闭抑制门），其他因素保持一致；消融结论只讲该机制的因果贡献，不冒充产品整体收益（项目执行原则 14：明确区分"产品整体收益"与"某子机制的因果贡献"）。
3. **名称纪律（protocol §2.5 冻结沿用）**：`reference_product_v1` 臂只叫"LoveBrain 研究 Harness"；确实执行 Kotlin 生产装配才叫"LoveBrain 产品 Harness"；指导词代理模拟不得称 Harness 实测；完整产品 Prompt 综合对照称"系统级对照"，不称"单机制消融"。
4. **旧臂名不得混称**：Direct、CoT、LEGACY、CURRENT、reference_product_v1 各自是不同对象，结果表逐臂实名；H 线（历史固定模型复评，统一 deepseek-flash-2）与 N 线（原生子代理新生成）禁止合并为任何"同模型总胜率"表；跨线只允许定性描述并显式标注不可直接相减（protocol §3 沿用）。
5. **旧证据层不冒充**：既有专项判决（R 线：FLJUDGE/LD1/W16/W17B/W15N01）如实转引、不重评、不并入 M1–M5 统计，引用时注明与本轮全产品评测是不同证据层（用户纠偏决策（2026-11-13）§一、protocol §3 R 线沿用）。

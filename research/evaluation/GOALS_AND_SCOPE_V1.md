# 目标与范围页 v1（这次实验到底要什么、比什么、什么还没测）

2026-10-25　配合 `EVALUATION_MASTER_DRAFT_20261025.md` §9.1　状态：待你审定

## 1. 总目标（不变的那句）

同一个固定模型服务下，把**完整 chat harness**（提示词 + 知识 + 记忆 + 意图 + note/历史边界 + 上下文预算 + 调用与输出消费策略）做得：**更会聊、更可靠、等得更少、花得更少、更好维护**。
"回复更短"不是目标；质量相当而资源/等待/维护实质改善，同样算进步。

## 2. 成功是什么（用可判定的话写）

一个回复算成功，要同时满足：
① 事实层——不错人、不错时间、不把没查的说成查过、不把提议说成已约定、不把第三人评价说成本人表态；
② 目标层——这一轮该接住时接住、该推进时敢推进、该收尾时收得住，且不把旧目标硬拽回来；
③ 连续层——该记得时用对、她纠正后用新版本、无关旧事不占题、草稿与私密备注不混成已发送历史；
④ 交付层——传输成功、原始协议通过、**消费适配后通过**、能真正显示与复制；
⑤ 体验层——从发起算起，首个可发送选项与全部选项的等待分别达标；
⑥ 成本层——输入/输出/cache/失败调用可核，有单价才算金额，看每个**可用结果**的成本；
⑦ 口味层——**只有你**能判"像不像我、愿不愿原样发"。

前三层里 ②③ 是过去最没做够的：现行题库把"别犯错"考得最密，把"敢推进、会反撩、能深聊"考得最稀（见任务地图）。

## 3. 比什么（参照系）

- **忠实原版 harness**：`reference_product_v1`，身份冻结 `6e65b6bc…`，只作公平基线，它的输出不是正确答案。
- **最小 harness**：v3 删除实验那一版，用作复杂度对照（证明简化本身省资源）。
- 现役候选：`v4_intent_context_r2`（`37076a76…`，已跑 48 次）与 `v5_purpose_aligned`（`ef855510…`，已跑 48 次）。
- 固定服务：`127.0.0.1:17770/v1`、model=dsf、temperature=0.7。换服务/买服务/改生产默认都不从"额度很多"自行推定。

## 4. 现在能宣布什么、不能宣布什么

**已成立（有真实付费证据）**：删 system 使总 token −60.79%；r2 架构使总 token −56.56%；v5 使总 token −57.65%、中位等待 −17.65%；三者**提速都未成立**（p95 分别 +45.91%/+26.95% 方向）。
**未成立/未证明**：任何"新版更会聊"；v5 的质量非劣（worker 初审的 2 胜/3 胜/19 平在未过线的评审维度上产生，已降级为待重评）；删 analysis 的单独因果收益（每批都是整套改动）；金额节省（无可核验单价）；未见故事上的泛化（E007/E008/E009 都是公开开发集）；底层供应商模型一致。

## 5. 明确未测（不猜、不冒充）

原产品的独立入口：开场白、谈心、润色；后台重估与完整纠错；长期记忆跨会话恢复的真实产品行为；Kotlin 编译、Android 真机与 UI 验收；产品侧空 analysis 消费者是否安全；kb/corrections 与考场的等价性；分支式互动（对方按候选实际动作反应）；你的真实使用反馈与愿发率。

## 6. 已知需要修的三件事（不属于质量结论）

接入原型的备注归属、消费器崩溃、协议键容错——已由并行修复线在 `integration_preview/` 内落地（9 项边界夹具 + 原 4 项回放全通过，恢复后真再发一轮已覆盖）。这三项属于**交付可靠性与实现负担**，不能拿它们当聊天质量进步。

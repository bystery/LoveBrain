## 2. 每个节点要交的字段（缺项=该节点未评，不得记通过）

对甲、乙各给：
- `claims`：把可核验陈述逐条列出，每条标 `F1 有依据 / F2 允许的新表达 / F3 信息不足下的正当处理 / F4 无依据具体断言`，并引用当时可见证据片段或写明"证据中不存在该项"。
- `goal_completion`：0–3 锚点整数。
- `insufficient_ok`：题面缺事实时，是否用"承认不足/反问/去查/商量"处理（yes/no/na）。
- `overkill_flag`：是否把正常玩笑、新提议、推拉、留白当成缺陷（true/false）。
- `attribution_ok`：第三人转述/草稿/私密备注是否被混成当事人表态或已发送历史（yes/no/na）。
- `pref`：`甲 / 乙 / 都行 / 都不想 / 说不清`（内容层，不含长度加分）。
- `cite`：至少一段被引用的原文。
- 另外单独一行：`protocol_vs_content`——若该份存在协议/键名问题，是否仍按内容单独评价（yes/no/na）。

## 3. 预定阈值（不达标就写"暂未证明"，不许事后挪）

| 维度 | 指标 | 合格线（dev 子集） |
|---|---|---|
| 明确事实错漏判 | 被独立复核确认为 F4 的断言中，评审者标出的比例 | ≥90%（漏判 ≤10%） |
| 自由表达误杀 | 控制项里属 F2 的正常新提议/玩笑被记为缺陷的比例 | ≤15% |
| 目标完成度 | 两两精确一致率；相邻（差一档）一致率 | 精确 ≥50%，相邻 ≥85% |
| 信息不足处理 | 标为 `信息不足` 的节点中正确使用 F3/`insufficient_ok=yes` 的比例 | ≥80% |
| 顺序敏感 | R1 与 R3（整体换序）在同一节点上偏好翻转率 | ≤15% |
| 跨会话自一致 | 同一内容在 R1/R3 两次判定中 `pref` 与 `goal_completion` 一致率 | pref ≥80%，分数相邻 ≥90% |
| 归属维度 | 涉及第三人/转述节点上 `attribution_ok` 判定一致率 | ≥75% |
| 协议与内容分离 | 出现键名/协议问题时仍单独判内容的比例 | 100%（这条不合格就直接停用程序 veto 当内容结论） |

## 4. 判"合格"的权限分配

- 通过的维度：才允许 AI 在该维度上批量辅助评审，且必须附原文与判词、允许"说不清"。
- 未通过的维度：保留"暂未证明"，转人工或用户抽样；不得用加权总分顶替。
- 口味维度（像不像我、愿不愿发）：**AI 永远不自称合格**，只有用户锚点算数；AI 至多在被标定后做经校准的预测。
- 两两一致 ≠ 真值；同模型不同会话 ≠ 独立模型；本轮结论只说明"这套手册下评审者稳不稳"，不说明候选好坏。

## 5. 已知缺陷（声明时已知，不掩盖）

1. 子集里 3 个控制项标着 `authored_control`，评审者知道它们是人工写的对照，可能更用力找"标准答案"（测 F4 识别够用，测自然语气偏弱）。
2. `信息不足` 类别已从节点里移除（只存密件），避免把"该承认不足"的答案直接告诉评审者。
3. dev 子集里 E007/E008 同位置在 v5 与 r2 两批都出现过，本 IRR 只取其中一份；跨批复用同一故事的曝光污染计入数据集缺陷，不在本轮解决。
4. 卡片缺陷条款（如 E007_T03"据 her 偏好确认不吵"）仍随节点公开，手册 §1 要求评审者拒绝把它当资格证明；若评审者照卡放行，就记为尺子问题而非候选问题，同时说明该评审者未正确执行手册。

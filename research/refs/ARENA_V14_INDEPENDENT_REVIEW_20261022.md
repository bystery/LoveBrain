## 4. 工作组一：可信边界仍失效（P0）

### 4.1 控制器在自己进程里执行候选代码

位置：`arena/isolation/trusted_controller.py:326` 调用 `lb_runner.load_mechanism(cand_dir)`；后者在 `arena/lb_runner.py:77` 执行 `spec.loader.exec_module(mod)`。

独立探针给一个合成候选增加导入时 PID 记录，用实际 IsolatedRun 跑两轮。记录得到：

- 宿主 PID **29388** 执行 staged 候选；
- 可信控制器 PID **44264** 又执行仓库原候选；
- 两个 PID 均来自本次实际运行，机制导入路径分别落在 staged 与原候选目录。

**候选没有通过 IPC，也能在评分器、原题与凭据所在的控制器里执行顶层 Python。** 即使下一步把宿主做成真正受限身份，这个导入也会穿过边界。因此“只丢弃候选自报 score/gold”不能关闭评分权威风险。

修复要求：控制器只读静态 JSON、散列、声明；候选机制只能在不可信宿主里导入。不能为了探测 v1/v2、memory-off 能力或构造比较而在可信侧加载候选代码。新增导入副作用 canary：宿主正常执行、控制器绝不能执行。

### 4.2 当前文件 ACL 不是完整隔离，失败还会继续运行

位置：同文件 `run_episode:314–326`、`start:228–239`、`deny_files:506–526`、`undeny_files:528–537`、`close:539–547`。

生产入口自动 deny 的仅为**当前 episode 一个文件**。out/control、已有日志、其他题面、原路径评分器、其他候选状态并没有由该入口统一隔离。相同用户下的普通 Python 子进程既不是只读代码容器，也不限制直接 open、启动子进程或网络。

本轮在控制器资料区放自建 canary，实际宿主成功读到。安全守卫记录的生产 deny 目标只包含当前合成 episode，canary 不在目标集合。这项证明的是“该文件根本没有进入生产保护范围”，不是声称测试了 deny 后绕过。

另有四处可直接从代码确认：

- deny 失败只写 FILE_DENY_FAIL，不抛错，宿主仍继续；
- 同一身份同时有设权/复原权，不能用“攻击夹具没调用 reset”证明恶意候选不能调用；
- `/reset` 恢复默认继承权限，不等于恢复操作前精确 DACL；
- close 先 undeny、后停止宿主，存在宿主尚活着而题面已经重新可读的次序窗口。

矩阵还手动额外 deny 了命名攻击靶子。**测试夹具临时保护一个已知靶子，不等于生产自动保护所有私有资料。** A4 的普通 `import lb_scorer` 得 ModuleNotFoundError 只证明搜索路径未放入该模块，不证明按绝对路径打开/加载也不可行。

修复要求：使用已经具备或一次性部署的真实隔离环境；候选只有声明依赖和自身状态，控制器/题库/备份/账本不挂载给它，网络只能经可信代理。若本机暂不能提供，明确保留 NOT_READY，提交一份部署前提，停止无限窗口站和 ACL 试验。**不允许继续在主仓试 deny/reset、搬整树或删残骸来换 PASS。**

### 4.3 媒体代理可被候选用来读取任意文件

位置：TrustedProxy.generate 直接接收宿主的 `images`；`arena/lb_gateway.py:54–61` 用控制器权限打开路径并编码。

独立探针不把自建文本 canary 登记为媒体，直接向 TrustedProxy 传其路径。控制器成功读取，完整内容出现在本机替身收到的 image data URL 中。相同请求还把冻结模型名改为 `candidate_override`、温度改为 **1.23**，均实际出站。

这不是测试资产里出现“车票”等词的问题，是可信代理缺少权限与公平配置约束：控制器被候选当作文件读取代理，候选也能改变配对实验的模型/温度。

修复要求：每轮从可信题面建立允许媒体的身份、散列和大小映射；候选仅能请求已授权引用，路径解析、符号链接、远程 URL 等服从明确策略。固定对照时模型/温度由可信配置提供，不接受候选覆盖。用合成私有文件反例和合法图片正例同测。

### 4.4 网络“密钥拒绝”测试实际上没到认证逻辑

攻击夹具 A6c 向 HTTP 端口发送的是裸 `hello` / `KEY wrong-guess` 行，没有构造 HTTP POST。正式矩阵因此记录 `unkeyed=0 guessed=0 served=0`；这不是证明认证严密，而是请求根本没有进入 do_POST。

独立把同一攻击夹具指向一个**有效 HTTP POST 不需密钥便返回 200**的本机替身：两项仍报告 BLOCKED_REFUSED，到达服务处理器的有效请求数为 0。随后发一条正确无密钥 HTTP 请求，确实得到 200。这个反例证明该测试连免密服务也会误判有保护。

正式日志的 A6b 子进程结果是 `BLOCKED:TimeoutExpired`，现有 judge 也把该值归 PASS。超时不等于读取被权限拒绝。网络认证需要真实协议的无密钥/错密钥/正确密钥三对照、实际请求计数和授权结果；子进程读也必须有确定的拒绝证据，不能用超时归零风险。

## 5. 工作组二：恢复、额度与统计没有收口（P0/P1）

### 5.1 --resume 之前就删除检查点和历史

位置：`tools/iso_run.py:47–55` 无条件 stage；`IsolatedRun.stage:175–181` 对 staged、out、control 执行 rmtree。

### 5.2 重建代理后额度和 attempt 身份重置

相同 run/case、quota=1，创建代理完成一次请求，再重建同身份代理：第二次请求仍成功。日志得到两个完全相同的 `(run_id,case_id,attempt_id)`，attempt_id 均为 1。计数 authority 仍是进程内 used，不是已有 started 的不可覆盖账本。

要求：新建拒绝已有运行目录；恢复不删证据，先验版本/候选/题面/检查点绑定；配额从可信持久 started 重建，恢复前后全局唯一 attempt_id，事件指向真实 case。未决请求按已消耗尝试处理，依失败政策停批；不能换 run 名逃逸同一授权总额度。

### 5.3 账本写失败仍然派发

## 8. 对简报五个问题的裁决

1. **三通道混淆**：现有程序分不足。source_id 存在不证明事实受该消息支持，也不证明 HER/ME 归属、时间归属、IDEA 私密边界正确。独立合成例中 ME 说“我在苏州，周末常攀岩”，HER 说“我在合肥，没爬过岩”；把 ME 事实写成“她在苏州，周末常攀岩”且引用真实 m0，首选也错称“你也在苏州”，仍得 10 分、无 veto（该例 gold 为空）。这是程序分的能力边界，不表示要把全部语义硬塞进关键词评分。结构门保留；语义审查必须看原上下文、首选及备选和下一轮实际行为。不能用 10 分或“词面零命中”宣布真人可发。
2. **能否养出 monster**：不能由题数担保。当前可做暴露开发诊断，尚不能证明跨故事泛化。重点是独立故事、反向保护、真实可见证据和独立选择，不是配额或一批多跑几十次。成本只记账，用户批准的调用上限仍是硬边界。
3. **隔离漏洞**：可信侧 import、仅单文件 deny、代理代读文件、任意网络、临时靶子替代生产权限均是实际问题；前三项已有本轮代码/合成执行证据。不能把网络必要条件自行降为白名单残差。
4. **59 条口味锚点**：适合给人类审查者校准“什么是该用户的语气”，做成正反对照并记录分歧；不能扩词表或让候选检索锚点答案当真人人设。已暴露锚点永不变回独立验证。用户偏好票与工程初审分开。
5. **HITL 是否太晚**：首次建立语气目标、表达方向明显改变、拟晋级三个时点需要用户标定；中间同族故障一次批量交付，不每修一个字段就等口令。无须等整批高额调用耗尽才发现方向错了，也不要求用户替工程师填写几十条基础事实审核。

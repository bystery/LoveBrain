# LoveBrain 题库建设指导书：先做好一版可用题库，再扩量

日期：2026-10-22。性质：审查方提出的出题与验收方案，不是题库已完成的声明，也不是新增模型调用授权。用户不需要亲自编题、写 gold 或判断代码问题。

## 1. 先把现状说清楚

本次直接核对项目文件：已有公开开发 episode 19 个、请求位 331 个；其中 PHASE0_GEN_220 是 220 位机械压力题，另外还有意图变体、full/control 对照和烟测。它们有开发价值，但不能等同 331 道独立自然聊天题。

split_manifest 明确：独立 selection 未建立，最终 B 线未建立。**缺的不是零到一的几千条台词，而是一套覆盖合理、按故事隔离、经过自然度审查的正式题库。**

当前真实集成验收文件仍为 overall_status=NOT_READY。真实通路跑过，不等于隔离与题库已经完成。出题与沙箱工程可以分开推进。

原计划曾是开发 80 + 选择 40 + 最终封存 80；后来允许按覆盖重设计。本书建议第一版暂用这个容易管理的 200 请求位规模，而不是突然扩大到几千。**这是建议规模，不声称它已获用户批准、已落盘或足以证明 monster。**

## 2. 三个计数不能混

- 聊天消息：HER/ME 发的一句话，可能连续发几条。
- 请求位：用户在某个节点请助手生成回复，一次可见输入；一位可含多条聊天历史。
- 模型尝试：harness 真正发给模型的请求。多阶段机制一个请求位可能调用多次，失败也消耗尝试。

本书的 200 指请求位，不是 200 条单句，也不是每轮训练都必须运行 200 次。不得用请求位冒充实际调用预算。

## 3. 第一版题库建议

| 部分 | 建议规模 | 用途与可见性 |
|---|---:|---|
| 公开开发 | 约 8 条独立故事，共 80 请求位 | worker 可看，可定位问题、调机制；可从已有优质开发故事整条选用/修订 |
| 独立选择 | 约 4 条新故事，共 40 请求位 | 由不参与调参的角色制作保管；用于冻结候选的阶段比较，不是每轮刷分 |
| 最终封存 B | 约 8 条新故事，共 80 请求位 | 最终候选验收一次；不因开发成绩差而提前打开 |
| 既有机械压力/攻击回归 | 单独保留 | 验证协议、隔离、长度、坏 JSON 等，不混入自然度和独立故事数 |

每条故事通常 6–12 个请求位，平均约 10 个；长记忆故事可以更长，从同一部分的总额中调整。不要为凑整把自然对话硬截成十次。

200 位还不够覆盖新故障时，再新增**不同故事与机制需求**；不先定 1000 个数字倒逼水题。原有暴露题永远保留暴露标签，不能改名移进选择或 B。

## 4. 按“故事”，不要按“关键词”出题

先定人物生活，再写聊天，再登记观察点。每个故事先交一页设计卡：

1. 双方是谁、关系到哪一步；同城/异地、作息与表达习惯；哪些信息未知。
2. 各自这段时间实际在忙什么，为什么有动机在这个时刻联系对方。
3. 哪些真实往来已经发生；哪些是备注、猜测、提议，尚未对对方说出口。
4. 日期、地点、消息时间和生活事件；允许自然沉默、失联和话题变化。
5. 几个可观察的回复机会；不是给每句台词塞一个考点。

生活素材至少跨工作/学习、朋友与日常、兴趣活动、出行或购物、居住安排等不同领域。关系含普通朋友、新认识投缘、逐渐暧昧；各划分都有强弱不同的互动，不把 B 线误称成“专门调情线”。

故事之间应在人际动机、消息习惯、事件结构和信息缺口上有差异。把“车次改签”换成“房号改了”，仍可能只是同模板换实体，不能冒充独立泛化。

## 5. 十二个观察族，每族都有反向保护

下表的“好行为”是允许行为范围，不是要求候选原样复述的一句标准答案。

| 能力 | 正向观察 | 反向保护 |
|---|---|---|
| HER/ME/IDEA 分清 | 回复对象、事实主体正确，私密备注不外泄 | 有根据的 ME 经历可以说，不因“我”字就判编造 |
| 意图与优先级 | 理解自由文本意图，尊重明确边界 | 意图关闭/完成后不继续推进；不能把所有闲聊都写成任务 |
| 关系与分寸 | 能调侃、回应暧昧、主动承接，也能克制 | 不把一切暧昧判危险，不把普通朋友默认成情侣 |
| 相关记忆 | 早先的有效信息影响本轮正确决策 | 只要求行为受影响，不强制复述旧事实或某个词 |
| 无关记忆 | 新话题不被旧事抢走 | 真正相关的旧事实不能一律删掉换“安全” |
| 更正与错人 | 同一主体/属性的旧值失效，新值保留 | 其他人的同编号、历史叙述、引用旧值不被误删 |
| 提议/确认/发生/取消 | 状态随真实证据更新 | 邀请不是已约定，拒绝中的“好/一起”不是同意 |
| 时间地点与物理可行性 | 跨日指代与异地行动正确 | 不能把消息发送时间当活动发生钟点，不惩罚合法新提议 |
| 事实出处与具体细节 | 已给出的编号/数量/时间保真 | 没给的信息可不确定；给了的信息不许全删、全问回去 |
| 媒体 | 授权图片真实进入请求并正确承接 | 不可见/链接无效时不装看过；caption 不冒充视觉输入 |
| 冷场、收尾与 no_reply | 允许不回时可不回或自然收尾 | 应正常回复时不能总拒发；重开后不能仍当晚安收尾 |
| 输出与后续行为 | 合同、审计、状态与下一轮实际使用一致 | 合法 null 不误杀，失败不补生成，内部 KB 指标不冒充回复质量 |

同一节点可覆盖多项，必须注明复用；不要把同一份证据当多份独立样本。每个比较都保留相关/不相关、已知/未知、纠正/引用、确认/否定等成对机会，但自然故事不必按机械矩阵逐句排队。

## 6. 一个公开示范，说明怎么从具体事情考一般能力

以下是公开讲解用素材，**不得放入独立选择或最终封存题**。

一条生活轨迹可以是：她原计划周六搬家，后来改到周日；周日晚上说终于搬完，之后两人聊早餐与工作。另有明确剧本 ME 消息表明用户周末不在同一城市，但没有约定帮忙。

| 节点 | 实际要观察什么 | 不能怎么评分 |
|---|---|---|
| 初次聊搬家 | 自然回应她的忙碌与关系语气 | 不要求一定问地址、安排帮助或说“搬家” |
| 日期变化 | 后续以新计划为准 | 不能把一句历史回顾中的“周六”判错 |
| 已搬完 | 承接完成后的疲惫/轻松，不继续当待发生 | 不强制回复“辛苦了”；“终于能躺会儿了”也可能自然 |
| 下一轮聊早餐 | 没有需要就不把搬家旧事再拉回来 | 不因没有显示背出记忆而扣分 |
| 对方后来主动问旧事 | 能用正确主体与状态回应 | 不允许为了防旧事污染把所有旧信息都屏蔽 |

这里真正考的是“人物—事项—属性—时间—状态—证据”，不是“搬家”这个词。换其他生活领域时，要换真实动机和信息结构，而不是教考生添加“改期/搬家/车票”特判。

## 7. 长记忆题必须真的测过记忆

每条长期故事同时登记三件事：

- 事实首次出现在哪次候选实际经历的请求，出处是什么；
- 中间经历哪些其他话题，哪些信息真正退出本轮窗口；
- 后测本轮完整可见输入是什么，目标事实确实不在其中。

时间过去 44 天不等于测了长期记忆；把答案放 initial_kb 也不等于候选自主记住。预置知识使用、空状态自行存储、重启恢复、跨话题检索分开登记。

可以在多条故事中安排短期、跨日、数周跨度及不同干扰长度，不必每次都用大量付费调用制造间隔。确定性剧本可提供多条真实 HER/ME 消息，但未经过候选输入的信息不能假称被它记过。真正的长链压力测试单列预算。

生成的推荐草稿不是已发送的 ME 历史。后续 ME 来自固定剧本并明确是模拟已发送历史，或来自用户确认的发送事件；绝不能把推荐自动追加后再用假想的 HER 积极回应证明恋爱效果。

## 8. 每个节点必须具备的评审资料

1. 全局 episode:case 身份、story_family、划分、来源与暴露状态。
2. 公开输入：HER/ME 实际消息、时间、用户备注、有效意图、可见画像、允许媒体与轮级许可。未知信息如实为空。
3. 评估侧资料：故事完整时间线、事实台账、主体/状态变化、该轮的观察机会。
4. 允许行为：多个合格方向；允许简短回复、提问、合理调侃、自然不回或不确定。
5. 不允许行为：必须指向事实或明确边界，例如把没说过的具体钟点当确定事实、把邀请写成已约定。
6. 评分依据：客观合同交程序，语义支持和自然度交人工监督评审，个人口味单列。
7. 下一轮验证：需要维护状态的节点，应有后续实际输入检验；不用 KB 中某行“已存储”顶替。

不要先写一条标准回复，再用关键词逼考生模仿。gold 不进候选输入；作者意图、未来事件、探针名称和评分提示也不进 note。source_id 存在不代表事实受来源支持。

JSON 以当前公共契约和 schema 为准；评审附件不能擅自塞进现有候选可见字段。语义上合理但执行器暂不支持的场景标适配缺口，不偷偷改考生或评分器迎合。

## 9. 自然度审核怎么做，用户只需管自己的语气

工程方先完成日期星期、时间顺序、地点、消息角色、媒体、意图许可、事实出处、划分/重复等机械检查；出题方和审查方再连续读完整故事，而非只看孤立好句。

逐节点问：

- 这个人此刻为什么说这句话？删掉考点后，这句话还像他/她会说的吗？
- 有没有为了让助手显得聪明而突然重复背景、主动报编号或配合邀约？
- ME 的性格、经历、承诺是否真的在剧本里，还是作者事后补了？
- 冷场、少信息、无须回复、意图变化是否被允许，而不是全线有效推进？
- 合格范围是否既允许自然短句，也能拦住主体/事实/分寸错误？

用户只需在第一次出题样本里看约 6 段代表性片段，指出“像我/太油/太保守/这段不像真人”等。AI 审查不能把自己的“可发”记成用户愿发票，用户不负责找代码、时间戳和 JSON bug。

## 10. 独立出题与保管，怎么安排才不折腾

不要求另买 AI 账号，也不必请专业命题老师。用户可以指定一个**专门出题、审核与保管、不参与考生调参的会话/角色**，开发 worker 不看选择/B 的内容、gold 或逐题失败答案。

“不能由 worker 随意指定自己人”是利益冲突的治理要求，不是必须某种账号或自然人身份的技术规律。关键是职责、访问权限、冻结时间与暴露记录。另开窗口本身不构成文件隔离；同账号也不会自动让身份失效。

按 story_family 先划分再写详细题。角色/地点/编号替换、同一事件骨架、同一素材的变体留在同一划分。开发者已经看过的题永远标暴露。作者不能读候选实现/输出/逐题调参记录后，专门照着该候选弱点制作所谓“未见独立题”。已知故障可以出回归，但如实归开发诊断。

选择集内容提交评测前，候选版本先冻结；选后若按逐题反馈修改，则该批题对后续版本已经暴露，不再宣称独立确认。最终 B 不反复刷。保管区必须由可信评测端控制，开发身份/候选不可读；G08 未实现这点时只能登记“未技术封存”，不能填一个 custodian 名字就 G06b PASS。

## 11. 两批交付，批内连续推进

**第一批：24 请求位编题 pilot，3 条故事，每条约 8 位。** 这是公开开发素材，未来不进选择或 B。一次交生活轨迹、连续台词、逐节点允许/错误行为、JSON 与校验报告；出题方自行连续修复常规问题，不每个字段都问用户。用户只做一次少量语气标定。

**第二批：补齐建议的 200 位正式划分与验收包。** 第一批可计入开发 80；其他已暴露开发题通过审核可整条纳入。选择 40/B80 由指定独立角色另行制作。选择/B 的内容只交保管区，给开发方的公开报告只列规模、覆盖、版本、散列、暴露与权限状态，不泄题。

若缺独立保管条件，先完成开发集与独立题设计工作，登记 NOT_READY，不把权限缺件转成无限出题停工；更不能把未封存草案说成已保密。

每批验收项：

- 文件存在且 schema/时间/媒体/角色/许可检查通过；
- 全故事自然度与人物动机有连续阅读记录；
- 12 能力族都有正反机会，重复节点/模板/家族清楚登记；
- 长记忆题有经历—驱逐—后测证据设计；
- 首选、备选与下一轮行为分审，无硬关键词替代自然度；
- 划分按家族，真实保管与暴露状态可验证；
- 没有凭空宣称真人愿发、正式晋级或 monster 已成。

## 12. 运行题库时怎么控成本

先审题、校验、确定性链路演练，再按用户明确批准的预算运行考生。不要“每写一道题就打一次真实 API”。

开发阶段先选有判别力的小批，同输入、同配置交错父子对照；有收益再扩大到开发全集，选择集仅在阶段检查使用，B 留最终。调用上限按整个授权的实际 attempts 累计，多阶段、失败、首轮与重跑全部算；不能分成多个 run 各自不超额。

改报告、补 evidence_file 路径、添加不影响执行的说明文档，不自动产生重跑许可。确需重跑而剩余额度不能覆盖完整对照时，停止并保留原始证据，不准先超额再坦白。

## 一、产品一句话

Android 悬浮 AI 助手：聊天时挂在聊天 App 旁边，帮用户想回复。**不代聊、不自动发送**——
输出候选，用户自己挑、自己改、自己发。

## 二、用户视角的真实交互流

1. 用户在悬浮窗里录入三类消息（可以长按自动捕获，也可以手动粘贴）：
   - **她（HER）**：对方发来的话
   - **我（ME）**：自己已经发出去的话
   - **想法（IDEA）**：写给军师看的备注，**不是要发出去的话**
2. 点「生成回复」→ 模型输出候选
3. 用户挑一条、改一改，自己发送
4. 后台自动沉淀记忆（本轮 analysis 写回知识库），供下次聊天用

另有「主动发」入口（润色用户草稿）和「谈心」入口（倾诉分析），本题库只考主链路。

## 三、harness 的输入（PromptBuilder v4 装配，代码级）

每轮生成时，harness 收到的东西：

| 输入 | 形态 | 代码位置 |
|---|---|---|
| 本轮消息序列 | HER/ME/IDEA 混排列表（用户按实际聊天顺序录入） | `ChatMessage` 列表 |
| 军师备注 | userHint（自由文本，IDEA 的代表形态；用户有时会写「军师：我想回复xxx」——这是**用户计划**，历史上被军师误当对方消息回复过，是真实事故） | `buildReplyUserPrompt` 入参 |
| 持续意图 | IntentConfig，**自由文本 ≤200 字**（如「想推进关系但别太急」），非枚举 | `IntentIdeaBlock.buildIntentBlock` |
| 进攻模式开关 | aggressive: Boolean（插入 aggressive.md 战术段） | user 知识段 |
| 知识库 | 按联系人隔离（每联系人一个 KB），内容见下 | `KnowledgeReadPort` |
| 当前时间 | 系统时钟注入，要求回复贴合时段 | `buildTimestampPrompt` |

### 知识库内容（每个联系人的"小本本"）

- `understand/me.md` / `her.md`：我方/对方画像
- `understand/warmth.md`：关系温度
- `understand/style.md`：表达偏好（点赞过的风格沉淀）
- `moment/scene.md`：场景事实链（近期发生了什么，2 小时有效期）
- `moment/recent.md`：最近对话
- `moment/topic.md`：当前话题（含话题年龄）
- `moment/plan.md`：进行中事项（selector 按相关性选注入）
- lessons：历史经验（踩过的坑，读侧净化后注入）
- stage：关系阶段（初识/暧昧/…，从 stage.md 提取对应小节）
- 归档冷存储：raw_chat.md / raw_topic.md 完整聊天记录（**主链路不读**——这是短板，见 §六）

### 最终 prompt 结构

```
system（静态，缓存锚）= core + naturalness_check + redline + format + 注入防御声明
user（动态）= 知识段(画像→阶段→记忆[+进攻]→此刻场景→最近对话→进行中事项)
           + 持续意图块 + 军师备注块 + <chat>围栏( [m0] PARTNER: ... / [m1] USER: ... )
           + 时间戳垫底
```

预算裁剪：byBlocks 按区块优先级裁（先旧经验→较早 recent→旧 scene→必要时旧 chat；
军师备注和最新真实消息最后才动）。

## 四、harness 的输出契约（format.md 原文规格）

单 JSON 对象：

```json
{
  "response": {
    "recommended": "…", "bad_boy": "…", "playful": "…", "warm": "…"
  },
  "directions": ["跟进|展开|表达|转向 各一条可直接发送的回复或 null"],
  "analysis": {
    "topic_status": "same | drift | new",
    "topic_label": "话题名",
    "scene_facts": [{"text": "她今天18:00到家", "source_ids": ["m0"]}],
    "ongoing": [{"item": "计划8-15见面", "status": "新出现|进行中|已完成|已取消",
                 "state": "本轮最新进展 或 固定词'本轮未提及'"}]
  }
}
```

关键规则：
- response 四风格 = recommended（有主见有温度）/ bad_boy（清醒有锋芒，允许推拉挑逗）/
  playful（轻松接梗）/ warm（直接表达在乎，不自动补叮嘱）
- directions 固定四方向，不适合的输出 null，不凑满
- analysis 的 scene_facts 必须带 source_ids 指向 `<chat>` 围栏内的真实消息标签；
  无来源不落盘；ongoing 只报变化、禁相对日期词、须复用既有事项名
- 场景类型（本轮自动判断）：日常分享/轻松互逗/主动邀约/认真沟通/争执/解释认错/收尾
- 优先级链：事实与明确边界 > 本轮用户意图 > 场景适宜性 > 持续意图 > 阶段默认战术
- 重复规则：同一事项已回应、无新信息时不得换措辞重提

**输出后处理**：analysis 由客户端解析写回知识库（scene_facts 进场景链、ongoing 合并
进 plan、topic 更新）；四类候选展示给用户挑选，**复制≠已发送**，只有用户确认发送
或捕获到真实 ME 消息才算"我说过"（9-15 指导书修复的 P0：候选不得冒充已发送历史）。

## 五、辅助引擎（harness 的一部分）

- **lessons**：话题结束后提取经验
- **reflect**：画像更新（瞬态信息不写画像，有证据门控）
- **vector**：关系向量/阶段推断

## 六、LoveBrain 的已知结构性短板（monster 要打的靶子，子代理侦察结论）

1. **没有长期记忆检索**：只有"最近 2 轮"窗口 + 归档冷存储（主链路不读）。
   她 50 轮前说"猫毛过敏"，现在聊到猫，当前架构想不起来。
2. **意图是一条自由文本**：无结构化处理，与记忆联动只靠关键词匹配。
3. **话题切换即清空**：上下文管理是硬窗口，无语义压缩。

## 七、对大牛上一轮 6 个结构性问题的逐条回应

| # | 大牛的问题 | 回应 |
|---|---|---|
| P0-1 | 「我」已说过话还让 AI 回复，回复目标混淆 | **真问题，认**。LoveBrain 真实场景里待回复的永远是 HER 的最后一条（或用户草稿）。A_ch01 样稿 t03/t11/t20 确实混了。修正：题库 schema 加硬规则——**每轮待回复的最后一条真实消息必须是 HER**（或明确「润色草稿」模式）；ME 消息只作为历史背景。正在改 |
| P0-2 | gold 关键词逼 AI 复述上下文说人机话 | **真问题，认**。修正方向：关键词检查只保留给**事实锚定**（约定时间/地点/称呼/禁泄露词）；开放式闲聊轮的 must_keywords 删除，自然度交给 judge 三维（单句/上下文/人物） |
| P1-3 | 固定剧本测不出互动能力 | 部分成立。固定回放（可重复、可公平对拍）是主体，保留；动态互动测试（模拟对方按候选分叉反应）列为 B 线验收期的增强，v1 不做 |
| P1-4 | judge 与写题 AI 同源偏差 | 已有防线：judge 上岗前必须过校准（与用户 59 条真实锚点一致率 ≥80%）；大牛建议的「成对样例 + 检查系统性偏爱长回复」采纳进校准协议 |
| P1-5 | 先定 200 轮再塞剧情，应该先建覆盖矩阵 | 采纳。改为：先按故障类型（长期召回/相关性/来源区分/更新时效四类）建覆盖矩阵，再定轮数 |
| P1-6 | 考熟题，需要隐藏验收集 | **已有此设计，是我口径错了**：B 线 80 轮从第一天起就是「封存验收线，开发期间任何人不可见，只用于最终验收」。我近期错误地把它说成"调情线"——现修正回原设计，调情覆盖放 A 线各章梯度 |

## 八、重要历史决策链（大牛你需要知道的仲裁规则）

1. 用户想法与大牛意见冲突时，**听大牛1 的**（用户钦定的仲裁规则，2026-10-07）。
2. α=0.40 线性加权成本分被两位大牛否决 → 约束筛选；后续用户升级为质量优先
   monster 导向（成本只记账）。
3. 训练的是 **harness 组织逻辑（机制），不是 prompt**——机制 >>> prompt 调优，
   连续两轮变异不得都是 prompt 措辞类；每 3 轮和争冠前必须扫描开源项目
   （Letta/mem0/A-MEM/GEPA）写引入或否决理由。
4. 知识库内部不单独评分（harness 自主决定怎么组织 KB，只看最终输出行为）。
5. 口味基准：用户标过的 59 条真实聊天锚点（中位 19 字、清醒+俏皮主导、
   暖要具体、阶段匹配是硬约束、关系确认后接受踩油门）。

# LoveBrain harness 删减、重构与循环优化——完整执行指导书

日期：2026-10-24。执行对象：现有本地训练 worker。原版项目：`D:/LoveBrain`；实验项目：`D:/lovebrain-arena`。

本文件是下一阶段的合并任务书。用户不需要另开窗口、重新解释目标或逐条批准离线实现。代码开发、公开开发题整理、离线检查、实验计划、初审和报告连续推进；真实 API 调用只使用匹配本批的有效授权。本文件本身不增加调用额度。

## 1. 总目标与完成标准

**在固定模型服务下，通过删除、替换、重组提示词和机制，得到比原版更好用、更可靠、上下文更干净，同时 token 更省、等待更短、维护更容易的完整 harness。**

需要优化的对象包括：

- core、naturalness、redline、format 等提示资产的内容、长度、重复与必要性；
- 当前意图的表示、触发、阶段切换、关闭、与当前对话的协调；
- HER、ME、第三人、真实历史、私下补充事实、目标、情绪、未发草稿的区分与使用；
- 知识和记忆怎么写、怎么纠正、何时取、取多少、怎样防止无关内容侵入；
- 上下文拼接、去重、预算、状态恢复，以及前后台调用策略；
- 输出是否真的有用，是否产生大量无人采用的备选和分析。

用户认为原版大部分实现无效。实验要允许大幅删除，而不是默认现有架构都值得继承。通过消融判断哪些值得保留，不将“80%–90%”直接写成已测量结论。

### 一轮完成的定义

一轮有效优化至少走到：

> 明确假设 → 版本化候选 → 针对性离线检查 → 在授权内收集真实对照 → 按卡评审 → 记录质量与代价 → 保留、淘汰或记证据不足。

只有代码和测试、尚无真实对照的工作，称“候选准备/工程修复”；不能称“效果优化完成”。一次真实实验即使没有改善也算有效产出，只要结果可信、据此淘汰假设。

## 3. 第一工作包：剩余接线一次收口

本包不改父本与 v2 的聊天主变量，不重新返工已签收的码元修复。依据上一轮独立检查：

`refs/experiment_protocol_20261023/abc_independent_review_20261024/CHECKS.json`

该检查独立通过批注/候选测试 30 项，并完成 48 次替身请求，但发现以下实际差距。

### 3.1 真正按 slot 交错

当前 `tools/exam_interleave_plan.py` 把计划压成六个臂/故事运行，再整条 `run_episode(stop_after=None)`，因此实际是父本 T01–T08 后才跑候选，和计划不符。

改现有执行入口，按冻结的 48 个 slot 逐项推进。每个 `(arm, episode)` 维护自己的连续状态；一次 slot 只允许执行该轮。

可选择持续持有既有运行实例，也可用已有 checkpoint/resume；选容易正确维护的实现，不强制新框架。若使用恢复，派发前核对精确前驱，缺失、落后或超前都在调用前拒绝，防止恢复时暗中补跑历史轮。

E001 父先子后，E002 子先父后，E003 父先子后。不同臂不读对方输出或记忆。原始剧情中的 ME 真实消息保持相同，不把任何候选草稿填成已发历史。

### 3.2 接通授权后的真实路径

当前 live 分支无条件拒绝，且没有授权参数；这不是一个可用的实跑入口。

在同一执行器接入既有授权级预算与 openai_compat 适配器。capture 与 live 共用调度、状态、边界和记账，capture 只替换网络派发；无效授权零调用，有效授权在固定配置内执行。

不要另写第二套 live 调度器，不绕开授权，也不新增系统隔离。测试授权只能用于不能出网的替身路径，不得拿来连接真实服务。

### 3.3 校验实际顺序与冻结配置

当前轮次集合校验不能抓住同臂 T02/T03 互换。改为检查列表实际执行顺序、逐臂前驱、配对、臂映射及当前固定次序。无需设计通用调度语言；本批固定计划可以直接严格比对。

每个实际 attempt 记录 batch、slot、arm、episode、case、run、attempt 标识；据真实事件检查计划与执行序列完全一致，而不是根据预定计划重造一份“实际顺序”。

冻结候选依赖、题面、评分卡、评分器、执行器和实际端点/模型/采样配置。记录响应 model 等服务元数据。只改报告不产生重跑许可；付费执行后发现纯报告字段错误，先另加更正记录，不因重新绑定文档散列擅自重跑模型。

### 3.4 评审绑定与产物接通

`_match_annotation` 当前在评估侧 `case_input_sha256=None` 时跳过题面比较，仍可能继承旧 pass。新批缺 run、身份或题面内容散列任一项，就记未验证，不继承标签。

题面散列来自本次运行输入快照，不从评审时的活动工作树补造。明确区分 authorization_id、batch_id、run_id，不把授权 ID 当作永远唯一的运行身份；兼容旧历史字段时单列其含义。

两臂输出、EXAM_INDEX 与 `exam_layered_score.py` 一起接通，能从同一批次直接生成逐臂及配对报告。不要生成了答案后再让用户决定怎么搬目录。

候选新增上下文检查应覆盖 extras 与 recall 的实际渲染贡献。现有执行诊断只测【回忆】段，不能把该值称为二者总量；沿用已修好的联合预算算法，补真实渲染核验或准确命名，不重复发明预算单位。

### 3.5 本包仅需的合并验收

| 证据 | 通过条件 |
|---|---|
| 48 次 capture | 正式路径、零网络；真实 started/completed 与槽位一一对应，执行顺序符合冻结计划，六份连续状态互不串 |
| 拒绝反例 | 重复/乱序/缺失前驱、冻结身份或配置不符，均零派发；缺失题面绑定不能沿用语义标签 |
| 失败注入 | 第 5 次网关派发失败，5 started/4 completed/1 failed，立即停批，无额外配对补跑 |
| 评分接线 | 样本经实际输出目录生成分层记录；未评如实 unrated；真实渲染的联合预算满足候选声明 |
| 授权入口 | 无授权/无效授权零派发；替身环境下的合法授权可走通与 live 相同的配置和预算接线 |

已有测试只重跑受影响部分及关键相邻回归。无需再为了增加“全绿总数”重复不相关历史矩阵。交付一个可用入口、证据索引和剩余状态即可。

**本包验收通过后，不再安排一整轮只审文档的准备工作。** 已有有效用户授权就直接进入下一包；没有则一次提交精确的 48 次授权清单，同时继续下一阶段离线候选与公开题整理。真正影响实验正确性的失败不能为了赶进度隐瞒。

## 4. 第二工作包：完成第一组真实 A/B

### 4.1 本批保持原假设

保持当前已冻结的回忆候选，不临时加入调情、意图路由、prompt 删减等新变量。

- 对照：当前 reference_product_v1 与 v2_recall。
- 数据：现有 24 位公开开发题，双方各完整运行三条故事。
- 预算：新授权总上限 48 attempts，不含任何额外生成冒烟；探活不得生成额外答卷。
- 执行：按第 3 节工作包所述逐轮交错，无自动重试、修 JSON 补问、补跑另一臂。
- 失败：传输错误、授权拒绝、状态/身份/边界/计量异常立即停批。已发生的调用保留在成本与交付分母。
- 输出解析/合同失败先按原冻结计划的停止口径处理，不在批中临时改规则；“尚未语义批注”不是生成中停批理由。

调用开始前固定全部停止条件。若需要改变既有计划，离线统一改好再开始，不边跑边重定成功条件。

### 4.2 本批只回答什么

主问题是 E001_T06 的首选回忆表现是否相对同批父本改善，其他公开位有没有退化、额外成本是多少。

- 父 fail、子 pass：支持该开发假设，同时看保护位与代价。
- 双方 pass：这位未观察到优势，不能改报“输入注入成功”当最终输出收益。
- 双方 fail 或子更差：不支持，保留失败归因，不继续重试到赢。
- 评审不确定或样本不足：保留不确定，不编造成显著提升。

三故事是开发探索，不是充分独立样本。该批不能证明整个新架构、用户口味、完整后台成本或泛化成功。

### 4.3 同批完成内容初审，不再拆一次交付

生成收口后，由 worker 连续完成：

1. 逐位查看首选与所有非空备选，保留字段路径、原文和当时证据。
2. 按 24 张卡判断事实、意图、状态、主体、补充信息使用、无关回提与互动质量。
3. 生成批次绑定的语义批注、配对差异和故障族归纳。
4. 汇总真实 token、调用、时延和失败；金额未知就写未知。
5. 制作匿名重点样例，包含明显差异、双方差、普通闲聊、调侃/推进和不回；身份映射分开。
6. 给出候选建议：保留、淘汰或暂不定，并说明证据范围。

个人语气由用户抽样判断，worker 不代填用户愿发票。独立复核集中检查这一整批的证据与结论，不要求用户每位审批后才能继续初审。

## 5. 第三工作包：开始删除实验，不再只给旧架构加东西

当前回忆 A/B 收口后，立即进入这个工作包；当前授权等待期间可先离线准备，不改动已冻结的两臂。

### 5.1 保留三个不同角色

| 角色 | 用途 | 约束 |
|---|---|---|
| 原版参考 | 回答是否超过原版 | 来源与范围忠实，不偷偷删弱 |
| 最小对照 | 检验原版复杂度到底贡献了什么 | 简洁实现，同一可用外部信息，公开说明历史保留/检索限制，不预填标准答案 |
| 重构候选 | 尝试比二者更好的设计 | 可删资产、换存储、重做意图/上下文，不要求继承原版层级 |

“最小对照”不是无脑拿掉历史然后嘲笑它记不住。它应有一个明确、简单的上下文策略，例如受预算约束的真实事件记录；有意不支持的能力标出。具体方案由 worker 根据本地接口选择，避免先发明大量抽象层。

### 5.2 先做资产删减候选

第一个删除实验建议先保持父本记忆写读不变，只把长 system 资产改成最短可工作的任务与行为说明，保留必要输出用途。

保留的信息可以概括为：当前谁与谁交流、真实记录与私下备注的区别、当前目标、不要补造既成事实、期望的可用回复形态。具体文字由 worker 重写，不要求沿用 core.md 的章节结构。

system 精简候选与原父本比较，回答：

- 删除大量文本后，意图执行、事实和互动有没有变差？
- 原先被压平的主动性、调侃和关系推进有没有改善？
- 真正节省了多少输入 token？等待是否随之变化？
- 哪些明确失败可以归因于删除后缺失的任务信息？

可以离线准备多个删减版本，但先挑一个有解释的版本做真实对照，不把所有排列组合直接烧一遍。必要时再对候选中的某一块做恢复实验来定位贡献。

单独优化提示资产也是合法研究。不为凑“必须机制变更”额外加代码；后续规范中与此目标冲突的旧机制配额应明确修订。冠军主张仍需真实质量与代价证据，不能因只改了 prompt 就直接通过或直接否定。

### 5.3 输出合同另列变量

当前 48 次不要改输出数量。后续若大量备选没有用户价值，可以研究减少槽位或按需生成，但要先固定新的可用交付用途，再公平测试质量/选择负担/成本。

原版的多备选能力若被移除，报告它是功能交易；不能靠少交付获得低成本后假称所有能力不变。不以“凑够八句”本身加分，不把合法 null 视为必须生成废话的理由。

## 6. 第四工作包：机制重构路线

下面是研究优先级，不是要求一次实现全部，也不是当前实跑前置。worker 依据真实低分分布选择一个主要设计假设；同一故障族可以合并改多个文件。

### 6.1 意图：从长口号变成当前行动策略

目标不是每轮机械调情，而是当前目标能真实影响回应与后续选择。

候选需明确：

- 当前有效目标是什么，是否启用、已完成、撤销或被新目标替代；
- 目标与对方当前反馈如何协调；关闭目标不能被旧记忆重新激活；
- 何时承接、何时留钩子、何时推进具体机会、何时深入、何时停；
- 生活题材由上下文决定，不在策略里特化车票、到站、杯子等测例词。

允许强一点的表达、玩笑、暧昧、间接回应和情绪张力；评价看是否服务当下互动，不用“礼貌完整回答”代替所有阶段的质量。

测试相同对话在不同意图下是否产生合适差异，也测试意图切换、关闭、冲突、对方接招/犹豫/转话题后的调整。不能只测试“有一句意图文本进入 prompt”。

### 6.2 补充信息：可用，但不能混成已发历史

区分真实可公开事实、私下目标/情绪、未发草稿、对她动机的推测。候选可用清晰分区或结构表示，避免要求用户每次手工填写复杂表单。

正反例必须同时保护：可公开位置/日程能自然使用；私密情绪不意外传达；草稿不冒充已发送；推测不升级成她的确定想法；真实 ME 记录也不能因为“防编造”而被一律禁用。

遇到不确定内容应按上下文合理处理，不能把所有 note 都判禁止，也不能原样转发整段军师指导。

### 6.3 知识与记忆：更少的重复状态，更明确的来源

优先回答每种状态是否必要，避免同一事实同时散落在多个文件并各自变形。可以探索统一事件/事实表示、简单相关检索、按需摘要等设计，不预设必须某数据库或向量方案。

至少保留可追踪的事实来源、主体、时间/状态及纠正关系；具体字段根据实际使用决定。提议、确认、完成、取消、过期与重开用真实证据区分。

成对观察：

- 应回忆时用上，与不该回忆时不抢题；
- 对象 A 与对象 B 的同属性，与同一对象的新旧状态；
- 有明确字面线索，与低字面重合的自然追问；
- 记忆丰富时的质量，与上下文和本地处理成本；
- 生成/解析失败时的记录，以及跨轮/重启后的行为。

不要把关键词规则越来越长作为终点，也不要用塞入更多历史掩盖检索失败。若完整保留历史本身表现更好且成本可接受，也应作为一种方案公平记录。

### 6.4 调用和关键路径

每个额外模型调用必须说明服务哪个用户价值；取消没有收益的固定反思/重估，或改按变化触发。后台纳入比较时两臂都记录，不让后台免费隐身。

每轮至少观察本地组织耗时、真实输入/输出 token、模型完整等待、调用次数、失败及补救。未来测首字或首条可用候选时才加入流式数据，不从非流式总耗时猜首字速度。

## 7. 数据集建设：现在能测，随后扩什么

### 7.1 不等全题库写完才训练

现有 24 位立即用于当前实验。新增公开开发题可以与候选离线开发并行，但不修改正在运行的题。已经暴露的故事留在开发集，不能洗成独立集。

建议下一版建设目标约 20 个独立故事，每条约 8–12 请求位，总计约 160–240 位：开发约 12 故事（含现有 3 条），选择约 4 故事，最终验收约 4 故事。

**这是待建设的覆盖目标，不是已存在的题数，也不是统计充分性的保证。** 不为凑整齐强行截断生活线。长历史压力可以单列更长故事；每个候选不必跑完所有开发题。

### 7.2 覆盖矩阵

| 能力族 | 正向场景 | 反向保护 |
|---|---|---|
| 自然承接与话题转换 | 有关切入、新话题入口、钩子 | 不每句追问、不无故强转话题 |
| 情绪与关系推进 | 调侃接招、暧昧、邀约、深入交流 | 普通朋友不被一律恋人化；不把每次回复都当推进指标 |
| 意图动态 | 目标切换、阶段调整、关闭 | 旧目标不复活，最新有效目标不被陈旧标签覆盖 |
| 补充信息与真实历史 | 有用的公开事实、ME 真实经历 | 私下指导不直说，草稿不冒充已经发生 |
| 相关回忆与污染 | 跨话题追问、低字面重合 | 无关回提、错人、过期事实与取消复活 |
| 纠正与状态 | 否定、改期、完成、重开 | 提议不冒充确认，一次取消不变永久禁令 |
| 可靠性和负载 | 长输入、重启、失败、丰富记忆 | 不因裁剪丢当前目标，不无限增加调用和存储 |
| 收尾和重新发起 | 合适不回、新问题重开 | 不靠一律不回躲过难题，也不强行续聊 |

不同关系、生活领域、说话风格、时间跨度交叉分布，不用一个模板换人名。某能力没有覆盖就标缺口，不假报 PASS。

### 7.3 每个请求位的最低内容

沿用当前可导入 schema，不发明新的题库平台。作者交付：

1. 当前可见的真实 HER/ME 消息、时间、允许的画像/初始信息；
2. note 与 intent，作用范围清楚，不混进真实台词；
3. 评估侧的当时事实证据和引用位置；
4. 当前可接受的目标/行为范围，至少说明不同自然表达为何可行；
5. 明确失败条件与有争议的边界；
6. 首选/备选怎么审，以及后续行为检查；
7. 暴露状态、故事/模板族、覆盖标签与版本。

gold、卡、作者说明、未来剧情不进入 harness 请求。没有程序 gold 的开放语义位，按卡审，不把缺少断言算成通过。

### 7.4 连续互动与泛化

固定后续台词用于可复现回放，不能声称“考生让她产生了好感”。研究反馈调整时，另列分支条件、固定反馈或模拟器版本，检查模拟器偏好；最终用小范围真实使用补外部证据。

选择/最终题由未参与该候选调参的现有出题/保管角色处理；训练 worker 不读封存内容。已有出题会话可以继续，不需要创建新账号或新窗口。无人保管时如实登记缺口，不让这阻止公开开发实验。

## 8. 评分：评价目标、自由度、代价和谁来评

### 8.1 每位分层记录

| 层 | 记录内容 | 使用方式 |
|---|---|---|
| 运行合同 | 完成、解析、来源 ID、动作与交付用途 | 程序能确定的失败；不等同内容正确 |
| 事实与意图语义 | pass/edge/fail/unrated，加原文、证据和理由 | 事实/主体/状态/目标是否正确；允许不同措辞 |
| 互动质量 | 承接、意图执行、主动入口、情绪与分寸、可继续性；各项适用才评 | 沿用 0不可用/1明显需改/2基本可用/3可原样使用的锚定等级；不适用记 N/A，不强凑总分 |
| 用户偏好 | 愿发、改后愿发、不想发、理由 | 用户抽样标定，其他人不代填 |
| 污染与代价 | 无关侵入、捏造、token、调用、时延、本地复杂度 | 与质量并列报告，不能被均分盖掉 |

明确区分“内容准确但平淡”“有趣但捏造”“有意图但方式不合适”。用户要的正向能力必须在卡中出现，不能只剩反错题。

### 8.2 自由度

标准答案是事实、当前目标、必要边界和合格行为范围，不是唯一句子。允许新提议、间接回应、幽默、调情、短句、适当留白及合法不回。不同强度可以同时成立。

只有目标需要时才评推进或钩子，不要求每轮提问/调情。收尾时会停、深聊时会认真也是能力。LCS、禁词和长度只是诊断，不能代替语义。

首选与所有非空备选分审。保留“首选合格”“至少一个合格”“含严重错误备选”的三态与覆盖度；未评不当零错误，合法 null 不凑句。若输出合同改变，按共同交付用途比较，报告备选数量变化带来的功能和成本交易。

### 8.3 评价分工

- 程序：合同、可判定的事实夹具、预算、账本、来源/版本绑定。
- 训练 worker：全量初审、故障归因、原文证据、候选建议；没有权力代填用户偏好或仅凭自评宣布全面冠军。
- 独立评审：合并检查批次关键证据、语义/互动争议及晋级结论，避免为每个测试单独审批。
- AI judge：先辅助筛查。用明确正反例、自然变体、争议例检验误杀、顺序偏差、重复稳定性；未校准不能成为唯一裁判。judge 调用另计预算。
- 用户：每批重点抽样与阶段口味标定，不要求逐位审批几百题。已认可/不认可样例形成风格锚点，另保留未参与调参的验证样例。

匿名材料必须从当时冻结输入和原文生成，不手写“差不多”的上下文；A/B 顺序均衡或交换，提供双方都不好/都可用选项。评估材料只在评估侧可见。

### 8.4 晋级与保留规则

每批预先写清一个主收益指标、退化保护、成本/时延观察与停止条件。当前回忆批仍用原 H1，不重新定义。

后续删除实验可以把“质量在预定可接受差异内相当，同时减少成本/等待”作为主收益。可接受差异和重要权衡在看到结果前确定，不能事后选一个刚好让候选赢的阈值。

- 有明确质量收益，严重错误/污染不增，资源不恶化：可保留为开发改进。
- 质量相当且资源实质下降：可保留为效率改进。
- 质量换成本或反过来：列出实际交易，用户选择，不自动冠军。
- 没有观察到收益：不替换父本；可淘汰或记尚不确定。
- 独立选择题收益保住后，才冻结候选进入最终题；按最终题逐题回改后，那些题就已暴露，不再声称独立。

当前计划的 +20% 输入和 +15% p95 是工程警戒线，不是用户已同意的质量交易。不能把 24 个嵌套请求当 24 个独立故事做显著性宣传。初期报告故事级与逐位差异；重复采样必须另外预登记，禁止试到赢。

## 9. 成本、时间与实验预算

固定的 dsf 名称之外还记录响应 model/服务元数据、采样、最大输出、缓存与时间条件。未知信息标未知，不伪造服务实现。

每个实验计划给出：

| 项 | 必须有的内容 |
|---|---|
| 调用清单 | 候选、故事、完整前史、请求位、每位调用策略 |
| 数量计算 | 全部生成、更新、辅助、修复和失败；评审调用另列 |
| 授权 | 新批 ID、端点、模型、温度、attempt 上限、有效状态 |
| 账本 | authorization 级持久占额，换 run/改报告不重置 |
| 费用 | 实际 usage 和有来源的单价；无单价只报 token，不说免费 |
| 时间 | 本地准备/检索与完整等待；p50/p95/max/n和故事总耗时 |

当前单调用两臂三故事是 24×2=48；再加入一个完整候选同跑是再 24，不能在原预算内悄悄增加。若只选部分故事，两臂都按该故事完整前史运行；不能只调用后测位却给候选预填正确记忆。

离线录制回复重放用于诊断，不当作候选真实输出或其真实 token 成绩。旧父本结果只有在信息、身份与比较目的真正相容时才可复用；跨时段结果不能直接证明延迟优势。

降低研发消耗的方法是：先离线淘汰明显错误方案；少量完整开发故事筛选；保留者再扩大覆盖。不是删掉所有反向保护，也不是每次重新跑全题库。

## 10. 每轮只交一份有结论的整合报告

沿用已有格式即可，最低需要以下内容；不要求再搭报告系统：

1. 一句话：本批改什么，实际跑了什么，保留/淘汰/不确定。
2. 身份与实际配置，题/卡/评分版本和暴露状态。
3. 授权与真实 started/completed/failed，停止条件是否触发。
4. 配对结果：胜/平/负/双方失败/不确定，首选与备选分开，逐位证据可点开。
5. 质量/污染/调用/token/等待差异，遗漏或未评覆盖。
6. 代表性原文与故障族，分清候选问题、量尺问题、基础设施问题、采样不确定。
7. 本批局限，下一批唯一优先假设与合并调用清单。

建议复用并补齐现有产物：CALL_MANIFEST/INTERLEAVE_PLAN、真实 calls 与 manifest、ANNOTATIONS、分臂 LAYERED_SCORE、PAIRED_DIFF、EXAM_REPORT。名称可与现工具一致，不为改名搬动原始证据。

不要再把“第几波/多少自检/多少包内文件”当主要进展。汇报第一屏回答：真实比较发生了吗，用户体验哪儿改善或失败，花了多少，下一代留什么。

## 11. 推进节奏与停止规则

### 立即执行

连续完成第 3 节工作包，最多一次合并交付。若中途出现实质阻塞，给具体错误、最小复现和可选替代，不在几轮报告里反复写“差最后一步”。

接线检查通过且有有效授权后，直接执行第 4 节工作包并完成全量初审，不另加一次“是否继续读输出”的确认。

### 同时可做的离线工作

在不修改当前冻结实验的前提下：准备 system 精简候选、最小对照设计、公开扩题、现有用户风格锚点与下一批计划。缺授权不意味着只能停着等；但不能擅自调用付费生成，也不能把等待掩盖为又一次平台工程。

### 后续循环

每批从最有价值的故障族或无效组件选择一个主假设；可以大改同族实现。候选结构由证据决定，不是固定一轮一个窗口，也不创建无人监管的自进化脚本。确定性计划执行与汇总可以用现有工具自动完成。

同一方向连续三批没有实际价值，暂停该方向，优先测试删除/替代或换更有价值的故障族；不为了把一个已知节点刷成 pass 无限修补。这个规则是研究资源止损，不是保证三批内成功。

不虚报小时级工期。每批报告实际开发/验证/生成/评审耗时与阻塞原因，识别时间耗在哪。完成一批真实比较比再增加一批不相关自检更优先。

## 12. 什么时候算阶段完成

| 阶段 | 完成标准 |
|---|---|
| 可用考场 | 能正确输入、独立维护状态、真实调用、预算约束、保留证据并按卡评估；不再要求额外系统部署 |
| 第一次有效机制实验 | 当前同批父子真实对照与语义/资源结果完成，允许结论为没有收益 |
| 组件贡献有证据 | 最小对照与至少一次重要资产删除/替换实验完成，知道某些复杂度是否值得 |
| 重构候选有开发价值 | 意图、补充信息、记忆/上下文等相关目标在不同公开故事上改善，且代价可接受 |
| 有迁移证据 | 未参与调参的选择故事上收益保住，没有只记住开发题 |
| 可交付新版 harness | 冻结最终候选，独立验收、用户抽样体验、所宣称模式/后台/恢复/性能范围验证，输出原产品接入清单与回滚方案 |

“monster”不是预先保证的结果。最终应能展示它比原版在哪些能力上更强、什么代价、哪些场景仍不行，而不是一个脱离原文和覆盖面的总分。

## 13. 给现有 worker 的立即执行口令

你是训练执行者，直接执行本指导书，不只提出计划。先核对第 2 节当前状态；已有通过部分保留；连续合并处理第 3 节工作包，不扩考场、不创建新会话、不部署系统账户。

第 3 节工作包通过后：若已有用户有效新授权，按第 4 节工作包执行并交真实比较结果；若没有，提交一次完整调用清单，并继续第 5 节工作包的离线候选准备及公开扩题，不冒烟、不复活旧授权。当前用户要求指导书不等于真实调用授权。

候选可删除和重构原版提示词与机制。原版参考必须公平；任何规则若把“复杂、保留旧资产、多写备选”当能力本身，应按本轮目标明确调整后再用于下一批。正在运行的实验不临时换量尺。

下一份交付先展示“执行入口与剩余接线是否真正完成”；有授权实跑后，下一份主要交付展示真实答卷、质量与代价、保留/淘汰结论。不要再次只交一份“离线全绿、等待下一波”的总结。

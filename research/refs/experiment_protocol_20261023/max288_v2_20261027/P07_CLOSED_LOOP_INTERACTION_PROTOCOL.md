# P07_CLOSED_LOOP_INTERACTION_PROTOCOL — 受控闭环互动实验（真反馈，不靠固定下一轮替候选证明）

签发：2026-10-27。状态：设计冻结，实跑待候选基座模型（dsf 已失效；本轮先按 gemini-3.8-flash 可用规划，
正式候选基座与 reference 需在**同一模型**上重建公平基线后再跑，绝不跨模型冒充收益）。
驱动来源：WORKER_MASTER_EXECUTION_V2.md P07 与 §"真闭环互动子实验"（用户新增、旧计划缺失的第 6 类能力）。

## 0. 为什么固定回放不够

P06 的固定回放里，后续 ME 消息是题作者写好的真实历史，**不是当前候选回复被真的发出去后的世界**。
所以固定回放只能证明“同一输入下谁答得好”，不能证明“候选能否根据对方真实反应调整、推进、修复误解”。
闭环实验专门补这一维，且结果与固定回放**分表**，不混。

## 1. 最小单元与随机化

- 8 条专用分支故事 × 4 类对方反馈条件 = 32 条分支轨迹；首批每条轨迹 4—6 个候选决策，确认模拟器有效再扩。
- 32 条不是 32 个独立人物：统计单位仍是**故事/共享人物轨迹**；按故事宏平均，位点微平均另报。
- 反馈条件（每轨迹选一主条件，可含一次切换）：积极(engaged)、含糊/害羞(ambiguous)、忙碌(busy)、
  明确不愿继续(refusing)。各臂**成对使用相同初始人物 + 相同反馈条件分布 + 同一随机种子方案**。
- 冻结：对方模拟器版本、system/params 身份、状态机、随机化表、发送策略。

## 2. 发送策略（派发前固定，不得事后从备选挑最好句）

对每个候选决策位：
1. 只取 harness **首选（recommended）** 作为“实际发出”的文本；
2. 首选不可消费（空/协议失败/非法 JSON）→ 记**交付失败**，本轮视为无正文发出（对方按“没收到实质回复”反应），
   并计入任务失败（V2：严重交付失败不被平均分掩盖）；
3. 合法 no_reply（候选显式选择暂不回，符合共同动作协议）→ 不发送，进入对方“未获回复”状态；
4. **禁止**人工从 bad_boy/playful/warm/directions 里挑最好的一句冒充“候选首选成功”。备选只作展示，不闭环。

## 3. 对方模拟器（也是真实实验调用，单独 purpose 计数）

- 模拟器读“已发送文本 + 冻结人物/生活动机 + 当前反馈状态”，生成下一条 HER 消息；
- 用同一固定模型（候选基座选定后一并冻结），但候选与模拟器**成对同种子同初始**，避免偏心；
- 模拟器可以自然改变反应，但不得按候选身份/标签偏向，也不得把“裁判认为正确的下一句”直接喂给候选；
- 每个模拟回合都是登记在案的 API 调用（purpose=`partner_simulation`），计入预算/等待/用量。

## 4. 候选侧上下文纪律

- 候选后续上下文使用**实际模拟发生的对话**（ME 侧用候选自己真实发出的首选，不再注入题作者的“理想 ME 回复”）；
- 默认不把生成草稿自动写进记忆；只有闭环里“真的发送并选中的首选”才作为 ME 历史写入，并标 `source=simulation`；
- 初始画像/共同知识按来源归档，模拟器新信息进入记忆要有稳定 uid/角色/时间，别和固定回放混。

## 5. 评测维度（只报“受控模拟效果”，绝不声称现实关系成功率）

- 互动推进：该展开时是否给了对方可回应入口并推进；该收尾时是否自然结束；
- 误解修复：含糊/害羞条件下能否澄清而不硬撩、不把犹豫说成欲擒故纵；
- 邀请生命周期：模糊兴趣 → 具体可选择安排 → 提议/确认/改期/取消，且不谎称已订已买；
- 主动话题得到具体回应的比例；反馈积极时是否敢主动推进与具体表达；
- 九维仍逐条评（复用 QUALITY_MANUAL_V1_1，裁判可与候选不同模型并登记），但**闭环专属指标单列**：
  `推进率/修复率/交付失败率/合法no_reply正确率/误解未修复率`，分母按轨迹与决策位分别报，未评不推定安全。

## 6. 失效防护（先测模拟器再上结论）

- 亲读每种反馈条件的成功与失败轨迹，排查模拟器**过度迎合**（无论说什么都答应）或**无反应**；
- 发现该失效：先修模拟条件/停止该轮，不得用“模拟器打满分”冒充候选有效；
- 每种反馈条件至少给一条成功 + 一条失败轨迹的原文证据。

## 7. 与现有链路的接线（复用，不重造平台）

- 候选仍走 `arena/lb_runner` v2 生命周期 + `IsolatedRun` 居民隔离；一条轨迹=一个居民，跨轨迹状态不串；
- 发送策略/模拟器/轨迹编排在**薄编排层**（新工具，不改共享执行器），按 `exam_interleave_plan.execute_plan`
  的配对与冻结身份方式登记；
- 调用分账：候选生成、对方模拟、语义评审三类 purpose 分别记账；每类各自有限授权；失败消耗不退款；
- 派发前冻结：题/卡/人物/反馈分布/发送策略/模型与采样身份/随机种子，capture 验出站白名单与数量，再 live。

## 8. 额度与阻断

- 先小样：每轨迹 4—6 决策 × 32 轨迹 ≈ 候选 ~160 生成 + 对方 ~160 模拟 + 评审若干，各建有限新授权，上限不是目标；
- 当前阻断：候选基座 dsf 已失效；正式闭环前先在同一直连可用模型上重建 reference 基线；
  裁判 gemini-3.8-flash 可用（见 P06_JUDGE_INTERRUPTION 记录）。

## 9. 出口

固定回放结果与闭环轨迹**分列**。闭环只在“受控模拟互动”意义下支持：某候选能否据真实反馈调整/推进/修复/收尾，
以及其交付失败与误解率。不支持：现实关系成功率、用户愿发 W（仍 unknown）、产品接入（仍暂停）。

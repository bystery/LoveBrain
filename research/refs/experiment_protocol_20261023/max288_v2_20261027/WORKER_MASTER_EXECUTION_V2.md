### P05-B 整合证据记忆与上下文分支

在同一目标分支上加入证据记忆/选择，必须可关闭，不能把“两个机制相加”当收益证明：

1. 原始真实事件日志不可用模型草稿污染。每消息有稳定全局uid、角色、时间、原文；当轮m0等别名仅映射，不用跨轮裸编号作为来源身份。

4. 来源成员和引文存在是硬校验，语义支持是另一层。主体无法确定或引文只支持一部分时，不凭字符相似度直接confirmed；保留原文与未核验摘要，避免将摘要投影成确定事实。
5. 初始画像/共同知识按来源归档，不能假装本轮对话新确认；同一初始事实在seed块与facts块去重投影。ME/HER/第三人的事实不可互换。
6. 上下文优先保本轮真实输入和有效指导，再选必要近期交流单元、相关旧事实、尚有效事项。窗口不足优先整条消息/事实截断，不截坏字符；保留最近纠正，抑制过期目标和无关回提。保留原始历史比例高并不扣分。
7. snapshot/restore后引用、纠正状态、目标关闭和原文索引不丢失；必须真的重启宿主再继续一轮，不只检查文件存在。

### 共同实现要求

- 兼容现有入口：`init(assets_root, episode_meta, gateway, sandbox)`、`run_turn(h, ctx, gw)`返回`{"reply":原始文本,"notes":审计说明}`、`snapshot(h)`返回可恢复字节、`restore(sandbox, snap)`返回可继续的状态。以当前宿主实际契约为准，不为新候选另造宿主。模型生成继续走提供的`gw.generate`，不能直接HTTP绕账。
- 同一候选只有一个实际生效的输出契约。需要的analysis字段与写回一致；字段不是越多越好，没消费的报告不要强制生成。
- 首选与每个非空备选是可发文本，不是“你可以这样发”；用户功能数量沿已登记契约，改变必须报告选择能力变化，不能靠删掉难槽位冒充质量进步。
- 新提议、未来承诺、玩笑和观点不能误判为已核实事实；确定亲历/已买已订/已知对方动机要有根据。
- 不增加隐藏模型调用。允许研究两步/路由等调用策略，但必须另作候选变量，全部计入预算/等待/用量；不能悄悄替换固定模型。
- 新候选不能运行时修改父本全局函数污染别的臂。复用现有加载/装配原语，避免又造平台。

最小实施验收表（每项实际经过run_turn请求捕获或状态读写，不只搜规则字符串）：
目标启用/调整/停止/替换；无目标不续旧邀约；私密草稿不入历史；第三人关系正负对；否定/纠正不误杀；提议与确认；跨日时间范围；当前消息不被预算挤掉；正确旧事回扣与无关旧事抑制；含糊反馈多动作选择；积极信号主动推进；明确收尾可结束；恢复后继续正确一轮；两候选间状态无串写。

交付不是“夹具全绿”：必须有两个新身份、实际请求变化、真实状态样例和下一节能直接执行的计划。随后立即进入P06。

固定回放与闭环严格分开：E/P旧题后续ME消息是题作者给定的真实历史，不是当前模型草稿被发送的证明。默认不得将生成回复自动提交进记忆；只有闭环实验的发送策略真实选中并提交后，才加入模拟ME历史并标注simulation来源。无图素材/图片未实际出站时不当视觉能力测试。合法no_reply在可用场景按共同动作协议消费，不强迫为了评分凑一句。

## 7. 所有后续工作共同使用的测量细则

### 7.1 单位、缺测与记录

故事/共享人物轨迹是独立聚类单位；位点、回复、备选、事实主张、需要召回的事实分别是不同单位。每条记录有 `experiment_id/story_id/case_id/arm_identity/input_hash/output_hash/slot/rubric_version/reviewer/source_quotes/applicability/verdict`。

`NR`=未测；`NA`=不适用；`uncertain`=已审仍不确定；`0/FAIL`=实际失败，不能互换。未知主张不自动判编造，先判断是否将不明信息作确定事实。无可核事实的玩笑/观点，不因找不到来源扣事实分，也不当作满分事实样本。

首选和每条备选分开。至少一个可用率：至少一个已确认pass则true；所有实际选项都评完且均fail才false；其余unknown。严重备选错误率报告已审分母、缺测及上下界，不能把未审当0风险。

### 7.2 质量九维与扩展切片

沿现行0—3：目标动作、事实、人物归属、时间/状态、信息边界、记忆使用、自然互动、主动钩子、情绪关系调节。0错误/反向，1关键欠缺，2合理完成，3有具体实质增益；NA要有理由。另按任务标签报告深聊、转场、反撩/调情、邀约、接受/犹豫/拒绝后的调节，不把这些全部压成一个interaction均分。

“是否当场会推进关系”不能只搜目标块；实际发出合适行动才算。目标可给方向，不提供唯一标准句。收尾没有钩子可正确；有钩子不等于必需问句；回复更长/更短本身均不加减分。

### 7.3 知识链：定义分母，防止在场率冒充质量

每个故事的标注原子有来源、主体、时间/状态、该保留期限和需要它的位点：
- **Capture recall** = 在检查时仍应保留且可从候选合法状态恢复的原子数 / 应保留原子数。按原文事件/模型摘要/静态知识分列；保住整条原文不证明其中事实都能正确使用。
- **Fidelity/support precision** = 有源证据语义支持的已存派生记录数 / 已核验已存派生记录数。源ID有效率单列；主体、否定、时间、状态错率单列；未知支持不悄悄排除，报其比例与上下界。
- **Update correctness** = 需纠正/撤回的原子中生效视图已更新者 / 实际纠正机会。保留历史档案不算污染，只有被当现行事实再用才算。
- **Retrieval recall** = 本轮确实需要且实际请求有足够证据的原子数 / 本轮需要的旧原子数。不是“全部历史×所有以后轮”。
- **Context precision** = 被评估为与当轮动作/约束相关的注入条目 / 实际旧知识注入条目；条目划分和NA声明，字面重合只作检索候选证据。
- **Use correctness** = 实际回复对需要的原子正确遵守/运用的次数 / 可评需要机会；显式复述不是唯一成功形式，不硬塞历史也可满足约束。
- **Contamination** = 旧目标、无关事实、错误摘要被不恰当带入正文的可核错误数 / 相关可评回复数；区分误注入与生成误用。

同时报每轮条件、逐故事结果和错误实例，别把所有链段平均成一个“知识分”。摘要条数多、structured比例高不加分。

### 7.4 裁判可信度与自由度

每维独立控制：检出、漏检、保护误杀、NA识别、同题重评、甲乙换序，以及同内容在首选/备选槽交换。声称新事实的确定断言与观点/玩笑/提议/条件句分开；岗位不证明本次亲历。引文核对的空白/标点归一不能改变人物、否定、数字或时刻。

裁判检测到major却给该槽事实高分，记内部不一致，回原文复核；不静默刷一次模型求更满意判词。当前开发控制没有独立保管，不能因32例达标就称全面已校准。同服务多次评审不是多个独立模型。用户W只由用户实际选择产生。

### 7.5 比较与决策

不默认等权平均九维来选冠军。每个实验预登记一至两个主要质量假设，其余作退化保护；同位点报告胜/平/负/不确定和严重错误。事实重大错误独立列示，不用更主动或更便宜抵消。重大错误定义与容忍边界在看到新结果前冻结。

先逐故事，再按故事宏平均；位点微平均另报。重复运行不能当新增独立故事。区间按故事聚类，样本少明确不稳定。可设事前实质差异容限，但不能从旧最高分事后抄“差0.2即非劣”。没有功效/精度依据不宣称N=96足够。

研究阶段可凭反复原文证据保留一个方向；“产品可替换/整体优于原版”需更强未调参新故事证据。无法选冠军可以是有效实验结果，接下来改最大质量短板，不能回到全局NR。

## P07｜主动话题、钩子、调情与深聊专项（约12—30h，多轮）

首批至少8条新自然故事，分普通朋友/投缘新友/双方已有暧昧三类。每条既有平淡日常，也有可推进点和明确不该推进点。机制必须提供内容，不只“接话还行”。

1. 话题枯竭：能观察旧话题结束，提出对方可轻松回应的新角度；不靠虚构ME经历和连续盘问。
2. 钩子：观点、轻挑战、具体小选择、俏皮反抛、留白分别取样；区分有信息的新切口和装神秘、无意义吊胃口。
3. 互动张力：合适时能反撩/调侃、把球抛回、邀请对方表态；随反馈松紧变化，不能所有含糊都逃回防御套话，也不能将明确犹豫/拒绝说成欲擒故纵。
4. 深聊：对具体观点、经历、矛盾情绪有实质回应，允许不同价值观；不把长篇安慰当深度。
5. 邀约：由模糊兴趣到可选择的具体安排，未确认不报已订已买；对方改意图后会调整，不死守旧目标。
6. 对旧机制做同输入反事实：无目标/+一般目标/+战术备注，测可观察行动差异及是否只复述指导。三种条件共用相同事实，控制身份另列。

参考卡以“交流动作与是否给对方可回应入口”判，不写唯一台词、强制问号或强制暧昧。公开开发专项可持续修改，结果不能当独立泛化。每次真实新失败合并到动作机制/上下文选择，不能只扩一张AI味词表。

### 真闭环互动子实验（不由固定下一轮替候选证明成功）

用8条专用故事，每条选择积极、含糊/害羞、忙碌、明确不愿继续等4种对方反馈条件，做32条分支轨迹；第一批先每轨迹4—6个候选决策，确认模拟器有效再扩。不同分支不是32个独立人物故事。

发送策略派发前固定为“使用首选；无可消费首选则记交付失败；合法no_reply则不发送”，不能人工从备选挑最好的一句再说harness首选成功。模拟对方读取已发送文本，按照冻结人物/生活动机和当前反馈状态响应；候选后续上下文使用实际模拟对话，不再注入题作者预写的理想ME回复。

对方模拟API也是实验调用，单独purpose计数；同一模型扮演对方不等于真实用户实验。冻结对方版本、状态分布及随机化方案，各候选成对使用相同初始人物与反馈条件。对方可以自然改变反应，但不能按候选标签偏心，也不能把“裁判认为正确的下一句”喂给候选。评审可评已观察的互动推进、误解恢复、邀请从提议到确认、主动话题得到具体回应的比例；只能称受控模拟效果，不能声称现实关系成功率。

固定回放结果与闭环轨迹单列。至少亲读每种反馈条件的成功和失败轨迹，排查模拟器过度迎合/无论说什么都答应；发现这种失效先修模拟条件，不能拿它把所有候选打满分。

## P08｜未调参故事与反事实泛化（约12—30h）

先冻结候选后揭晓本轮验证材料。优先用P02中16条未调参验证；如果开发者已看过，登记暴露，不能叫独立封存。真正外部独立出题若可用再单列，不搭新权限系统。

最小变化对照：只换主体、只换否定、只换目标状态、只换事件日期、只换关系阶段、只换“建议/已经完成”的措辞。各自期望有些动作变、有些事实保持；检验是不是靠场景关键词触发固定话术。

测试“开发集高分、换题失效”和“正确但过度保守”两类退化。新验证只用于报告或淘汰，不能边刷边仍称未见。修改后的候选使用下一份保留集复验。样本批量先小后大，初批明显无效就修设计，不照计划烧满。

交付逐维开发→验证差异、关键错误变化和依据；不能只给一个总平均。

## P09｜长历史、纠正链、跨日与真实恢复（约12—30h）

至少8条长故事，每条40—80真实事件/请求节点，依据实际上下文预算安排，保证目标事实真正离开近期窗口。原文完整在prompt时，不能宣称“长期记忆召回”。

每故事包含：早期偏好/约定，其他自然生活插曲，第三人相似事实，一次更正/改期/取消，长间隔，至少一次真正宿主重启，之后需要正确约束的请求。资料可恢复与请求采用分开。

同时留无记忆/无投影小型消融；诊断分支是机制因素控制，不硬占整个正式批的一半。错误定位到写入、保真、状态更新、选择、注入、生成使用或消费，不一律归咎模型。

正反保护：真实已确认的未来约定跨日仍可用；已取消不复活；同名不同人不串；同一人新一轮同类活动不被旧取消吞掉；没有可靠记忆时自然问/承认不确定/给新建议，不谎称已发生。

## P10｜因果消融与结构重构，不只是继续加规则（约16—40h）

根据P06—P09确定入围架构，做预登记成组消融：
- system资产：旧core/精简core、自然表达规则有无、重复底线/冗余说明有无；输出功能不能偷偷删。
- 意图行动层开/关，反馈调节开/关；不把去掉一个模块同时换了一整套契约说成该模块纯因果效果。
- 原始事件记忆、结构化投影、选择器分别开/关或替换；检查长期正确使用与污染。
- 上下文预算/当前输入优先/旧事实重排；测质量变化，不预设更短最好。
- 单步vs明确登记的多步调用策略；所有调用、等待、用量计入，不隐去额外“思考”。

每组先用敏感故事小筛，入围后在相同冻结故事和随机/轮换顺序重复。变化参数、提示词、消费契约分别登记。若只证明整套组合有益，就报告组合收益，不虚构每个组件贡献。

允许彻底删除无用旧资产或重写旧机制；不为“借鉴原版”保留无效复杂度。三轮同类细调无可复现收益，停止继续加同样规则，转向更简单参照、数据/评价盲区或不同机制假设。

## P11｜质量约束下的性能、费用与可靠性（约8—24h）

质量优先不代表整周期不记录性能。所有真实调用从开始就收usage/timing，此包才集中优化和决策：
- 传输、原始协议、消费成功、首选可发、语义任务成功五层分列；零宽键等共享协议故障不独占归因给某候选。
- 首内容、首选完整且通过消费验证、所有选项就绪、落盘时间分别测；角色delta/心跳不算首内容。没有消费回调就NA，不拿完成时间倒填。
- p50/p95/最大值与实际样本数，分别报端到端和模型服务等待；无分段证据不解释长尾成因。小n的p95只作样本描述。
- 输入/输出/缓存/失败/额外调用用量；缓存unknown不填0；无可靠单价金额unknown。每语义成功结果token与每消费成功结果token分别报。
- 比较协议约束、流式、上下文选择、缓存前缀稳定性等改动时，两臂同API配置；不能把流式与旧非流式表无缝拼成提升百分比。
- 维护复杂度包括实际模块/依赖、状态种类、额外模型调用、变更风险和恢复路径；代码行少或文件少本身不等于更优雅。

质量未过线时资源收益只能保留效率方向，不能晋级冠军；质量相当且未解释的重大错误不增时，效率收益可单独支持保留，不要求回复文字更短。

## P12｜研究级阶段决策和下一代任务（约8—24h）

主报告按论文结构交：任务与范围、原生/移植基线、数据组成和暴露、候选谱系、评估与资格、实验设计、主结果、消融、失败案例、成本/等待附表、限制和可复现入口。

必须交的矩阵：原版声明范围与限制；各实际参赛候选同面板九维；知识链；主动/调情/深聊/转场/收尾切片；重大事实错误；首选/备选；开发与未调参验证；资源和实际等待。无实测版本NR，不画v1→v5必然上升曲线。

正式判断分四档：淘汰、保留开发、某范围领先、具备更广替代证据。每档写适用关系/故事/窗口范围、相对什么基线、哪些失败还在。用户W未收集时不宣布“最像用户本人/用户最愿发”。本周期即使达到研究门槛，产品接入仍暂停，除非用户另行恢复；不能自动切Android生产默认。

## 13. 真正持续续推的规则

### 13.1 单轮闭环

`真实质量缺口 → 可检验假设 → 机制/资产改动 → 必要离线保护 → 新身份/冻结计划 → 真实比较 → 证据审核 → 保留/淘汰/重构 → 下一缺口`。

每轮至少解决一类高影响使用问题或得到能改变设计选择的反证。报告数、测试数、候选编号、调用数不是进度。不要求永远正向；发现某复杂机制无益并删除也是进步。

同一候选最多连续三轮相同类型的小修还无可复现收益，就转另一架构/简化参照/测量盲区。不得用连续改措辞代替机制研发。每一轮都维护回归保护，防止只会已知故事。

### 13.2 节奏与恢复

按当前完整任务工作，不靠每15分钟巡检切碎主线。真实worker在完成节点、长调用批启动/结束和中断前保存状态；在平台允许的活跃期间继续，不把自动化卡片或陈旧RUNNING当存活证据。心跳与原生进程/日志进展分开判断，观察失联不等于失败。

每4—8小时交一次简短真实里程碑；不等汇报后用户再说继续。只在任务真实需要前台操作时拿短锁，不锁住整个数小时实验。无持续运行能力就明确依赖现有调度/人工恢复，不谎称会自动醒来；本文不创建新窗口或定时器。

跨上下文恢复只需读本书、`RUN_STATE.json`、当前任务输出与实际账本尾，不读整周聊天。状态里列：有效入口、冻结身份、已完成清单、正在运行的原生ID/PID、已用次数、不可重复操作、下一条具体动作。重启先查是否已经完成，不能因没有done文字就重跑。

### 13.3 早完、卡住、到288小时

早完继续按价值排序：最严重可复现质量错误 → 正向聊天能力缺口 → 长链/主体状态 → 新故事泛化 → 有疑问的组件消融 → 质量相当后的效率。队列少于两个完整实验时主动补下一批设计与材料，不等用户塞任务。

模型/权限/设备/个人口味某项阻断，登记精确条件并继续不依赖它的任务。用户W和产品设备不阻塞本周期。所有任务都确实受阻时如实报告最后证据和恢复动作，不能前台sleep假装持续工作。

到288小时若仍有高价值问题，按同一规则开启下一研究周期，先写新假设/停止条件/有限预算，不重置历史累计消耗。没有新假设就做错误分析或数据/参考核验，不随机刷候选与调用。

### 13.4 预算如何连续而不失控

本周期新增规划管理上限16,384 attempts，**不包含已经关闭的173评审和其他旧消耗，也不是必须花完**。阶段细目在同目录JSON，按实际实验逐批新建授权/空账本，生成、命题/对方模拟、裁判分scope；既有未用许可先核对去重，不叠加隐形余额。各批先预检整批需求，再发；不把阶段总帽当无身份的大钱包。

每批完成、传输失败、消费/解析失败、未决都入账；失败消耗不退款。确定无效就提前停，未耗预算不自动补满。预算登记是执行职责，不再称“用户没口令”而原地等。

阶段未开始的额度可按新证据重排，但已冻结授权/已占额不得原地增大；变更写补充登记且累计不超过本周期帽。若耗尽16,384而仍有明确新研究目标，依用户持续迭代指令为下一周期建立新的有限额度与累计对账，不复活旧批或把失败批改名继续。若用户撤回持续授权、指定新的费用上限或要求停止，立即以该指令为准。

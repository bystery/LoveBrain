# v5_purpose_aligned — 用途对齐的简化 harness 候选（可实测版）

**主假设（REVIEW §三 B）**：让**输入、内部状态与输出按真实用途对齐**——删除本 harness 从不消费的
内部摘要，同时把"未知资料"从"多加禁止词"转成"合理行动选择"。继承 r2 的简化真实事件记忆 +
目标作用域/上下文优先级 + 三项输入边界护栏；r2 与原版保持冻结不动，本候选另建新身份。

## 相对 r2 的两项设计变量（整套比较，不单独归因）

1. **B1 删除不消费的内部摘要**：r2 生成后只取 `res['text']`，从不读回 topic/scene_facts/ongoing
   维护状态，却仍按旧格式每轮要求生成完整 analysis（实测约占原始 JSON 字符 41.87%——**字符占比，
   非 token 占比、非预计节省比例**）。v5 采用最小兼容改法：`analysis` 固定输出空对象 `{}`，
   **保留** response 四风格、directions 四方向及合法 null 语义，不改用户可选文本数量、不要求短答。
   真实事件的来源/说话人/时间仍由 harness 自己从消息保存。
   - 诚实边界：删内部摘要后，"analysis 来源错误"不再是同等测量项，**不能把这一项变少单独宣称为聊天
     真实性或记忆能力提升**；事实/状态仍要审真实回复与真实事件行为。协议可沿用已由
     EMPTY_ANALYSIS_PROTOCOL_PROBE 离线复算（24 份候选原答卷 analysis→{} 合同仍合法、程序分不变），
     但这只证协议兼容，不证 v5 生成更快/质量不变/已省 token——必须实跑。
2. **B2 事实与行动的区分（通用装配规则，非按后摇/凤凰山/耳塞等素材特判）**：信息不足时仍可推进
   （查场次、比较、表达兴趣、提时间/路线建议、允许玩笑调情）；只禁把未查明说成已查明、把希望说成
   已发生、把一般常识冒充本次现场/路线/设施/天气、把新提议冒充已有装备或既有亲历；私下目标转自然
   商量不冒称她已同意、关闭后不让其它备选再推同一邀约；首选与方向槽都必须是收信人一致的可发正文
   （非"你可以这样发"类操作指令）；已发生后据回顾收尾不复活旧约。

# v5_purpose_aligned — MECHANISM（用途对齐的简化 harness：r2 架构 + 删未消费摘要 + 事实/行动边界）

登记为整套架构（依 REVIEW §三）。继承 r2 的四项决策，另加 B1/B2 两项设计变量。

## 四项决策（沿用 r2）

| 环节 | 策略 |
|---|---|
| 存储 | 简单有序真实消息事件（只收实际发送的 HER/ME，每条带 uid+role+ts；模型回复是草稿，绝不写回）+ 种子事项 `plans`（来自 initial_kb.ongoing_plan） |
| 检索/注入 | 历史整段预算 ≤`MAX_EVENT_HISTORY_CU`；当前窗口逐条 `m<i>` alias + 稳定 source_id + canonical_id_map，整条不被裁 |
| 意图 | 解析 `input.intent`(enabled+text+status)，有效才进【当前目标】区（预算保护），关闭/替换不留旧目标；目标可指导行动但不复述/不谎称已同意 |
| 上下文组织 | 种子画像 → 当前目标 → 已确认事项（独立于目标、持续）→ note 四类 → 真实历史 → 当前窗口 → 时间；三护栏（来源/媒体/时间作用域） |

## B1 用途对齐的输出协议（本版关键差异）

- r2 执行器生成后**只取 `res['text']`**，从不读回模型自撰的 topic_status/scene_facts/ongoing 来维护状态；
  却仍按旧 format 每轮要求生成完整 analysis（实测约占原始 JSON **字符 41.87%**——字符占比，非 token、非预计节省）。
- v5 最小兼容改法：`format.md` 将 `analysis` 固定为空对象 `{}`，删除只为这些未消费摘要服务的生成要求；
  **保留** response 四风格、directions 四方向及合法 null；不改用户可选文本数量、不设短答目标；真实事件仍由
  harness 从消息本身带来源/说话人/时间保存。
- 已由 `EMPTY_ANALYSIS_PROTOCOL_PROBE.json` 离线复算：24 份候选原答卷 analysis→{} 后合同仍合法、程序分不变。
  这只证**协议可沿用**，不证 v5 生成更快/质量不变/已省 token——须实跑。
- 诚实边界：删摘要后 analysis 来源错误不再是同等测量项，**不得把该项变少单独宣称为聊天真实性或记忆能力提升**。

## B2 事实与行动的区分（通用装配规则 `_fact_action_rule()`）

信息不足仍可推进（查/比较/表达兴趣/提时间路线建议/玩笑调情）；只禁"未查明→已查明""希望→已发生"、
一般常识冒充本次现场/路线/设施/天气、新提议冒充已有装备或既有亲历；私下目标转自然商量不冒称她已同意、
关闭后不让其它备选再推同一邀约；首选与方向槽都必须是收信人一致的可发正文（非"你可以这样发"类操作指令）；
已发生后据回顾收尾不复活旧约。**按通用信息边界组织，不特判后摇/凤凰山/耳塞等素材。**

## 明确不做 / 能力缺口（如实登记）

- 不做 topic/ongoing/scene 多层摘要、自动画像重估、跨轮反思、辅助生成（保留 v0/r2 简单性）。
- plans 仍只来自初始种子，无自动事项状态机；"关闭目标≠删已确认约定"靠状态分区不被 intent 清空体现，非自动写回。
- 1400 码元旧史可能遗漏远处事实；长 emoji/罕见兼容/系统隔离进入 backlog，不作开测前置。
- 是否"更会聊"未证；本批比较整套简化架构对原版，不凭结果单独宣称删 analysis 或某条护栏的因果收益。

## 与 r2 / 原版 / v3 关系

`build_system_prompt`、`rc.*`、语义块来自 `reference_product_v1`（进身份闭包）。system 自带副本，
`format.md` 的 analysis→{} 使 v5 system 与 v3/r2 **不再逐字节相等**（设计变量）。reference_product_v1、
v3_system_slim、v4_intent_context_r2 均冻结不动。

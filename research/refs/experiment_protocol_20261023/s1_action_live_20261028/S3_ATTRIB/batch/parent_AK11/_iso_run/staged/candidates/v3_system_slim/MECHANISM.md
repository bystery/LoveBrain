# v3_system_slim — MECHANISM

## 一句话

系统提示资产删减候选。**机制逐字转发父本 `reference_product_v1`**（init/run_turn/
snapshot/restore/记忆读写/检索/上下文拼接/输出契约全部同一份代码）；唯一变量是
`assets/system_prompt/*.md` 的长度与措辞。

## 为什么只动资产

机制文件 `mechanism.py` 只做 `import` 父本并重导出四个生命周期入口，控制器把
`ctx["assets_root"]` 指到本候选 `assets/`，于是父本 `build_system_prompt` 读的是
这里的精简版。因此：同一份录制回复喂给父本与 v3，**user prompt 装配、写回的
记忆文件应逐字节相同**，只有发给模型的 system 块不同——这是"资产长度/内容"单变量
对照成立的前提，`tools/test_v3_slim_replay.py` 用真实答题重放核验它。

## 信息边界（REVIEW §4 修正）

`core.md` 不再把"备注/意图/目标"一概当私下动机，改四类分明：

- 真实消息：可直接引用承接；
- 可公开事实（用户明确给出的位置/时间/已定事项/偏好）：**允许**入正文、可用于追问推进；
- 私下目标/情绪：只指导口吻分寸，不转述、不写成军师讲道理；
- 未发草稿 / 推测：不算已经说过、不算她的确定想法，不升级成既成事实。

`format.md` 把反重复改成正向保护：**服务当下、带新意的旧事回扣鼓励**，只挡无关占题
与对已定事项的机械复读。不加入车票/杯子/地名等特例词，不做程序禁词或一律 veto。

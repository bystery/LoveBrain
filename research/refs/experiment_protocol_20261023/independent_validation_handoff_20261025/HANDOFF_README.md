# 独立验证出题交接包（自包含委托）— 2026-10-25

用途：v5 真实 48 次出结果且**开发保留**后，直接进入"未见故事"验收，不再从零准备。本包是交给
**独立出题/保管角色**的自包含委托，不依赖本轮任何具体失败文本或候选专用规则。

## 0. 独立性铁律（先读）

- 出题角色**不参与本轮 v5/v4/r2 的调参**，不读 `benchmark/b_line/` 秘密题、不看候选答案后回填。
- 本包**不含**本轮暴露题（E004–E012）的具体失败句、候选专用规则、或"改个名字的同款题"模板。
- 开发者可准备导入格式与本示例格式，但**不得先读答案再自称未见**；未指定独立保管角色时，只完成
  交接与保管流程，**不用自编题冒充独立集**（这不阻塞当前公开 48 次）。
- 复用用户已有的独立出题窗口/角色；不主动新建或轰炸新窗口。

## 1. 建议的最小验证批（有限范围，非"monster"证明）

- **2 条新生活故事 × 8 请求位 = 16 位，两臂共 32 次真实生成**（这是**后续条件清单**，
  **不在**本次已批准的 48 次额度内；须另行一次明确授权才跑）。
- 覆盖：短程目标启用/暂缓/重新接上/确认后收尾；跨话题事实使用与第三人归属；一次自然收尾。
- 三条故事不得复用本轮生活领域骨架（换城市/职业/关系阶段/活动），避免与 E007–E012 同型。

## 2. 交付格式与 schema

- 故事文件、输入消息、意图、note、时钟、gold 归属**完全沿用** `tools/import_pilot_questions.py`
  已校验的 schema（见同目录 `episode_schema.md` 与 `neutral_example.json`）：
  - 三通道输入：真实聊天记录(HER/ME) + 补充信息(note，私密) + 意图(intent，部分位有)。
  - `persona.me/her` 为字符串；`initial_kb` **只用双方均消费的支持字段**（me/her/warmth/style/stage/lessons
    标量，或 ongoing_plan），值必须标量、平面（不放任意 dotted key）。
  - 每轮 `gold={}`（评估侧断言挂独立评审卡，不进题面）。
- 评审卡沿用现有分层结构（`04_GRADING_CARDS_*` 字段），见 `card_schema.md`。
- 交付后运行 `import_pilot_questions` 机械自检：0 硬失败 + harness-loadable，再交独立保管。

## 3. 资料可见边界（防作弊）

- 候选可见 = 真实 HER/ME 消息 + note + 有效 intent + 时间戳 + 画像/初始知识种子。
- 候选**永不可见**：gold、评审卡、测试替身台本、未来轮次、出题者的期望答案。
- 候选输出**永不写入**后续轮已发送历史；生成草稿与用户确认发送分开。
- 出题者知悉：比较是"整套 harness 对原版"，不针对某条规则埋单点陷阱。

## 4. 允许的多样性（不预写唯一参考回复）

确认/新提议/玩笑/调情/合理旧事回扣/合适短答/合法不回均可；参考答案只规定事实、意图、状态与必要边界，
不规定措辞、不强迫命中关键词。信息不足时允许澄清/不确定（不借后续位答案追罚当前位）；note 语气歧义
允许合理轻松回应/商量，不把出题者某一种解读当唯一事实。合理新提议不因没有逐字参考被误杀。

## 5. 额度与执行边界（写死，防挪用）

- 本次已批准额度只覆盖 `BATCH-V5-CTX-20261025` 的候选答卷 48 次；**不得**拿它做出题、judge 或额外生成。
- 未来 32 次独立验证是**条件清单**：需一份新的、逐字绑定端点/model/temp、覆盖整批的明确授权后才跑。
- 独立验证批同样：固定 dsf、温度 0.7、逐位交错、无重试/补跑/第三臂/自动 judge、fail-fast。

## 6. 例子（仅示形，非可提交答案）

`neutral_example.json` 给出一条**新生活骨架**（示例：跨城通勤同事因一次行业分享认识、围绕"周末市集/展览"
的轻量推进与收尾）作为格式与自由度示范；它**不是**建议提交题，也不得直接加入验证集（提交前须由独立
角色另写并保管）。

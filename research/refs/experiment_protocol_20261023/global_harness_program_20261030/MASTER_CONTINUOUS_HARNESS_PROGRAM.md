## 0. 主目标与排序

在固定dsf模型、可比输入和透明成本条件下，重新设计完整Harness，使它在**事实/人物/时间/状态、知识正确使用、意图完成、自然互动、钩子与转场、调情与推进、深聊及反馈调整**上优于公平原版。合格质量之后减少用量、金额、等待、故障与复杂度。

优化对象包括core/format/其它资产、意图技能、HER/ME/备注处理、知识写回和更新、检索、上下文选择、调用与消费。允许删掉/替换原架构；原版是参照而非必须继承的模板。用户“80%–90%无用”要用删除实验检验，不宣称已证实这个比例。

**总闭环：需求/机会→可判任务与证据→候选设计→真实共同对照→质量/代价判决→消融/新故事→保留或淘汰→下一轮。** 任何一轮修复、评审、整理都不得替代这个全链。

## 2. 多轨组织：并行推进，不全局串行

每条轨有独立输入/输出和负责人；公共代码由一位集成人串行写。宿主支持子代理/外部会话时可按本节委派，实际运行数受环境限制；不支持就同一worker交错执行，不虚构并发。

| 轨 | 长期职责 | 现在即可做 |
|---|---|---|
| E 评估/数据 | 量尺、证据原子、故事扩展、盲审与质量表 | 复用F3量尺，补正向分项和错卡，不等新候选 |
| H 架构/机制 | 最小Harness、提示删除、意图、知识、上下文分支 | E3作参照，复用v0/v3资产做竞争架构；C只是其中一族 |
| X 实验/复现 | 输入公平、固定模型、共同对照、恢复、预算与实时产物 | 复用runner，准备首轮共同筛选和长知识任务 |
| R 独立复核/综合 | 源码与结果核验、证据级别、消融、阶段判决 | 抽查支持/反例与主体状态，不照worker标签打分 |

同一人同一轮写的候选、题卡、判词不能称“独立人类评审”。不同AI上下文可降低偏见，但不等于独立身份或真人口味。作者知道失败样例就登记DEV_EXPOSED，不假封存。

慢评审、设备缺失、用户未填W表只阻塞对应结论；其它轨继续。基础设施工作通常不超过每循环有效投入的15%；真正破坏证据、预算或常用功能的缺陷可优先修，并说明具体影响。不得为凑比例忽略硬错误，也不得用低概率猜想无限增加前置门槛。

## 3. 统一评估合同

### 3.1 一级质量，不压成一个掩盖错误的总分

沿用当前0–3量尺，定义行为锚点：0反向/严重错，1关键不足，2合理完成，3当前情境有实质增益。NR未测、NA不适用、UNCERTAIN审过但证据不足分别保存，不用0补空。

九维主表：Goal、Factuality、Attribution、Time/State、Boundary、Memory Use、Interaction、Initiative、Emotion/Relation。再为自然表达、话题钩子/转场、调情/推进、深聊、反馈修复、收尾建立可适用子切片；不凭“情绪关系均分”冒充全部子能力已测。

每条评分记录：故事/位点/臂/身份/实际输入与原始输出hash、评价槽、适用性、分数或未知、可核引文、支持来源、判词与评审者/cohort。首选与全部非空备选分别审；合法null无需凑句，备选不掩盖首选。

自由度：参考是事实证据和允许行动集合，不是唯一标准句。新提议不要求历史已发生；未来承诺与过去亲历分开；玩笑/试探/调情不自动当事实；不强制短答；合法不回仍能评行动/边界，表达维度可NA。既不能为了“敢推进”放过假事实，也不能为减少错漏让它全部变成“你自己确认”。

### 3.2 知识六段

| 阶段 | 分母与成功条件 |
|---|---|
| Capture | 事先标注应保留原子；从真实来源正确写入的比例，不按库存总条数 |
| Fidelity | 被保存原子的主体/谓词/客体/否定/时间/状态是否被证据支持 |
| Update | 纠正、撤销、取消、完成、重开机会中当前视图是否正确；未确认变动不能硬生效 |
| Retrieval | 必须用旧知识且实际原文已不在场时，请求是否提供足够正确证据；Capture失败不能被筛出总链成绩 |
| Use | 需要用且最终首选正确运用；另报备选可用，不以prompt在场率替代 |
| Contamination | 无关/过期/错误知识导致的不当断言、旧目标复活；分注入与使用两个来源 |

在种子、原文、摘要、事实投影、更新记录分别登记证据通道。当前输入/永久画像/题目备注携带答案时不能声称长期召回。相关性和主体时间不是裸子串能判的，脚本只负责可确定的机械部分；语义记录有引文和分歧。

### 3.3 可靠性与代价

交付分五层：传输T、原始协议P、消费后可提取C、语义适用S、用户愿发W。W只来自用户真实选择；不等用户把全部样本打完才允许其它研究。

同批记录prompt/completion/cache usage、重试失败消耗、可用结果单位用量；无价目金额null。延迟分排队/请求前、本次首内容、首个经验证可使用回复、完整结束、消费/落盘；没有某段证据就未知。首token不是可发回复。报告按故事与成对位点分层的p50/p95、失败/超时和样本量。并发/缓存/流式配置不同的旧批不可无痕混表。

### 3.4 评审资格与统计

优先复用已登记评审cohort；辅助允许hy3、dsf、qwen3.8-flash、gemini-3.8-flash，选择在实际任务上速度和资格都合适的路线，不把某模型永久绑为慢瓶颈。代表性真实长度校验优先，不以一句PONG证明能批评长材料；小控制集全对不证明所有维度可靠。记录顺序交换、误杀、漏检、信息不足及跨材料表现，不能以“同意worker80%”校准。

可并行不同模型负责不同已登记维度/独立cohort，但同一对两臂由同一模型看同证据；未经桥接不能把不同尺度均分成一个榜。发现资格不足：该维度降为辅助＋证据核读，其它维度和研发继续，不能无休止“校准到全绿”。Gemini在真实任务慢/空返时退出关键路径；qwen在长材料慢时同样切独立路线，不能凭旧快测默认更快。模型切换建新cohort或做必要桥接，不为换裁判重跑全部历史。hy4-preview硬禁。

独立统计单位是故事；重复抽样和同故事轮次相关。报逐故事结果、共同适用配对差与不确定性；故事足够时用故事级bootstrap，少于8篇只作探索性读数。不做伪精确显著性。比较多候选须预登记主要比较与最终验证候选，不反复看保留集挑赢家。

### 3.5 晋级和失败

冻结前登记本轮主假设、目标族、正向保护、严重错误清单、评价范围和停止条件。开发保留不等于最终晋级。最终晋级需：可信共同质量证据、严重错误风险未被省钱掩盖、主动互动等保护维度无已解释不清的退化、新故事验证、可用代价与复现。具体容忍差/样本量事先定，不看结果后挑阈值。

“未发现下降”不是“证明非劣”；未测不是通过；r5没效不是所有机制没效。连续两次高质量对照未支持同一假设就换方法/删分支，不继续改同一句试到赢。

## 4. 数据分期：几百故事不是几百轮

当前stories_v2文件统计31篇350位。先校准质量与暴露，不直接将全部文件认作已验收集。使用既有故事schema、compiler/importer、card结构；不要重新写一套出题格式。

扩展目标按**48→96→200篇独立故事**分期，非同故事换名字算新故事。第一循环新增24篇DEV（8–12位）、8篇候选冻结后新故事（约12位）、8篇长知识（24–48位），先拿代表性子集做实验，整池分阶段消费，不一次调用全部材料。第二阶段补领域/反馈/长度缺口后到96篇，后续有有效研究问题再至200篇。未通过语义审查不为凑数量入库。

覆盖：新认识/熟悉/暧昧/长期沟通，轻松/忙碌/失落/兴奋/冲突修复，生活/工作/学习/兴趣/出行/共同事项，多人主体、跨日更新、消息枯竭、反馈分支、目标启停、无图/有图边界。没有用户授权的个人聊天原文不入外部出题/裁判请求；优先虚构且去标识材料。

拆分单位为故事/家庭和生成模板谱系，不能同模版改实体分别扔DEV/验证。出题上下文不提供候选代码、已知失败原句或答案；先冻结候选，再生成/封存未来验证，审题与评分分工。如开发者已看过就登记暴露，不发明独立身份。

固定历史回放只测在给定历史下的建议，后续作者ME不是已发送模型草稿。要测真实连续策略，另建可追溯受控分支或模拟交互队列，记录实际选择的输出；模拟器结果与固定回放、真实用户数据分表，不以模拟对方“喜欢”作真人成功证明。

## 6. 实验波次与预算：大工作量不等于盲花钱

## 8. 循环调度与停止条件

任务状态：`PLANNED → READY → RUNNING → EVIDENCE_REVIEW → ACCEPTED / REWORK / ELIMINATED / BLOCKED / SUPERSEDED`。复用项经差额核验标`REUSE_VERIFIED`。不得把所有旧任务重新标TODO。

每次调度：①核活体/认领/预算；②收已完成结果并独立验收；③解依赖；④选能改变用户能力结论的最高价值READY任务；⑤并行不同所有权工作；⑥写持久状态和下一步。没有GPU/模型/设备的任务可BLOCKED，继续其它轨。

价值排序看：一级质量影响×真实发生/能力机会×证据确定性÷研究成本。该公式仅辅助调度，不替代安全/预算/真实性硬门。一次发现100个小问题不自动挤掉全部正向能力研究。

同一错误族最多两次未支持的高质量假设后换思路；当前核心已稳定解决就转其它未测能力；不能永远选熟题证明自己。组件若两轮无收益且无必要性证据，进入删除/降级试验；不是把“未证”当永久保留许可证。

### 断窗恢复

每个长批已有pid/日志/原子checkpoint/attempt账本/完成回执。新窗口读最新状态而不是旧聊天终句；先核是否还有真实进程，不新开相同run、不覆盖输出、不盲目重发孤儿。账本关闭和未决attempt是两列，不伪造终态。

每个大动作完成刷新心跳；每4有效工程小时或一个真实批产出阶段快照；每轮终结必须写handoff：当前身份、已完成证据、物理/逻辑请求数、预算、未决、下一可执行命令/参数、关键教训。没有交接文件也能从机读队列与账本恢复。

持续运行必须依托实际可存活的宿主进程、已有runner或平台自动化；**文档不能让会话结束后继续推理**。环境提供已授权调度能力时按其工具创建/更新现有唤醒，不能手写绕过调度系统的cron；没有调度能力就保留可恢复队列并说清缺少唤醒。不得未经用户要求新建对话窗口或给其它会话发消息。后台helper隐藏启动，Windows用CREATE_NO_WINDOW或Start-Process -WindowStyle Hidden，不改管理员权限/窗口站/共享账户。

### 正当停止

具体批次到有效cap、预算落盘失败、身份/题/实际出站配置不符、明显系统性服务事故时停止对应批并保留证据。人类明确暂停才全局暂停。人类W未给、产品设备缺失或一个裁判慢，不导致全项目停工。

完成全部合格目标可给有范围ACCEPT；若预算或外部条件阻断当前闭环，交已完成结果和精确恢复条件。禁止无期限收费、凑288h、虚报后台存活或刷接口制造“工作”。

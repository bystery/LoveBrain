## 结论

1. **延迟差异 100% 在首内容前段**：headers 逐毫秒相同（非网络/排队），流式跨度相同（非输出
   速度），输出长度几乎不变——差异 = 服务端**预读输入（prefill）成本**随输入长度变化。
2. **优化杠杆 = 缩短输入，不是缩短输出**：输出 token 数与完成延迟零相关；r9_slim 的 −3.8%
   输入换来 −24% 首内容延迟（非线性放大，疑经网关批处理/缓存效应）。r9_slim 的瘦体路线
   恰好打在真正的杠杆上。
3. **后续等待优化排序**（按杠杆大小）：① 输入再瘦身（r8 混合窗假设的又一动机）；
   ② 网关侧前缀缓存（W14-03 已登记观察项——若启用，静态 system 前缀复用将进一步压缩
   预读段）；③ 流式消费/输出侧无可杠杆（corr≈0，流式跨度仅 1.5s 占 6%）。

## 边界

单批 n=32/臂、单故事组；结论"输入长度→预读延迟"方向可靠（headers 严格同值控制了网络变量），
弹性系数（−3.8%→−24%）为该批经验值，不外推为通用常数。不做任何新调用验证——
后续批（wave 扩测）timing 数据自然累积复验。

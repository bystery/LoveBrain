> 依据：W06-01 意图合同差额场景 V1（S1-S5）+ 冠军链（r7_supersede → r1 → v6_goal_context）机制实读。
> 纪律：零模型调用；input 仍是状态机唯一真值源（W06-01 合同不动）；所有增量确定性渲染 + flag 门控。

## 二、五要素映射与最小增量

| 要素 | 现状 | 差额 | 最小增量（全部确定性、零调用） |
|---|---|---|---|
| **目标** | input 状态机完备 | 无 | — |
| **阶段** | 三方材料齐备（history/categories/自报）但无推导无渲染 | **渲染缺口** | 【目标阶段】注记行：近 3 轮 goal_category 众数 → 推进期/探索期/收线期，只在 goal 生效轮追加一行 |
| **可选动作** | plan_items 已投影 | 无 | —（接口文档将其正式纳入"动作层"，W06-03 场景复用它） |
| **反馈** | goal_history 有 | **摘要缺口** | 【近期反馈轨迹】行：近 3 轮 category 序列（如"推进→暂缓→推进"），她明确拒绝/收尾时轨迹自然显示降速 |
| **暂缓/切换** | 终态合同 + 零残留证据 | 关闭轮无负面提示 | **可选 tombstone**（默认 OFF）：PAUSED/CLOSED 后 K=3 轮内渲染"该目标已暂缓，勿重启除非对方重提"；由 W06-03 S5 实测决定去留 |

防 S4（无目标轮发明目标）纪律：两条注记行**只在 goal_history 存在生效目标时渲染**；无目标轮块保持空串（现状不变）。

## 三、实现落点与候选化

- 落点：`v6_goal_context._goal_block` 尾部追加 flag 门控渲染段（`goal_stage_annotation`），历史数据源 `h["goal_history"]` + `h["action_log"]` 的 goal_category 已在内存，无新状态机。
- 候选化：**r8_goalstage**（r7_supersede + 该 flag，flag off 逐字节复现 r7）——但**先不建**：W06-03 场景实跑本身是验证载体，正确顺序是 W06-03 反事实矩阵把增量臂作为 treatment，场景判据（输出行为差异）直接检验接口价值。
- 预算影响：两条注记行 ≤ 60 CU/轮，MAX_GOAL_CU 600 内自洽。

## 四、W06-03 耦合矩阵（场景 × 特性）

| 场景 | 检验特性 | 判据（W04-01 Goal 维） |
|---|---|---|
| S1 目标中途关闭 | tombstone（若开）/零残留基线 | T07+ 不围绕旧目标推进；已确认事项（周二七点半）仍可自然提及 |
| S2 ADJUSTED 改向 | 阶段行切换渲染 | 请求/建议按新目标变化，非复读句子 |
| S3 反馈三版 | 反馈轨迹行 | 正反馈敢推进、含糊可试探、拒绝不硬推（联动 W08-05） |
| S4 无目标差额 | 防发明纪律 | 无意图块时不自行发明目标，当前事项正常承接 |
| S5 复活陷阱 | tombstone vs 基线 | EXPIRED 同文本注入不复活；tombstone 是否过度（该收尾时拖沓） |

判读：主判据 = 输出行为差异（GOAL_COUNTERFACTUAL，非搜注入串）；两序各一次；差异归因到块进/不进。

## 五、结论

接口五要素中三项（目标/可选动作/暂缓切换合同）**现状已完备**；真实差额只有两个渲染缺口（阶段、反馈轨迹）+ 一个实验性加固（tombstone）。全部为确定性渲染、零调用、flag 门控、不触碰合同。**W06-02 = DONE**（本设计件）；W06-03 场景实跑（含增量 treatment 臂）为下一步，实跑结论反哺 tombstone 去留与 r8 候选化决定。

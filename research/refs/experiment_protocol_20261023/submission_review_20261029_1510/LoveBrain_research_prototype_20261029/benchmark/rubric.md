## 1. 三层评估架构（v0.5 门禁语义变更）

| 层 | 评什么 | 谁来评 | 在分数中的角色 |
|---|---|---|---|
| 层 1 程序规则 | 输出契约、source_ids、状态断言、LCS、关键词、AI 味词表 | lb_scorer.py（确定性） | **契约与红线检查，可触发 veto**；不再独占晋级门禁 |
| 层 2 语义与互动 | 事实/人物/意图/事项状态、自然度、话题污染语义档、可发送性 | 人工监督（现阶段）+ 校准后 judge 辅助 | **并列门禁**：语义失败率、污染率、严重问题备选比例 |
| 层 3 用户偏好 | 是否愿意真的发送、语气与个人口味 | 用户锚点 + 小范围实测 | **最终裁决**；worker/judge 不代投 |
| 层 4 资源与等待 | 全链真实用量、调用、时延、失败 | 网关 usage + 考场计时 | **并列门禁**：token / 延迟 / attempts；失败不从分母删除 |
| 层 5 可维护性 | 状态与规则是否重复、用户纠正次数、故障恢复难度 | 报告式；无数值阈值 | 报告；不擅自设"优雅分"硬门禁（REVIEW_DISPOSITION） |

**多目标晋级判决**（协议 §6 + fair_baseline §5）：
- 质量更好 + 严重错误/污染不增 + 成本/等待不恶化 → 明确收益；
- 质量在预登记可接受差异内相当 + 成本或等待实质下降 + 另一项不恶化 → 效率收益；
- 均分微升但严重问题/污染/成本明显增加 → **不是整体更好**；
- 某项收益换某项代价 → 报告交易，由用户裁定，不自动冠军。

**门禁语义**（v0.5 明确）：
- **程序 veto 级严重错误**（json_schema_broken、非法 source_id、跨对象写入、已取消事项复活）
  由层 1 直接触发；
- **语义严重错误**（错人、编造已发生安排、明确禁止的私有内容泄漏、完成/取消事项复活）
  需带原文与当时证据复核，**不由未校准 judge 单独判死**（§3）；
- **合法 null 与不主动回**：不强迫凑句；worker 不得把 null 视作"没内容 = 通过"。

## 2. 层 1 检查点清单（lb_scorer.py v0.9.2 已实现；v0.5 语义微调）

| id | 判定 | 权重 | veto |
|---|---|---|---|
| json_schema_valid | 单 JSON、按候选声明契约校验（默认 legacy：4 风格至少一非空、directions=4、含 analysis；候选声明契约则按声明，候选输出总数须 ≥8） | 2 | ✅ 破坏即 0 分 |
| source_ids_exist | scene_facts.source_ids ⊆ 真实消息 id | 2 | ✅ 非法引用即 0 分 |
| **note_lcs** | 回复与备注原文最长公共子串占比 ≤ **0.6**（v0.5：分母改 max(len(a),len(b))；<10 字短文本豁免；仅"整句照搬"才判违规） | 2 | — |
| must_not_kw_* | 禁止关键词零命中（全部可发送文本） | 1/条 | — |
| must_kw_* | 必要承接关键词任一命中 | 1/条 | — |
| topic_status / topic_label | analysis 话题断言 | 1+1 | — |
| forbidden_fact_* | 禁止新增事实（猜测不得升级为事实） | 2/条 | — |
| ongoing_* | 进行中事项期望状态 | 2/条 | — |
| cancelled_* | 已取消事项不得复活 | 2 | — |
| ai_flavor | AI 味违禁词表零命中 | 1 | — |
| intent_kw_* | **意图契约**（仅带 intent 的题）：回复命中意图关键词组 / 避开意图禁区 | 2/条 | — |
| stale_kw_* | **旧事重提（记忆污染）**：gold `stale_fact_must_not` 列出的旧事关键词零命中 | 2/条 | — |
| geo_must_not_* | **物理可行性禁区**：gold `geo_impossible_must_not` 列出的客观不可能动作词零命中 | 2/条 | — |
| style_diversity | **风格趋同**：非空话术两两 LCS 子串比 ≤ 0.6；无 gold 依赖、全题生效；阈值 pilot 封板前可调 | 1 | — |
| soft_kw_* | **软关键词**：v0.5 保留，命中只进 evidence 不计分 | 0 | — |
| decline_appropriateness | 合法不回恰当性（expect_decline 或本轮 may_decline 才得分） | 2 | — |

**gold 缺席的诚实登记**（v0.5 新增）：题目 `gold={}` 或某子字段缺时，
`must_kw_*` / `must_not_kw_*` / `forbidden_fact_*` / `ongoing_*` / `cancelled_*` /
`intent_kw_*` / `stale_kw_*` / `geo_must_not_*` 等**相关断言缺席**，
`scoring.json` 的 checks 列表里应显示这些断言"未实例化"，不得记成"已通过"，
也不得从 `pts_total` 里悄悄消失。当前 `lb_scorer._finish` 用 `sum(c["pts"] for c in checks)`
即检查点数列的实和，未实例化的检查本就没进列表——**语义正确**，但报告层要显式说明"程序分
只覆盖已实例化的 N 项，其余 gold 相关项未测"（评审采纳记录 REVIEW_DISPOSITION 事实更正 2）。

单题 score10 = 通过权重 / 总权重 × 10，veto → 0。程序分的变化只证契约与相似度红线
变化，**不推语义**。协议变更需版本化 + 用基线候选离线重评，见 §8。

### 输出契约声明

- 候选在 `params.json` 可选声明 `output_contract`：`{"style_keys": [...], "directions": 4,
  "min_nonempty": 1, "extra_text_fields": [...]}`。
- 约束：可发送候选总数（style_keys 数 + directions 数 + extra_text_fields 数）**≥ 8**；
  未声明按 legacy（4 风格 + directions=4）。
- 声明随候选版本化；scorer 按声明校验 schema、采集可发送文本。

### C10 意图契约

- 题目可选字段 `input.intent`（调情/邀约/安抚/收尾/日常）。**只有部分题带意图**，
  无 intent 跳过本检查。
- gold 配套：`intent_keywords_any`（任一可发送文本命中任一组即得分，判"确实在调情"）；
  `intent_must_not_keywords`（与意图冲突的禁区词）。
- 语义级意图对齐归层 2（校准前只辅助）。

## 3. 层 2 judge 与人工监督协议（v0.5 收紧）

- **校准前置**：judge 上岗需 20 锚点盲评一致率达标，落 `logs/judge_calibration.json`；
  **未通过的 judge 只做辅助筛查，不能单独触发 veto 或宣告候选失败**。
- **人工监督优先**：当前阶段（v0.5）语义判决以人工初审为主，逐位保留原文、字段与当时证据；
  worker 可做初审与归因，**但候选晋级不能仅由写候选的 worker 自己决定**（协议 §4.3）。
- **盲评五选一**：A 更愿意发 / B 更愿意发 / 相当 / 两个都不合格 / 信息不足。
  「两个都不合格」必须保留。
- **可发送性四档**：0 不能发送 / 1 需明显修改 / 2 基本可发 / 3 愿意直接发送。
- **话题污染四档**：0 不提或有依据 / 1 轻微附带 / 2 明显挤占 / 3 替代当前主题。
  2–3 判污染，1 仅作诊断；**关键词法只用于初筛，语义判定以人工或校准 judge 为准**。
- **顺序交换**：每对候选 A/B 各评两次（顺序互换），不稳定记 disagreement。
- 待校准指标：侵入率、承接率、重激活率——三指标同时报告。

## 4. 首选与备选分审（v0.5 落到 LAYERED_SCORE）

**逐槽字段**（每个请求位）：
- `primary_slot` = "recommended"（或候选契约声明的主槽名）
- `primary_semantic` ∈ {pass, edge, fail, unrated}
- `primary_semantic_note` 一句话依据 + 原文引用
- `backup_slots` = 其余 style_keys + directions 非空项的数组
- `backup_semantic_per_slot` = 与 backup_slots 对应的 judgement 数组
- `backup_with_severe_error` = 备份槽中出现"错人 / 编造已发生安排 / 明确禁止的私有内容
  泄漏 / 完成或取消事项复活"任一者 → true

**汇总三个指标**（每个 episode 与总计）：
- **primary_semantic_pass_rate** = Σ primary=pass / N（不含 unrated，未评不入分母）
- **at_least_one_pass_rate** = Σ (primary=pass OR 任一 backup=pass) / N
- **severe_error_backup_rate** = Σ backup_with_severe_error / N（越低越好）

**判决纪律**：
- "一个好备选不能掩盖坏首选"——`primary_pass_rate` 单列，不得与 `at_least_one_pass_rate` 混用；
- 合法 null 与非空备选分开：null 是"该位本轮不交付"，不算不合格；
- 未评 = unrated，不冒填 pass 拉高比例。

## 5. 成本双账与并列门禁（v0.5 恢复）

- **评分账**：token 消耗（episode 全程：生成+记忆更新+反思+画像+修复+重试+失败）。
  真实 usage 用 `api_usage` 口径；上游未给 usage 时用 `kotlin_len_chars` 估算并**标注**
  为字符数不是模型 token，不填 0 冒充。
- **法币账**：DeepSeek 当轮 price sheet 折算金额；本地网关单价未提供 → 记"金额未知"，
  不按"本地=免费"记账。
- **v0.5 修订**：v0.3 的"成本不再作晋级门禁"历史选择**保留在文件里作为沿革**，但
  **本轮采用多目标并列门禁**（协议 §6 + fair_baseline §5），成本/时延/污染/可维护性
  进入并列判决；具体可接受幅度与预算须在看到该批结果前登记（协议 §5.3）。
- 报告分层：每故事总量、每请求位、每合格交付的用量；解析失败的语义可记不可评，
  但仍计交付失败与资源消耗，**不从分母删除**。

## 6. 每轮报告八数（v0.5 扩容）

①首次完整输出成功率 ②严重错误数与类型 ③**首选合格率** ④**至少一个合格候选比例**
⑤**含严重问题备选比例** ⑥关键记忆探针通过率（更新/纠错/应用细分）
⑦相对基线盲评胜/平/负（含两者均不合格数）⑧episode 成本（评分账+法币账）与 p50/p95 延迟
⑨记忆污染率 = stale_kw_* 命中题数 / 配置 stale 探针的题数（v0.3 保留）

统计纪律：N 案例零严重错误时报告单侧 95% 上界（如 N=60 → 上界约 4.9%）。
24 位嵌套 3 故事不能当 24 独立样本；报告逐位配对差异与故事级结果。

## 7. 晋级流程（五步 + 人工对齐检查点）

1. **契约与红线**：程序层 1 全过、veto 零触发；候选自修复保留但计费，报原始失败率。
2. **已知故障回归**：`refs/KNOWN_FAILURES.md` 全量回归，不得复现。
3. **开发质量与并列门禁**：A 线开发集上，语义/污染/成本/时延四项按 §1 多目标判决；
   任一维度显著退化 = 不晋级（不因"均分涨一点"过门）。
4. **选择集盲评**：A 线选择集，候选 vs 现行冠军，筛决赛版；对照材料隐藏候选身份、
   顺序做均衡或交换。
5. **封存验收 + 小范围实测**：B 线只开一次；有明显收益才换冠军；未参与调参的故事上
   才叫独立迁移证据。
6. **人工对齐检查点（HITL，v0.3 降频保留）**：攒够一个故障族收官时产出「回复展示包」
   （`logs/showcase_round_N.md`），交用户过目；冠军替换不强制打扰用户。
   用户反馈 → KNOWN_FAILURES / anchors / gold 契约补丁三类资产之一。

## 8. 版本纪律（v0.5 新增）

- 本协议每次版本变更必须：①顶部沿革保留旧选择；②`lb_scorer.py` 与 `exam_layered_score.py`
  同步实现并单测；③对已有全部答卷离线重评（不重烧 API）；④新旧口径同时输出一次
  以对比是否评分改动带来的差异；⑤协议变更**不算候选收益**，只算尺子校准。
- 未校准的 judge 不进 §7 步 3 的门禁；judge 校准通过后才升为层 2 主判。
- **gold 覆盖度**是尺子可靠性的一部分：gold={} 的题只测契约，程序分与语义无强相关，
  不得据此推断语义通过率。

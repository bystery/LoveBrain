# 当前进度、ABC 独立复核与完整 harness 优化指导

日期：2026-10-24。供用户及现有训练 worker 使用。依据本地代码、公开题及本目录 CHECKS.json；未读取封存 B 线，未调用真实模型，未修改原版产品、候选、评分器或原始答卷。

## 1. 用户到底要做什么

目标是：在同一个 dsf 模型服务上，重新设计并循环改进 LoveBrain 的完整 harness，使聊天更有用、更能按意图推进、更少失忆和上下文污染，同时减少 token、等待和维护负担。

训练对象包括 system 资产、意图处理、HER/ME/补充信息的使用规则、知识与记忆的写入/检索/注入、上下文选择与预算、调用策略。这里优化代码与提示词，不训练模型权重。

用户认为原版 80%–90% 的 harness 无效，这是重要的研究起点，尚不是经过消融确认的比例。实验应允许大幅删除、合并和重写，不再预设 core.md、现有层级、关键词选择器或输出槽位数量必须保留。原版复杂不等于能力强，候选更复杂也不等于进步。

**两种身份不能混淆：原版参考实现要忠实，候选实现可以彻底不同。** 保真修复只是让对手公平，不是要求最终产品继承原版的所有复杂度。

## 3. 本次 ABC 复核判决

本轮直接运行批注测试 15 项、候选测试 15 项，30/30 通过；另外执行一次独立目录内的 48 次 capture，账本为 48 started / 48 completed / 0 failed。capture 的出站函数由替身接管，真实网络禁用；这些不是新模型答卷。

六个被观察的关键源码/批注文件前后散列一致。这里未重新宣称其余 64 项都已独立运行。

### A：接入正式链签收，逐轮交错与授权实跑入口不签收

`tools/exam_interleave_plan.py:402` 遍历 `_ordered_runs`，每个臂/故事调用一次 `run_episode(stop_after=None)`。实际前十次是：

```
父 T01、父 T02、父 T03、父 T04、父 T05、父 T06、父 T07、父 T08、子 T01、子 T02
```

计划却是：

```
父 T01、子 T01、父 T02、子 T02、父 T03、子 T03……
```

这是实测执行顺序不符，不是文字格式问题。原测试只验证 48 次和六个 run，没有验证真实尝试顺序，故能全部通过。

另外：

- `validate_plan` 只检查轮次集合，没有检查实际列表中的前驱。交换父本 T02 与 T03 后仍被接受。
- `execute_plan` 第 375 行对 live 无条件抛错，没有授权参数。CLI 也没有可用的授权实跑通路。“无授权会拒绝”只证明拒绝分支，不能证明有授权可运行同一路径。

修复属于同一工作包：按计划逐槽执行、接入已有真实授权与预算接口，并用真实调用事件核对顺序。不是新建另一套平台。

### B：现有反例和历史标签修正签收，缺失题面绑定仍有旁路

原文/槽位改变后旧标签失效、错误身份拒绝、历史两条备选误判移出首选等已有测试通过。

但 `_match_annotation` 第 117 行仅在 context 的 case_input_sha256 非 None 时比较题面。独立构造同 run、同 harness、同输出，但评估侧题面散列为 None，仍返回旧 pass。它与“缺任一上下文就拒绝”的声明矛盾。

`_case_turn_input_sha` 当前读取工作树里的题面，而非本次运行冻结输入；不能因注释称“冻结题面”就视为历史快照。

收口方式：新批上下文三项均必须存在且一致；从本次答卷绑定的输入快照取题面散列。保持纯历史复算的兼容入口显式区分，不给新批静默兜底。并让新两臂结果目录/EXAM_INDEX 能被现有分层工具直接消费，不要求人工搬目录后才评分。

### C：码元修复签收；执行期测量需与声明一致

候选 15 项已有测试通过，包含 emoji 和联合预算反例。无需再围绕这个问题重建一轮候选。

但执行器 `_recall_newseg_from_calls` 只测【回忆】段，没有计入新增 ongoing 行，因此 `newseg_max_utf16` 不能宣称是两者合计。修执行器时把此诊断补成实际完整新增内容核验，或如实改名；完整预算另用同一渲染规则检查。没有回忆内容的 canned 替身批不能单独证明有回忆时的预算。

**准入：保留已签收部分；以上执行接线及缺失绑定合并修完后进入限定前台开发 A/B。当前不是“只缺付款授权”的状态。** 不新增 OS 隔离、几百题、全自动 judge 或整个安卓重构作为本批前置。

## 4. 用户说的这些，在实验中分别是什么

| 用户表达 | 实验中的对象 | 必须回答的问题 |
|---|---|---|
| core.md 等可能没用 | 组件贡献与冗余假设 | 删除后哪些表现不变/更好，节省多少；哪些能力确实丢失？ |
| 意图指导不好 | 目标表示、触发与执行策略 | 当前意图是否改变行为；阶段变化能否切换；关闭后是否停止影响？ |
| HER/ME/补充插入混乱 | 信息来源、可见性与冲突优先级 | 私下想法是否被说出口；草稿是否冒充事实；谁说的、说谁的是否正确？ |
| 知识注入不好 | 记忆写读、相关性与上下文选择 | 该用时拿到，不该用时不塞；过期/纠正/取消能否生效？ |
| 改完再考再改 | 版本化实验与候选选择 | 哪个变化带来真实收益，付出什么代价，保留还是淘汰？ |
| 更好更优雅 | 多目标成果 | 聊天质量、污染、token、时延、状态与规则复杂度能否同时改善？ |

这些不是“残血想法”：已经给出了研究对象、问题假设和优化方向。缺的是可执行的组件删除实验、覆盖真实目标的数据、可靠判定，以及“结果→保留/淘汰→下一候选”的真实闭环。

## 5. 完整闭环还需要的内容，按用途补齐

### 5.1 建一个真正有竞争力的最小对照

后续不再只比较“原版”与“原版加一个功能”。至少要有三种研究角色，但不要求全塞入当前 48 次预算：

1. 原版参考：相同外部信息，忠实保留被比较范围的原语义。
2. 最小 harness：简洁任务说明、必要输出约定、真实当前聊天、当前有效意图与补充信息；历史/画像按明确的简单策略使用。公开声明其记忆限制，不暗塞答案。
3. 重构候选：针对明确故障改变组件，允许删除、替换、合并整族实现。

最小对照的作用是回答：原版堆的复杂度到底比一个简单实现多提供了什么。缺少它，持续给原版打补丁很难发现“大部分可以删”。

原版参考和最小对照分开保存。不能把原版删弱后叫公平基线，再用它证明候选更强。

### 5.2 用删除和替换实验检验资产与机制

下一阶段优先研究族：

| 实验族 | 候选变化 | 正向与反向观察 |
|---|---|---|
| 系统资产 | 去掉/压缩 core、自然度检查、重复限制；保留必要任务与交付用途 | 回复质量能否维持，是否更主动、更省；有没有明确能力退化 |
| 意图 | 常驻长指令改为当前目标/阶段策略，切换、关闭和冲突处理明确 | 破冰、调情、邀约、深入交流能否表现不同；收信对象和分寸正确 |
| 补充信息 | 把可公开事实、私下目标、情绪与草稿区分使用 | 可用事实不被全禁；私密内容不无意转述；草稿不冒充已发送 |
| 记忆与知识 | 去掉重复层、合并状态、选择相关片段、预算控制 | 相关历史能用、无关历史不抢题、主体/纠正/过期正确 |
| 调用与输出 | 减少无效辅助调用、重复备选与冗长分析 | 首选质量/有用选择不明显损失，真实总成本与关键路径减少 |

“一个主变量”是一个可解释的设计变化，不是每轮只能改一个文件或一句 prompt。可以提交整套新架构作为候选，再对主要贡献做针对性消融；不要把所有变化揉在一起却声称每项都已独立证明。

提示资产本身是合法优化对象。若主要收益来自删除冗余 prompt，不能为了旧的机制配额而强塞无用代码。当前已冻结的两臂先不改；后续规范应与用户这一目标同步，输出数量也不应永久以旧“必须八条”约束掩盖浪费。

### 5.3 数据不能只考记车次、记杯子

已有 24 位继续做诊断回归。后续按下列能力扩故事，不是把同一道题换名词：

- 顺着聊、话题变弱后开新入口、有自然钩子而非连续盘问；
- 根据不同关系与当前意图，调情、接招、表达兴趣、提出线下机会、深入交流；也覆盖普通朋友与需要结束的时候；
- 对方反馈变化后的多轮策略调整，记录当前目标如何变化，不能只奖励某一句漂亮话；
- HER/ME/第三人、真实历史/草稿/私下备注的区分，信息冲突与人工纠正；
- 有关/无关回忆成对、状态结束/取消/重新开启、跨话题和长历史；
- 长输入、持久化恢复、不同设备/工作/生活领域等性能与可靠性保护。

数据划分按故事/模板族进行：开发集可见可反复改；选择集低频比较；最终验收集在候选冻结后使用。开发方读过的题不能改名成“未见”。已有封存目录不得为扩题被训练 worker 打开。

几百请求位是后续覆盖目标，不是今天付费试跑的前置。出题与机制开发可在既有分工中并行推进；不要求用户再开窗口。先公布覆盖缺口，再优先增加独立生活故事；数量须随预算安排，不把任意故事数称为统计保证。

固定后续台词可测“面对此输入回复得如何”，不能证明上一回复让对方更喜欢你。要验证根据反馈调整，需要评估侧明确分支/反馈条件或另列小范围真实使用；模拟对话模型的偏好同样需要核验。

### 5.4 目标与评分必须同时覆盖正向收益和代价

不能把目标缩成“不编造、不泄露、JSON 正确”。这些是必要底线。用户要的正向能力也要逐项出现：意图执行、情绪与互动推进、钩子质量、自然与原样可用性。

每位按卡记录：当时证据、允许多种行为、明确失败条件、首选判定、备选逐槽判定、不确定项和理由。参考答案规定事实/目标/边界与合格方向，不规定唯一句子、不按车次/杯子词命中刷分。

成本记录所有调用、失败、输入/输出真实 token；后台未纳入时明确范围。时延记录本地处理与完整返回，未来做流式时才增加首字/首条可用候选。按故事和成功交付并报，不能仅删掉失败后的平均值。

性能与维护性：本地处理耗时、持久化读写、重复状态和规则、纠错/恢复难度。行数减少不是唯一标准；核心是是否减少不必要的真相副本与用户负担。

### 5.5 谁评分

| 职责 | 谁做 | 权限边界 |
|---|---|---|
| 合同、账本、预算、确定性事实夹具 | 程序 | 不把 JSON 10 分升级为聊天好 |
| 全量初审、原文与事实证据提取 | 训练 worker / 辅助评审 | 可定位故障和提出判定，不自封全面优于原版 |
| 按卡语义和互动复核 | 独立评审；后续可使用校准后的 AI judge | 隐藏候选身份、检查顺序/重复稳定性，争议复核；当前不把未校准 judge 当唯一冠军裁判 |
| 个人语气与愿发偏好 | 用户抽样标定 | 用户只需重点样例、争议与阶段标定，不逐位审批几百题 |

用用户已认可/不认可的实际例子形成锚点，同时保留未参与调参的例子。允许搞笑、暧昧、短句和间接表达，不用词表把所有刺激性交流判坏。每次初审保留槽位和原文，不再张冠李戴引用备选。

### 5.6 怎么选下一代

一轮产出必须包含真实答卷的逐位胜/平/负/双方失败/不确定，故事级汇总，以及 token、等待、污染和新增故障。

- 质量相当而成本或等待明显减少，可以是合格进步；不是只有“回答多一分”才值得保留。
- 质量明显变好但成本变高，报告具体交易，由用户选；不能默认任何加量都是升级。
- 一个已知节点改善只是开发收益；在不同故事上保住收益后才讨论迁移。
- 没有可观察收益就保留父本，淘汰或回滚候选；不为凑进步不断修改指标。
- 随机生成会有波动。初次单次比较给开发方向，不假装有统计确定性；需要复采时预登记另外预算与前史，不重试到赢。

“monster”应最终体现为多类真实场景的稳定改善与可接受代价，不是一个总分。不能保证预定一定训练成功，可以保证失败也被识别，避免选出只会公开题的候选。

## 6. 同一个 worker 接下来连续执行的任务

### 第一批：只做剩余接线，一次收口

保留父本、v2、已签收的码元/批注/评分实现，不引入新的聊天主变量。

1. 改现有 execute_plan：遍历冻结的 48 个 slot，复用六个独立状态，每次只推进对应一轮。若用 checkpoint/resume，派发前检查精确前驱，禁止顺带重跑任何历史轮。
2. 同一入口提供真实授权参数，复用已有授权级预算和真实适配器；无效授权零派发，有效授权才运行。不要另写一套 live 调度器，也不要把授权校验删掉。
3. 计划校验检查真实顺序/前驱及臂映射；冻结配置必须与实际配置一致。真实事件逐项记录 slot、arm、case、run、attempt，再对照整个计划；不凭“48 次总数”签收交错。
4. 新批评估侧题面散列缺失就记未验证；从运行输入快照绑定，而非当前工作树补造。两臂产物、EXAM_INDEX 和分层评分的入口一并接通。新增段测量包含实际 extras 与 recall。
5. 离线只补三类有用证据：48 次真实路径的替身交错序列一致；前驱乱序/身份漂移/缺失绑定被拒；第 5 次传输失败记 5/4/1 且不补另一臂。fake 授权只能用于不能出网的替身测试。

不重开会话，不重做原版所有机制，不扩考场，不为报告改动触发真实重跑。不再给交付贴一个笼统“全部 FIXED”；附实际事件和最短运行入口即可。

### 第二批：当前 48 次开发 A/B

前述接线通过且有用户有效新授权后执行原冻结设计：父本 24 + v2 24，dsf/0.7，48 attempts 硬上限，无重试补跑，传输失败停批，原始材料与失败保留。旧 AUTH-EXAM1 不可复用。本指导书本身不新增真实调用授权。

实跑后一次交齐：真实答卷、逐槽证据与语义初审、匿名重点样例、配对质量/污染/成本/时延差异、H1 的支持/不支持/不确定。不要只交“程序分很好”再等下一轮才开始读内容。用户个人票可并行，不阻止工程初审。

这批回答的是回忆候选是否有开发收益，不回答 core 是否无用，不回答整个新架构是否完成。

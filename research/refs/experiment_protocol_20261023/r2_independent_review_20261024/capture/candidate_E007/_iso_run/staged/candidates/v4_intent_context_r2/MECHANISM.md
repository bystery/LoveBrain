# v4_intent_context_r2 — MECHANISM（整套架构：v0 简单事件记忆 + 目标作用域/上下文优先级 + r2 输入边界加固）

## 决策表

| 环节 | r2 策略 |
|---|---|
| 记忆 | 简单有序真实消息事件（只收实际发送的 HER/ME，模型回复是草稿绝不写回）+ 种子事项 `plans` |
| 画像/初始事实 | `ep_meta.persona` + `ep_meta.initial_kb`（支持字段 me/her/…）作种子块，两臂可公开使用 |
| 当前目标 | 解析 `input.intent`(enabled+text+status)，有效才进【当前目标】区（`is_intent_effective`），预算保护（`MAX_GOAL_CU`），关闭/缺省→空、不留旧目标 |
| 目标→行动 | 装配指令明确：可主动创造机会/表达兴趣/反撩/深入；但**不复述目标原文**、**不把新提议说成已同意**、未知不假装关系已确立 |
| 已确认事项 | `initial_kb.ongoing_plan` 种子进【已确认/进行中事项】区，**独立于当前目标、跨轮持续**；关闭目标不清此区，此区条目不自动变成新目标 |
| note | 四类分清提示：公开事实(可直入正文)/私密情绪动机(只调口吻不外发)/拟发草稿(未发不算既成约定)/推测读心(不当对方已确认)；缺信息承认为"不足"不臆造 |
| 时间/来源 | 复用父本 `build_timestamp_prompt`（当前 clock）；当前窗口逐条 `m<i>` alias + 稳定 source_id + canonical_id_map + 消息 ts；**r2 追加来源/媒体/时间作用域三护栏**（见下） |
| 预算 | 历史整段 ≤`MAX_EVENT_HISTORY_CU`，连最近一条旧史单独超限也省略、当前输入独立整段完整保留（不切代理对） |
| 生成 | 单次 `gw.generate(tag=main)`，与父本同一网关/同一契约；**无额外模型调用、无题材词特判** |

## r2 三项输入边界加固（纯上下文组织，实跑故障族驱动）

| 护栏 | 装配内容 | 治哪个已付费故障 |
|---|---|---|
| `_source_rule` | 当前 <chat> id 列表为 analysis.source_ids 唯一合法来源；历史 `m_src[uid]` 只供理解/相关回扣，不得作本轮新证据 | E006_T02 非法引用历史 ID(t1_0) → 程序 veto |
| `_media_line` | 按本轮真实附带图片数表达；0 图时明确禁止评价构图/摄影，仅文字分享可期待/追问/聊内容 | E004_T08 无图装看图（images=[] 却称"照片看着有意思"/"构图可以"） |
| `_time_scope_rule` | 时间性事实属于其出现日期、跨日不自动继承；职业/身份不证明实际出席/亲历；不确定就说不确定 | E005_T06 把旧日"三点前有空"迁到新日；由教练职业编造带课亲历 |

三护栏都是把"该信息属于谁/哪天/是否真的可见/能否作本轮来源"显式写进装配，不改 system 资产、
不加第二次模型调用；是否降低真实错误率须由 原版 vs r2 实跑对照证明，fixtures 只证明它们进入请求。

## 明确不做（公开声明的能力缺口）

- 不做 topic/ongoing/scene 多层摘要、自动画像重估、跨轮反思、辅助生成（v0 的简单性保留）。
- 不从模型输出自动提取/写回"已确认约定"——初稿 `plans` 只来自 `ongoing_plan` 种子；"关闭目标≠删已确认约定"体现在状态分区不被 intent 清空，而不是自动记忆写入。真正的自动事项维护留作后续对照，本稿不声称已实现。
- 语义是否"更会聊"未证；fixtures 只验输入行为，效果须实跑。

## 与父本/v3/v0 关系

- `build_system_prompt`、`rc.*`、各语义块来自 `reference_product_v1`（进身份闭包，不复制漂移）；system 资产与 v3 同一份（自带副本，不改冻结 v3）。
- v3=父本机制+精简system（只动 system）；v0=精简system+简单记忆（公平输入）；v4=在 v0 记忆简单性上加"目标作用域/上下文优先级"一层。

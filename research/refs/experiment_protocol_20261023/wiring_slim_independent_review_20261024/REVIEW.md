## 3. 一个合并实跑收口工作包

### 3.1 paid 证据默认会被删除，live 数字报零

`tools/exam_interleave_plan.py:407` 默认 `keep_tmp=False`；结尾第 665–666 行会删除整个 out_base，live 也不例外。

独立测试实际 live 分支但用假 HTTP：执行 48 次，账本 48/48/0；函数返回后指定的输出目录不存在。

同时第 631 行使用 `len(captured)` 统计 live 次数，但只有 capture/live_stub 才填 captured，故同一次测试汇报 `real_model_calls=0`。

这是普通真实运行就会碰到的问题，必须在派发前改好：live 强制持久目录、拒绝覆盖，成功/异常都保留原始产物；真实调用数据真实网关事件统计，替身次数与真实次数明确区分；完成或失败时收口授权与实际消耗。不要只在调用示例里加一个可忘掉的 keep_tmp=True 来掩盖危险默认行为。

### 3.2 整批预检只检查 8，而非本计划 48

每个 resident 给 `batch_need=8`，六个 resident 在生成前一起初始化，均可看见相同的未消费额度。独立将计划保持 48、授权上限设 8，结果先派发 8 次，直到第 9 槽才因额度不足停批。

没有超额派发，但这不是所声称的“整个 48 次批次在不足时零派发拒绝”。在初始化/派发前通过同一授权级预算权威检查完整批需 48；此后仍逐 attempt 原子占额，不因预检而取消逐次约束。已有关闭授权、未决账本或不足剩余额度必须在首发前拒绝。

### 3.3 两臂总 prompt 差不是联合注入预算

`_combined_newctx_from_calls` 以 `max(0, len(candidate_user)-len(parent_user))` 作为新增 extras+recall。

两臂真实生成后状态可以不同；共同裁剪也可能移除其它片段，所以这个差值既可能隐藏越界，也可能因其它状态变长而误报。独立构造父 prompt 长 5000、候选回忆段长 2005，函数报告 added=0。

保留差值，但命名为“跨臂 user 总长差”，仅作诊断，不能作为 1800 联合预算的门禁。真正的注入预算应从候选同一份状态、同一次装配的 extras/recall 渲染片段计算，并和最终请求对应；不需要拿另一臂的随机状态反推。现有 `_fit_new_context` 的 15 项测试继续保留，无需重写 v2 检索。

### 3.4 评审的题面绑定还在读活动工作树

缺散列拒绝已修复，签收。`exam_layered_score.py:255/330` 仍从工作树 benchmark 读取 case input；只是增加了不同身份的展示字段，尚未改成真实运行快照。

与实跑证据保留一起处理：在生成侧保存当时 input 散列/快照，评审消费这份证据，逐条绑定实际 run/batch/harness/输出。旧批兼容显式区分；新批缺失记未评。无需为此再造一种题库 schema 或重跑模型。

本节四项属于“真实答卷可保存、预算可执行、指标可解释、评价可复算”的同一闭环，不拆成四次退修。更多低频工具美化不列本批前置。

## 4. 精简候选的研究判决

`v3_system_slim` 是值得真实测试的资产删减候选，不是已证明的新冠军。独立重放支持其保持父本机制行为的设计意图；模型读到新 system 后，记忆摘要和后续状态仍可能变化，这正是实跑应观察的结果。

下一批离线准备中直接处理两点：

1. core 将“备注/意图/目标”统称私下动机并写“不能当作既成事实写进正文”。note 也可能包含可公开的真实位置、日程等，不能一概禁用。区分可公开事实、私下目标/情绪、未发草稿和推测，不增加特定考题词。
2. 补齐候选 MECHANISM.md 并更新身份记录，一次完成即可；不为几十行元数据重开审稿波次。

另外，format 对“同一事项不再借它调侃”的概括可能压制合适旧事回扣。将其作为正向能力保护：重复叮嘱和无关占题应减少，服务当前互动的新回扣仍允许。不把它当程序禁词或一律 veto。

之后做真实比较才判断：删掉资产是否保持准确，是否更自然/主动，真实 token 与等待如何变化。

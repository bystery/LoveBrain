# 给本地 worker 的修改与交接指导书 v2

日期：2026-10-22。目标：修正汇报与额度闭环、收口实际隔离、支持纯上传的独立出题会话。不要把三项工作变成几十轮零碎请示。本文不是新增真实模型调用或系统配置变更授权。

## 1. 对前一份汇报的评价与必须更正项

有实际进展：新集成记录与当前release散列匹配，两次run的真实开始/完成账在位；新的自报状态也保留G08失败与独立题库未就绪。对实际通路证据予以保留。

但不能再写“工程全部修完，只缺用户给钥匙”：

1. 受限环境未部署、未授权文件仍可读，这是尚未完成的工程能力。可以需要部署权限，但不能把通过责任全部转给用户。提出一个基于现有环境的具体建议、变更范围/回滚/验收，再走必要授权；不要只丢三个术语让非技术用户选。
2. 独立选择/B不仅缺身份，还缺实际故事、评审条件、素材/来源与保管。填一个名字不会自动出完题。出题、工程导入、权限隔离三件事要分别报状态。
3. G11真实通路跑过不等于全考场通过，也不等于授权额度合规。现有总验收仍NOT_READY；已做过开发实验不等于正式受控循环已准入。
4. “两次结果完全一致”改为“两个run均分同为10.0、均无veto”。独立逐字比对两批6个reply_raw：**0/6逐字相同**，不得把分数一致写成文本或行为一致。
5. 首跑延迟13,977–34,536ms；第二跑21,496–40,638ms。当前结果应报约21–41秒，不能沿用首跑14–35秒。每个数字自动从对应run账本计算，带单位与run_id，不手写串位。
6. “我自己设了≤8次”不能淡化额度约束。依据授权单max_attempts=8，两个run合计12，超出4；这是执行事件，不是仅“版本瑕疵”。当前通路数据保留，授权合规项登记FAIL/EXCEEDED，不以第二个run的6/8冒充整个授权合规。

本次审查只核对新报告、验收/授权文件、release散列与两批真实账和原文一致性；没有完整独立复验你新修的所有代码。汇报中的“26项全过”等应标worker自验，不伪装成审查方已经全单签收。

## 2. 首先做零新调用的额度事故收口

保留这两个run及历史原件，不覆盖、删掉或通过改报告抹除：

- iso_20261022_134330_c14b8a：6 started/6 completed。
- iso_20261022_134917_17cb65：6 started/6 completed。

新增更正记录，列授权范围/消息来源、两个run、总尝试12、上限8、超额4、触发原因、当时应停止的点。首跑后只剩2次，重跑完整6次在派发前就应被拒绝。历史授权不能自行追认或再用。

预算权威应属于整个authorization_id，不属于run目录、代理实例或release显示名：

- 每次真实派发之前，从可信持久账本核对该授权全部started；失败与未决都计消耗。
- 创建新run、重启进程、恢复、修授权单/evidence路径、换版本或代理实例都不能重置额度。
- 多阶段与辅助调用也算；并发占额必须原子化，不能两个进程各看见剩2次后各派2次。
- 预计整批需要6次、只剩2次时，整批预检拒绝；不先跑到一半再申请补额。
- started落盘失败零派发；失败终止/未决结算政策不能被候选捕获异常后继续调用绕过。
- 同一个单次授权完成后关闭；新授权只能来源于用户，不能自动复制authorized=true。

用本机替身或确定性假适配器完成反例，不新增真实模型尝试：已花6/上限8再申请6；新run重入；跨进程；并发抢占；重复attempt；日志写失败；终止后重启。必须断言实际派发次数，而不是只看拒绝文案。

## 3. 版本与证据分层，避免改文档就再烧一批

保留运行时真实execution_fingerprint（执行代码/契约/题面/候选/参数/允许媒体等），运行授权身份和报告/路径元数据分别记录。原始运行证据不可改写。

补evidence_file位置、改报告数字或添加本次出题指南，不自动意味着模型行为变了，更不构成重跑许可。可以保留当时完整版本与散列，再用独立的索引/更正记录解释差异；不能把旧run伪绑定到新版本。只有影响执行的变更确需新实测时才提出新的、足以覆盖完整批次的授权申请。

不要因为本指导书或上传指南新增而自动freeze→复跑。先判断它是否进入执行依赖；即使进了，也先保存旧版本与证据，不借重冻结绕预算。

## 4. G08需要交的是部署与攻防结果，不是名字

先只读盘点现有可用隔离能力与接口，选择一个实际可落地的建议。提交具体受限对象、只读挂载/依赖闭包、自身写状态、控制器私有区、凭据、媒体与代理网络策略，以及部署影响、回滚和正常功能/攻击对照。不做新的窗口站/令牌/DACL试错长跑。

真正需要系统变更的动作先准备到可审阅，再按用户明确授权执行；未获许可不部署。不通过则保留NOT_READY，明确一份最小部署前提。不要把G08必要失败改叫“残差PASS”，也不要把“装好某个产品”当隔离自动合格。

部署后的检查必须走同一生产入口：普通open、路径跳转、绝对路径模块加载、其他候选/历史答卷/备份/账本、子进程、未登记媒体、真实协议直连、正常依赖/媒体/自身状态/恢复。必须是实际拒绝证据；FileNotFound、超时、HTTP协议错误不是权限拒绝。

保留原题库和旧证据。不再对主仓deny/reset试验，不搬整树，不为了通验收删ACL残骸。此前“每批<50/逐文件删除以避开批量确认”的建议撤回：不能靠拆分删除规避宿主安全确认；优先用新建审计目录，真实清理另行核验路径与授权。

## 5. 给纯上传出题会话的材料规则

审查方已提供两份自包含文件：

- QUESTION_AUTHOR_GUIDE_UPLOAD_v2_20261022.md：完整背景、格式、示例、题库划分、12族与交付标准。
- QUESTION_AUTHOR_START_SELF_CONTAINED_v2_20261022.md：启动prompt与上述指南的一体文件；上传这一份即可开始首批，不需要读取本地目录。

新会话只能读上传文件，不能写“先读AGENTS/某个本地路径/旧会话”。不要把候选源码、实跑输出、调参记录、选择/B内容或私人原始聊天塞进公共命题包。无需另买账号；角色分工与实际保管必须明确，另开窗口本身不算技术隔离。

如果本地公开契约有确实必要的新变化，你可以做一次定点补充：

1. 只读公共输入/输出契约与有效版本，提炼字段类型、默认值、许可与限制；不复制整项目或历史意见。
2. 把必需内容直接写进上传文件，不留下要求读取电脑的依赖。
3. 内嵌完整可解析示例和允许/禁止行为；已知不足如媒体未上传、接口未支持明确标注。
4. 输出新版本和简短差异表，不静默改变24首批或200建议规模，不夹带针对既有题面的车次/编号特判。
5. 检查文件里的每个“参见/读取/运行”要求：要么内容已内嵌，要么是可选的本地导入职责。出题会话不能被要求执行本地程序或假报其成功。

本地来源路径和源文件散列可留在worker审核附件，不作为出题会话必须取得的输入。没有变化则直接使用自包含文件，不必再扩成巨大资料包。

## 6. 题目回来后的本地职责

先接收公开开发pilot的3故事/约24位；逐一核对数量、角色、时间、媒体/许可、schema、来源、隐藏资料边界及故事家族。不调用考生来判断JSON能否读入，不让用户逐行修工程问题。

命题方的语义判据保留为评估侧附件；不要把它塞进note/persona。当前运行器不支持的字段/媒体标适配缺口，不擅自改成别的故事或修改评分器迎合。机械拆文件/登记素材可确定性完成；台词、事实、观察条件的变更留版本并交内容方确认。

独立选择40/B80的全文只交可信保管角色，开发方不能为了做导入而全部读一遍后仍宣称独立。缺可信保管流程时明确“内容草案完成/未技术封存”，不能给custodian填个名字就G06b PASS。

不为补数机械造几千位。正式200建议目标为开发80/选择40/B80；开发可复用通过自然度审核的已有完整故事，暴露题不移进独立集。按整个故事家族分，素材、模板和派生都留同一划分。

## 7. 汇报与收口方式

一次交三个工作包的结果：A 额度与证据更正/离线反例，B 隔离部署方案或已授权后的真实验证，C 自包含命题交接与公开pilot导入准备。不每改一行就问继续，不额外真实复跑，不自动开会话或子代理。

状态必须分开报：

| 项 | 报什么 |
|---|---|
| 执行引擎 | 同路径装配/调用/评分/恢复/审计的已验与未验 |
| 授权与预算 | 当前授权累计消耗、超额/未决、是否已关闭；不能只报本run |
| 真实隔离 | 实际运行环境与攻防结果；未部署就是未完成 |
| 开发题库 | 自然故事/机械压力/变体分别计数，已验收还是草案 |
| 独立选择与B | 内容、独立性、保管分别报，不泄题 |
| 用户语气 | 用户实判与工程初审分开 |
| 正式训练准入 | 唯一入口与准入条件是否真满足，不用程序满分顶替 |

G11已有通路数据保留，但预算事件不能消失；新代码的worker自验与审查方独立签收分开。当前不能再说“用户选个人、批个权限就全部齐了”。当设施、授权闭环与所用开发集验收确实通过，可以交付明确限制为开发诊断的训练启动prompt；独立选择/B未就绪时不得宣称正式晋级或monster。

# 给 worker 的 Arena V14 合并收口执行书

日期：2026-10-22。配套证据与完整判决：`refs/ARENA_V14_INDEPENDENT_REVIEW_20261022.md`、`refs/arena_v14_review_20261022/`。

## 0. 这次只交一批，不再小修一条就等下一轮

目标是**收口考场设施并交付可复制的开启 prompt**。不训练 phase3，不追 monster，不重跑旧 66/52，不改被测候选来迎合本次验收。以下独立项连续推进，最后一起给结果；真正的环境硬阻塞只报一份具体前提，继续做不依赖它的工程。

本执行书没有真实模型调用授权。不得开新会话/代理，不得新建窗口站，不得继续修改主仓 ACL、移动题库树、清理残骸或循环试管理员权限。先读证据，保留已签收代码和测试。

## A. 先关闭真正的可信边界

1. 控制器禁止 import/exec 候选、候选父依赖或回传代码。版本/能力通过静态声明与宿主握手获得。导入副作用探针必须只在宿主留痕，可信进程零执行。
2. 选择一种实际可用的隔离运行环境，使候选仅见声明代码/资产/媒体和自己的状态，不见题面原文件、控制器私有区、备份、原评分器、历史答卷、其他候选状态或凭据。普通 cwd、Python -I、同用户设权不是替代。若环境未提供，登记 G08 NOT_READY/FAIL 和一份部署前提，停止权限试验，不把必要隔离降为残差 PASS。
3. 模型代理只接受该轮可信登记的媒体引用；解析后必须属于授权资产、散列与大小匹配，拒绝私有文件、路径跳转与未批准远程 URL。模型/温度在固定比较中以可信配置为准，候选覆盖应被拒绝。
4. 文件权限若仍用于合法环境外围管理，必须恢复精确原权限，失败即停止，宿主退出后再解除保护；不得对主仓做试验。合成攻击的保护策略必须来自生产入口，禁止测试自行额外保护靶子来冒充生产通过。

本组必须一起测：合法候选依赖/媒体/状态正例；导入副作用；普通 open 和绝对路径导入；未点名私有 canary、其他候选、历史日志/副本；私有文件伪装媒体；真实协议直连免密本地上游；子进程绕过。PermissionError 等实际拒绝才能算阻断，FileNotFound/超时/协议坏请求不能冒充权限隔离。

## B. 恢复、额度与账本一次修完

1. new 与 resume 分开：new 目录存在即拒绝，resume 不删除 staged/out/control，不默认回退 init；校验候选/题面/版本/检查点身份后，从准确下一轮开始。
2. 整个授权批次的硬上限由可信持久化 attempt_started 决定；恢复/重建代理不得重置。attempt 身份全局唯一，run/candidate/episode/case 均正确。未决尝试计入已消耗，失败政策与停批策略明确。
3. started 写入失败时**零请求派发**；完成/失败落账异常不能当正常成功。固定配置与授权清单绑定，重新启动不能绕额度或换端点。
4. 调用总账不可覆盖；每轮 calls/usage 只记本轮，episode 累计只能相加一次。两轮各一次要得到 1+1=2；多阶段与恢复都同测。
5. 用同一个生产 CLI 演练“前两轮→结束进程→恢复→下一轮”，验证前史字节未变、真实计数连续；故障后不得静默从头生成或自动补跑。

## C. 把已有正确部件真正接入总验收与交接

1. 验收结果集合必须唯一、完整并绑定当前 run/release；任何实际 FAIL、重复 ID、未知检查项或不允许的残差均不能被吞。G09 读取真实事件与 sidecar，不能只查非空 note 字典。
2. G07 直接复用 rv2 的内容验证器，并重新核验录入/聚合；篡改实际展示原文必失败。生产匿名材料读取冻结 calls/reply_raw/manifest，不从手写 spec.reply 生成；有效意图、许可、历史、真实注入分别展示，fixture 与真实输出分开。
3. 保留参考基线 26 个 helper 夹具，补至少 8 组完整生命周期→下一轮请求/恢复的确定性对拍。机制入口缺失、损坏或状态更新缺失时 G04 必须失败；期望值溯源冻结产品，不拿父子互相一致当原产品保真。
4. 完成现有覆盖族的正反保护证据登记，允许复用真实节点但不虚增独立样本；自然故事与 220 机械压力轮分开。不为补数字机械造题。selection/B 未建立继续明确 NOT_READY/NOT_CREATED。
5. 本地替身独立标 G11_STANDIN；G11 只认可当前版本、已授权真实上游的有限集成证据。没有真实执行不得 PASS，退出码与总状态必须一致；用同版本离线证据承接状态，避免 integration 只写一条 G11。
6. 发布包纳入实际唯一 CLI 及其完整依赖；干净包分别测试 offline 和本地替身完整入口。重算当前 release 后，旧散列的 G11 替身记录作历史证据，不混用。
7. 更新 START_PROMPT 与指导书为本版本唯一有效交接；主动标明旧 lb_runner 非隔离入口与管家 core/full/test_suite/aggregate 不适用当前训练。更正“成本唯一排序”“审查者高于用户”的错误。

## 一次性交付及停止规则

交付一份整合报告，格式固定：已关闭问题→新增正反证据→剩余阻塞→当前状态；附本次完整 raw 账、版本散列、干净包与**一段可以直接复制到用户手工新开的会话中的开启 prompt**。不要以又一份任务清单替代结果。

开启 prompt 必须：先快速检查当前验收；不通过则最多汇总三组阻塞并停止，不能在训练会话重建考场；通过后按用户明确授权的轮数/实际请求预算训练，不写自动进化脚本，不开会话，不读封存内容，质量优先、成本如实记账。使用唯一可信入口。

泛化纪律写入开启 prompt：训练对象是通用主体、证据、事件/属性、状态、时效与对话组织；禁止按具体题目/编号/交通等话题词路由答案。开发验收使用至少三个不同生活领域的正反对照，已暴露题和同模板换名仍是开发回归。考生尚不会某一能力不阻塞考场工程签收。

离线证据真正全过之后，只申请**一次**已有范围的 ≤8 次真实集成授权，清楚写实际端点、模型、温度、逐请求目标、失败停批、禁止重试与总额度。此前审查和旧 52/66 授权均不等于新授权；不要求用户重设计模型部署。

最终状态三层如实交付：离线工程已过 OFFLINE_READY → 真集成已过 ENGINEERING_READY → 独立选择内容/保管已落实 ARENA_V1_READY_HUMAN。如果只缺独立选择，可提供明确限制为开发诊断的开启 prompt，不能宣称正式晋级、自动 Judge 或 monster 已通过。

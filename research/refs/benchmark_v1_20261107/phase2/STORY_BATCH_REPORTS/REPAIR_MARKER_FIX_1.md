## 二、修复机制登记（为什么改这些就够）

- 构建期 `enrich_cancel_atom` 会对取消族原子**重算并覆盖** `affirm_markers`（value/quote ∩ 源消息/语料），仅当其四步全提不出 ≥4 字逐字信号（`no_verbatim_signal` / `single_phrase_too_short`）时 reference.json 原值才落盘。逐原子核验：**43 处违例全部来自 enrich 返回 None 的原子**（如 E337_T08_A02/T10_A04/T12_A03、E338_T11/T16/T23/T26、E338_T14_A02/T28_A01），即修复后的 reference 值就是实际落盘值；enrich 成功覆盖的原子（E337_T06_A01、E338_T13_A01 affirm、E338_T31_A01 等）其 reference 内旧 markers 是死数据、QC 不可见，按「未违例不动」原则保留原样。
- `item_markers` 仅 status∈{cancelled,canceled} 时进 C8（`gold.cancelled_items`，子串匹配 ongoing item）；superseded 原子的 item_markers 为 QC 可见、判分不消费，按同规则修复。
- E325_T09_A01 仅动 item；R2 刚修复的 affirm 重锚 [["匀两节","教练"]] 与方向未触碰。

## 六、同规则发现登记（未在本轮修，交协调方裁决）

对 `unknowns` 对象（GOLD_SCHEMA §8#3 `{topic, affirm_markers}` 形态）按同一逐字规则额外扫描（官方 Marker QC 只扫原子，不含此项）：wave4_dev 190 个对象化 unknowns 共 635 个 marker 词，**303 处（48%）非逐字违例**，分布在 33 篇（E334=26、E337=17、E313=16、E309/E318=15、E328=13、E312/E314=13、E307/E311/E316=11-12 … E331=1）；且各 unknowns 的 `markers` 与 `affirm_markers` 为逐字镜像字段，违例集合完全相同。根因与原子侧同族：把"候选可能说什么"的假设短语（如"组长其实特别满意""批注里骂的是"）写成了 markers。**本轮未改动**，理由：①官方门禁与本次交付范围均为原子 markers；②假设短语 markers 命中即近乎必然是坐实（精确率高但零逐字合规），机械换成 topic∩题面锚点会把"提及"误判为"坐实"（C15 对正确回声误伤），需要逐 topic 设计或按 §8#3 enrich_unknown 口径+"诚实置空→unrated"的专门一轮处理。建议另开 marker-fix-2 承接（含 markers/affirm_markers 双字段同步纪律）。

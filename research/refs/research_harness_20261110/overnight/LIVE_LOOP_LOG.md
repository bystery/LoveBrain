## LOOP-14 — RH-B-22 角色内化（Deep Persona 文献驱动，撞墙后从头重设计）

**文献驱动（看门狗撞墙合规：≥5 篇精读 + ≥2 方向）**：

5 篇精读（方法节+实验节）：
1. 精读 **Deep Persona** (2609.22255)：三层架构——可观察表达 / 潜在信念 / 核心动机驱动。现有 persona 描述是浅层（"她叫什么、做什么"），缺少信念层和动机层 → 行为不连贯。
2. 精读 **From Memory to Behavior** (2609.21349)：Situation→Internal state→Behavior 框架。角色行为不是直接从情境生成，而是经内部状态中介。
3. 精读 **EchoChat** (arXiv 2026)：认知共情=感知→心理状态推理→响应。LLM 把共情当直接映射→"superficially warm but emotionally hollow"——精确描述我们的 Q2=4 天花板。
4. 精读 **MemRole** (2611.01778)：长期角色扮演的记忆→决策推理。记忆不是注入上下文，而是塑造角色决策。
5. 精读 **Few-Shot Bot** (2110.08118, 重读)：示例锚定有效（b20 验证），但示例应与当前情境相关——b20 的 3 个通用示例缺乏情境适配。

2 条替代方向：
- **方向 A（实现）**：角色内化帧移——system prompt 从"你在帮助我回复"改为"你是[我]，此刻正在看她的消息"；输出结构增加"此刻心态"一行（单次调用内生成，非二次调用）；保留 b20 示例锚定。
- **方向 B（备选）**：动态示例检索——从对话历史中检索与当前情境相似的好回复作为示例（Few-Shot Bot 的检索版）。需相似度计算，复杂度高。

**方向 A 选择理由**：
- 帧移是 5 次实验中唯一未测试的维度（M5 prompt 资产 + M3 意图处理层）
- EchoChat 的"superficially warm but emotionally hollow"精确对应 Q2=4 现象
- 单次调用（= b20/DIRECT 成本），不加调用
- "此刻心态"字段在 JSON 内同次生成，不是 b19 的二次调用分析

**机制设计（rh_b22_persona_internalize）**：
1. system prompt 重写：第二人称参与者帧——"你是{me_name}。你正在和{her_name}聊天。你看到了她的消息，想着怎么回。"
2. 历史格式改："[我]"/"[对方]" → "我："/"她："（聊天界面帧，非观察者标签）
3. 输出结构：{"state": "此刻你的心态（一句话，不输出给对方）", "action": "reply/no_reply", "recommended": "..."}
   - state 字段在单次调用内生成，迫使模型先确定"我此刻是什么感受/想什么"
   - state 不发给对方（归一化器只取 recommended）
   - 与 b19 本质差别：b19 的分析是"对方情绪+策略+事实"（外部观察）；b22 的 state 是"我此刻心态"（内部参与）
4. b20 的 3 个示例保留（已验证锚定长度/风格有效）
5. 成本：1 次调用/轮（= DIRECT/b20）

**预登记判据（smoke_24，对照 DIRECT 4.69 + b20 4.62）**：
- ①五维均值 ≥ 4.75（首次超过 DIRECT 即有信号——帧移假设验证）
- ②Q2 逻辑连贯均值 ≥ 4.3（b20/b21 稳定 4.0，帧移预期提升——内心状态锚定逻辑链）
- ③tokens/位 ≤ 1,600（state 字段约+50 tokens）
- ④长度中位数 30-70 字（b20 示例锚定保持）
- ⑤亲读：state 字段是否真实反映内心状态（非套话）；recommended 是否从 state 自然流出

# 机制候选预注册（架构级，非 prompt 调优）2026-11-11

**性质**：预注册。设计依据＝`RESEARCH_EVIDENCE.md`；测试前提＝`RULER_REBUILD_PREREGISTRATION.md` 的 §3 健康门通过（**门不过不得跑配对、不得做任何晋级判决**）。
**设计空间耗尽门槛**（用户原话）：至少要 **15 个实质不同版本**的 harness 才有资格说"设计不出来"；换措辞、加角色名、挪并发数、改上限一律算**配置对照**，不算新版本。本文件先立 5 个机制族（F-A…F-E），每族含 3 个可独立实现的版本位，共 15 个版本槽，逐族按证据保留或淘汰。

统一评审口径（全部候选共用，冻结）：**pass^3** 加权质量分、按 §-1 判停主口径 ≥50 个百分点绝对提升、并列报告严重错误族与 token/p95 等待；配对 + 交换轮位 + ≥3 次有效复跑；judge 未过上岗线前只做初筛。

## F-A 记忆双门与说话人分池（对应 M1+M2，直击"旧事重提/张冠李戴"）

**机制内核**：记忆条目结构化 —— `{fact_id, subject(HER/ME/AI 三池), source_msg_id, t_at, valid_until, status(ongoing/cancelled/superseded), confidence}`；写入时按**说话人分池**（用户说的 ≠ 助手说的），读取时**相关性门控 + 时效过滤**，取消/被取代的事实**不删除而标失效**，注入前做 `suppressed_by_relevance` 判定。

**外部依据**：HaluMem（arXiv:2511.03506）把错误拆成提取/更新/问答三段，长记忆完整率低到 **3.23%**，且"助手自创细节被当用户事实写入"是主要错误；Mem0（2504.19413）用 ADD/UPDATE/DELETE 标失效换到 **p95 −91%、注入 token −90%+**；LongMemEval（2410.10813）**会话级检索 0.670 > 轮级 0.615**、时间感知查询扩展 **recall +11.3%**，并把 single-session-user 与 -assistant 分列；A-MEM（2502.12110）**无时效/失效策略**，故不能用来防旧事重提（这条是否决依据）。

**版本位**：
- F-A1 说话人分池 + 失效标记（存储层最小改动）
- F-A2 会话单元写入 + 时间感知检索扩展（检索层）
- F-A3 相关性门控注入（注入层，宁可不注入也不污染）

**可检验假设**：在 M-PAIR item 上，F-A3 使"记得住且知道不该提"的 pair 通过率相对基线提升 ≥15 个百分点，且 `stale_kw_*` 族严重错误相对下降 ≥50%；注入 token 不升。
**预期失败题型**：需要**合理旧事回扣**的场景（相关性门控过严会把该提的也压掉）——所以每个版本必须同时报 recall 与 suppress 两侧，只看 suppress 侧收益是作弊。
**与 prompt 的边界**：本族全部是数据结构与检索控制流改动，不得用"在 system prompt 里加一句别乱提旧事"冒充本族实现（§-1 ⑤）。

## F-B 回复时机与是否回复的专用判定（对应 M3，外部证据里唯一接近 +46pp 的机制族）

**机制内核**：把"要不要回、什么时候回、回什么长度档位"从 prompt 判断挪成**独立判定环节**（分类器/打分头），输入为 静默时长、消息密度、用户提问性、话题状态、未回收钩子、当日互动节律；输出 `{reply|no_reply|delay}` + 置信度，低于阈值才回落模型判断。**合法不回**与"该回不回"都进严重错误族。

**外部依据**：TimelyChat（arXiv:2506.14285）**专用小模型 Timer-3B F1 0.79 vs GPT-4 提示法 0.33**；Inner Thoughts（2501.00383）人评含"时机恰当性"维度；外部还提示提示法判"何时回"很差 → 机制化是唯一正解。

**版本位**：F-B1 规则+阈值（零额外模型调用）；F-B2 轻量判别头；F-B3 与记忆相关性门控联合决策。
**可检验假设**：`decline_appropriateness` 与"该回不回"族错误相对下降 ≥50%，同时**每 episode 调用次数与总 token 下降**（不发无谓回复就是省钱）——这是唯一可能同时满足主口径与成本口径的族。
**风险/反例**：误判不回 = 直接破坏真实互动（用户明确"合法不回应评动作，但要求回答的轮次不能靠全不回来拿高分"，§10）。因此该族必须在配对的"必须回"子集上零退化才允许晋级；单纯提高 no_reply 命中率不算收益。

## F-C 多候选 + 硬边界否决（对用户点名"广撒网"机制的**证据修正版**）

**机制内核**：保留"生成多条"，但**取消 judge 口味择优**，改为**可判定的硬边界否决链**：事实一致性、主体一致、时效/状态、禁区词、契约完备、物理可行性；被否决的候选**不得成为首选**，只在全部被否决时按预登记次序回落。首选始终只有一条。

**外部依据（否决依据更硬）**：best-of-n 的正收益全部来自**有可执行验证器**的场景（Large Language Monkeys 2407.21787：SWE-bench Lite 15.9%→56% @250 样本，且必须靠验证器把 coverage 变准确率；Snell 2408.03314：compute-optimal 比朴素 BoN 高效 >4×，策略取决于验证器强弱；BoN-RL-V 2412.15287 明示验证器会误选）。反向：Self-Consistency（2203.11171）**要求唯一正确答案**，自由文本不适用；arXiv:2407.10457 显示 **greedy 在多数任务优于温度采样**；2403.02419 显示调用数增加**非单调**；MT-Bench 换序一致率仅 65%；2305.17926 仅换位置就让 Vicuna 在 66/80 题"胜"ChatGPT；**本地** `vote_sim` 5 位置票仍 33/100 翻转。
**结论**：同一基座自生成 + 自挑选的误挑率量级 ≥30%，"择优"不成立；"否决"成立（否决项都是可机械判定的断言）。
**版本位**：F-C1 纯否决（首选一次生成 + 违规重生成，最多 1 次）；F-C2 并行 2 条 + 否决链；F-C3 否决 + 分段回退（否决后不重生成，直接降级为安全回复）。
**可检验假设**：F-C1 使**严重错误率相对下降 ≥30%**、`severe_error_backup_rate` 下降，代价为重生成调用 ≤1 次/请求位；若 `at_least_one_pass_rate` 高于 `primary_semantic_pass_rate` 的差值主要来自"合格但更差"的候选，则说明广撒网对本场景无价值，本族整体淘汰。
**依赖**：正在跑的 `analysis/wide_net_20261111/` 给出"生成瓶颈 vs 验证瓶颈"占比，占比结果直接决定本族是主线还是配角——**预注册于此，不因结果好看不好看出入**。

## F-D 上下文分区与压缩注入（对应 M4，质量与成本同时达标的先例族）

**机制内核**：对话分区（当前活跃话题 / 未完成钩子 / 稳定事实 / 近期叙述）+ 关键约束前置 + **压缩中间段**后注入，显式预算分配与溢出降级次序。

**外部依据**：Lost-in-the-Middle（2307.03172）U 形退化；LongLLMLingua（2310.06839）**4× 压缩下 NQ +21.4%、LooGLE 成本 −94%、延迟 −2.6×**（注意：客观 QA 场景，迁移需本地验证）；Mem0 full-context 质量最高但代价 12× → 我们 17770 上下文本就装不下全史，压缩是必需而非可选。
**版本位**：F-D1 分区 + 约束前置；F-D2 摘要压缩中间段；F-D3 预算驱动的动态降级（超预算时按"稳定事实→近期叙述→钩子"次序丢）。
**可检验假设**：总 token 下降 ≥50% 而质量在预登记可接受差异内相当（§-1 ① 的成本口径达标路径）；若质量下降，必须报交易而不是平均掉。
**风险**：压缩会误删事实 → 与 F-A 的失效/来源字段联动，被压缩内容不得成为唯一证据源。

## F-E 意图驱动分支路由（对应 M3+M4，"很少提示也知道你要什么"的 harness 本性）

**机制内核**：意图（调情/邀约/安抚/收尾/日常）显式路由到**不同装配分支**：不同注入组合、不同长度与钩子策略、不同否决严格度；无 intent 的题目走保守默认。主会话不做"什么都自己拼"的全量装配。

**外部依据**：DeLM（arXiv:2606.10662，我已亲验摘要）**用共享上下文 + 任务队列取代主 agent**，准确率最高 **+17.5pp**、速度最高 **2.49×**；Scaling Agent Systems（2512.08296，我已亲验摘要）**可分解任务 +80.8%，顺序依赖 −70.0%**，且"无集中验证的架构更易传播错误" → 只有**可分解**的判断才值得并行，其余一律单路径；MAST（2503.13657）失败主因是系统设计（干预后 ChatDev 25%→40.6%）。
**版本位**：F-E1 意图→装配分支静态路由（C10 已有意图契约，天然可测）；F-E2 意图 + 话题状态联合路由；F-E3 共享证据工件版（活跃事实/钩子/状态写成工件，各分支自取，不做全量重装配）。
**可检验假设**：F-E1 在带 intent 的题上 `intent_kw_*` 合格率相对基线提升 ≥20 个百分点，且**不增加调用**（路由本身是控制流，不是采样）；F-E3 相对 F-E1 降低重复装配 token ≥30%。
**预期失败题型**：意图隐含或混合（安抚里带调侃）——必须报"意图误路由率"作为独立严重错误族，否则路由会把错分支的回复直接送出去。

## 跨族统一禁令（写在这里防止下一轮手滑）

1. 不得以 prompt 措辞改动冒充上述任何一族的实现（§-1 ⑤）；每族实现必须有 `mechanism/` 代码 + 事件记录证明分支/字段真的被用到。
2. 不得在量尺健康门通过前跑配对赛；通过后**第一批只跑对照**：基线、负对照（无记忆/全量复述）、最小 harness、各族 1 个代表版本。
3. 不得用"均分涨了"宣布收益；一律 pass^3 + 配对差 + 严重错误族 + 成本四项并列。
4. 每 3 轮、每次冠军替换前必须再做一次外部机制扫描（§3.1），并写 `logs/round_N_scan.md`，列"引入/否决 + 理由"≥3 条。
5. 结果只停在"设计/离线/模拟/未触发"的，必须标明实际到达的层级；无效场（越界、缺回执、泄漏、超时）单独归因，不得充当质量差距。

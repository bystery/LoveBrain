## A. 量尺与区分力（决定题目要做到多难）

**A1 项目分析（item analysis）经典判据** `[子检索]`
出处：Real Statistics《Item analysis basic concepts》、Jdyu 医学教育选择题分析。
作者验证：区分度 = 高分组通过率 − 低分组通过率；**全对或全错题 DI = 0**；D < 0.2 应弃用；难度（通过率）宜落在约 **0.3–0.8**。
局限：来自选择题测验，迁移到"连续剧情 + 多槽位回答"需按请求位而非按题计算。
本地假设：把 LoveBrain 质量池的每个请求位当作一个 item，按基线通过率与"能否把高分组/低分组分开"筛题；基线 ≥0.9 的请求位全部出质量池。
反例：难度 0.3–0.8 的题仍可能因 gold 太宽而对任何机制都给出高分，区分度还需配合失败行为可复现。

**A2 GPQA 的设计目标** `[子检索]` arXiv:2311.12022。
作者验证：以"领域博士 65%、非专家 34%"为目标构造题目，即**基线必须显著低于天花板**才叫有效量尺。
本地假设：对应到我们场景 = 参考答案判据要难到"普通 harness 只能拿一半分"，而不是人人满分。

**A3 SWE-bench Verified / 自动评分会错杀** `[子检索，openai.com 直抓 403，经搜索页原文快照核验]`
作者验证：93 名开发者标注 1699 题，发现 **61.1% 题目的测试"可能错判正确解法"**，**38.3% 题面欠规格**。
局限：编程题，非开放对话。
本地含义（重要，双向）：①程序分/单测式 gold 断言不能独裁，否则会错杀合理回复；②"程序分与语义无关"也不能反推——必须先修测试再谈相关性。**这条直接约束我们不能靠加检查点数量来制造区分力。**

**A4 EvalPlus 弱评分器假阳性** `[子检索]` arXiv:2305.01210。
作者验证：把测试扩充约 80 倍后，pass@k 下降 **19.3–28.9 个百分点**。
本地假设：我们的 gold 断言集越稀疏，越容易虚高。修题的方向应是**加强断言的对抗性**（隐藏输入、时序变化、等价实现仍要过），不是加题数。

**A5 pass^k 与运行方差** `[子检索]` τ-bench arXiv:2406.12045；Adding Error Bars to Evals arXiv:2411.00640。
作者验证：τ-bench 用 **pass^k = 连续 k 次全部成功的概率**，GPT-4o 在 retail 域 **pass^8 < 25%**，而单次通过率远高于此；Error Bars 主张题层 + 运行层两层方差、机制比较必须配对 + 重复运行。
本地假设：晋级必须看 pass^3（同题面三次全过），均分与单次通过只作筛查。**温度 0.7 的聊天 harness 天然高方差，这条对本项目尤其致命——很可能现在的"通过"里有大半是运气。**
反例：k 越大对随机性越敏感，可能把"偶尔能做好"误判为"机制不行"，所以要与失败行为可复现性并看。

**A6 成本必须进晋级门** `[已亲验]` arXiv:2407.01502《AI Agents That Matter》(Kapoor/Stroebl/Siegel/Nadgir/Narayanan)。
作者验证（摘要原文）：现有 agent 基准与评估实践存在若干缺陷，主张**准确率与成本联合优化**，指出**holdout 不足导致过拟合**、缺标准化导致不可复现。
本地含义：本项目"质量 +50% 且 token/时间不明显退化"的双条件与此一致；另外**开发集上反复调机制本身就是过拟合风险**，封存题只开一次的纪律有外部依据。
**引用纠错**：本册初稿曾把本文标为 arXiv:2402.01580（子检索给的编号），经主控核对，正确编号为 **2407.01502**。旧编号不得再引用。

**A7 泄露与"假提升"** `[子检索]` SWE-bench Pro Verified arXiv:2609.08149。
作者验证：封堵文件系统 / git 历史 / 网络 / 元数据四类泄露后，某模型报告成绩**下降 21.5 个百分点**。
本地假设：聊天 harness 的同类风险是**评分依据泄漏进候选可见输入**（rubric 关键词、gold 片段、参考答案措辞）。必须在装配阶段做"候选可见输入 = 真实消息 + note + 意图 + 时间戳，永不含 gold"的字节级核查，并把任何分数回落如实登记。

## B. 机制收益的量级参照（决定 ≥50% 目标现实与否）

**B1 单 agent 能力饱和后，协调收益递减甚至转负** `[已亲验摘要页]` arXiv:2512.08296《Towards a Science of Scaling Agent Systems》(Yubin Kim et al., 2026-04-08)。
作者验证（摘要原文）：协调收益在**单 agent 基线超过一定水平后呈边际递减**；跨度为"**可分解金融推理 +80.8% → 顺序规划 −70.0%**"；**无集中验证的架构比有集中协调的架构更易传播错误**。
本地含义（三条，全部可检验）：
① 若基线已饱和，任何"多候选/多人"机制只会付成本——**这正是我们现在看到 token +63%~+293% 而质量零 gains 的原因**；
② 任务结构决定机制上限：**可分解**才值得并行，**顺序依赖**加人必负；
③ **必须有验证环节**，否则多路产出互相污染。
局限：编程/推理基准，非一对一聊天；R²≈0.5 量级的预测力说明"任务结构判断"本身会失灵。

**B2 去中心化共享上下文可拿到大幅收益** `[已亲验摘要页]` arXiv:2606.10662《Decentralized Multi-Agent Systems with Shared Context》(DeLM, Yuzhen Mao et al.)。
作者验证（摘要原文）：DeLM **用"共享上下文 + 任务队列"取代主 agent**，准确率**最高提升 17.5 个百分点**，速度**最高 2.49 倍**。
本地假设（本轮机制设计的第一个候选族）：聊天 harness 里对应的是**去掉"主会话什么都自己拼"的做法，改为共享证据工件（活跃事实条目 + 未回收钩子 + 当前关系状态）+ 任务队列（意图驱动的装配分支自取）**；收益同时体现在质量与等待时间。
**诚实标注**：子检索曾报"Pass@4 +9.3pp、成本约 −50%"，主控只核到摘要级"up to 17.5 points / 2.49x faster"，表格数值未逐字核对，故本轮**只引用 17.5pp / 2.49x** 这两个已亲验数字。

**B3 多代理失败分类学：失败主因是设计而非模型** `[子检索]` arXiv:2503.13657 MAST。
作者验证：1642 条轨迹、7 框架，14 种失败模式分三类（系统设计 / 智能体间错位 / 任务验证）；针对性干预把 ChatDev 从 25% 提到 40.6%（**+15.6pp**）。
本地含义：聊天 harness 的"任务验证缺失"类对应**回复发出前没有自检门**（事实/主体/时间/该不该回）。干预收益 +15.6pp 是外部可参照的"改设计"量级。

**B4 judge 与人类一致性有上限且有系统偏差** `[子检索]` arXiv:2306.05685 MT-Bench/LLM-as-a-judge。
作者验证：GPT-4 judge 与人类一致率 >80%（接近人际一致），但存在**位置偏差、冗长偏好、自我增强偏差**。
本地含义：与我们既有纪律一致——judge 只辅助筛查，不单独判生死；且**任何"更长更详细就更优"的评分倾向都会把机制推向灌水**，必须在 rubric 里显式防长偏。

**B5 归因不可靠 ⇒ 边界必须前置** `[子检索]` arXiv:2505.00212 Who&When。
作者验证：127 条系统轨迹，LLM 找"责任 agent"最好 53.5%，找"决定性步骤"仅 14.2%。
本地含义：不要指望事后让 judge 说清"这条回复为什么差"。**写权限/可见性边界要在装配时硬约束**（例如记忆条目的来源与时效字段缺失 = 禁止注入），而不是靠事后评审。

## C. 对话记忆/知识机制与"何时回、要不要回"

**C1 LongMemEval** `[子检索]` arXiv:2410.10813 表3/§5。
作者验证：500 题、40–500 会话、六类能力（含 knowledge-update、temporal-reasoning、abstention）。**会话级检索 acc 0.670 优于轮级 0.615**；索引/检索/读三阶段优化后 0.714（**+4.4pp**）；**时间感知查询扩展把 recall 提到 +11.3%**；商业助手与长上下文 LLM 相对"新记忆更新"掉约 30%。
本地假设：记忆写入单位应是**完整交流单元（会话段）**而非单轮；检索词要带时间扩展。反例：更细的轮级检索更差（我们 M2 曾按 N=2 条注入，方向需重测）。

**C2 HaluMem（记忆幻觉三段记分）** `[子检索]` arXiv:2511.03506（EMNLP26 主会）。
作者验证：把记忆错误拆到 **提取 / 更新 / 问答** 三段分别记 acc、F1、memory integrity。Mem0 Medium 完整率 42.91%、QA 53.02%；**Long 完整率 3.23%、QA 28.11%**；主要错误类型是遗漏，且**助手自己编造的细节被当成用户事实写入**。
本地含义（最大的一条头部空间候选）：**"旧事重提/主体张冠李戴"是可分段量化的**，且长记忆下完整率可以低到个位数百分比——若我们按此重建断言，基线自然掉进可优化区间。同时它给出机制方向：写入时必须区分"用户说的"与"助手说的"，并按来源标记。

**C3 Mem0** `[子检索，全文此前已读，本轮核到表]` arXiv:2504.19413。
作者验证（自报）：**全上下文 J=72.90 高于所有记忆系统**（Mem0 单跳 F1 38.72、多跳 J 51.15；Mem0g 时序 J 58.13），但 **p95 17.1s vs 1.44s（−91%）、注入 token 26,031→1,764（−90%+）**；操作用 ADD/UPDATE/DELETE，旧事实标失效而非删除。
本地含义：**结构化记忆卖的是代价，不是质量**；在我们 17770 装不下全史的约束下，它的价值在于成本与延迟——这正好是"质量相当而资源数量级下降"的合法晋级路径（§0 完成标准）。

**C4 A-MEM** `[子检索]` arXiv:2502.12110 表1/表3。
作者验证：6 种 backbone 上优于 MemoryBank/MemGPT/LC-UDA；消融显示"链接生成"与"记忆演化"各有贡献；每题约 1.2k tokens vs 16.9k；多跳 ROUGE-L 44.27 vs 基线 18.09（小模型）。
**局限（关键）**：**没有时间戳与失效策略**，不能用来支撑"防旧事重提"。

**C5 压缩与注入位置** `[子检索]` Lost-in-the-Middle arXiv:2307.03172（U 形退化）；LongLLMLingua arXiv:2310.06839（**4× 压缩下 NQ +21.4%**，LooGLE 成本 −94%、延迟 −2.6×）。
本地假设：上下文分区 + 关键约束前置（M4）在外部有质量与成本**同时**改善的先例，但属客观 QA 场景，迁移到聊天需本地验证。

**C6 人称/视角** `[子检索]` Persona drift arXiv:2402.10962（**8 轮内可测漂移**；split-softmax 稳一致性但**降 MMLU**=能力-人设权衡）；RPT 视角转换 arXiv:2501.09265（12 个**主观**任务、多个基座，**+3.27~4.56pp**，客观任务无收益）。LongMemEval 把 single-session-**user** 与 single-session-**assistant** 分列，支持"记忆按说话人分池"。
本地结论：**"你我他代换"机制只对主观/人际类有效且量级 ≈+4pp**，不得指望它带来 50pp；但"按说话人分池"是防主体张冠李戴的结构改动，优先级更高。

**C7 "何时回 / 要不要回"最像能达标的机制** `[子检索]` Timely Response / TimelyChat arXiv:2506.14285（324 段对话）：**专用小模型 Timer-3B F1 0.79 vs GPT-4 提示法 0.33**。另 Inner Thoughts arXiv:2501.00383 人评含"时机恰当性"维度。
本地含义：这是外部证据里**最接近"绝对提升 ≥50 个百分点"量级的机制级改动**（+46pp），而且它属于"把判断从 prompt 挪进机制"——完全符合 §-1 ⑤"机制 >> prompt"。它同时是成本机制（少发无谓回复）。

**C8 广撒网/择优的真实前提与反例（对用户点名机制 (b) 的判决性证据）**
- 正例全部依赖**可执行验证器**：Large Language Monkeys arXiv:2407.21787（SWE-bench Lite 15.9%→56% @250 样本，**coverage 必须靠验证器才能变成准确率**）；Self-Consistency arXiv:2203.11171（GSM8K +17.9pp，**要求唯一正确答案**，自由文本不适用）；Let's Verify Step by Step arXiv:2305.20050（过程监督 78% MATH）；Snell arXiv:2408.03314（compute-optimal 比朴素 BoN **高效 >4×**，策略取决于验证器强弱）；BoN-RL-V arXiv:2412.15287（pass@32 60.0→67.0，并明示**验证器对噪声敏感、会误选**）。
- 反例三连：arXiv:2403.02419（调用数增加**先升后降，非单调**）；arXiv:2407.10457（**greedy 在多数任务上优于温度采样**，"多样性候选"前提不牢）；Self-Refine arXiv:2303.11366（无外部反馈时自我改进有限且有自我偏好）。
- 选优裁判不可靠：MT-Bench arXiv:2306.05685（与人一致 >80%，但**换序仅 65% 一致**）；arXiv:2305.17926（仅换位置就让 Vicuna 在 **66/80 题**上"胜"ChatGPT）；LC-AlpacaEval arXiv:2404.04475（控长后相关 0.94→0.98，**长度本身是混淆项**）；arXiv:2410.21819（自评自的 self-preference/perplexity 偏差）。
- **本地实测同向**：`logs/phase1a/vote_sim.json` 同序 3 重复 25/100 选项翻转，5 位置轮转仍 33/100 翻转。
- 结论：**"生成多条、judge 按口味择优"被外部与本地证据共同否决**（同基座自生成+自挑选的误挑率量级 30%+）。可保留的是**"多条候选 + 程序可判的硬边界否决式筛选"**：只用事实/主体/时间/禁区一致性这类可判据否决不合格候选，不做好者择优；这与 §10"合法多样性不靠唯一措辞"一致。

## E. 本轮导出的设计规则（取代上一版 D 节）

1. **量尺重建是硬前置闸门**（§-1 ①）：现有均分口径已饱和且负对照同分，**在此之前禁止新增机制候选、禁止做任何晋级判决**。重建四件事：
   a. **断言级区分度**：对每条 gold 断言算 r_pb（该断言得分 vs 候选总分），删 DI=0 与负区分断言；难度带压进 p∈[0.2,0.8]。
   b. **负对照必须显著掉分**：无记忆、全量复述两个负对照若与主候选同分 = 该请求位不进质量池。这是比"空目录 0 分"更强的双向校准。
   c. **0/1 改分档加权**（HealthBench 型 criteria + 权重），并按 §-1 要求保留"合理多样性"：primary / backup / 合法不回答 三槽分审，`gold={}` 不记通过。
   d. **探针密度 ≥1/10 轮**（已登记旧要求，落实为硬门）+ 召回关键词不得出现在当轮消息。
2. **judge 上岗双指标**：与人工的 α≥0.80（0.667–0.800 只支持试探）**且**合格保留率达标（当前 65.8% 不过线）。judge 只做初筛，不单独判生死；换 judge 版本 = 换考场，历史分数钉版本戳不纵向比。先补"合法 no_reply / 新提议"锚点题再谈收紧。
3. **稳定性口径改 pass^3**（同题面三次全过），并报配对差 + SE + 相关（同题得分相关 0.3–0.7，配对是免费方差削减）。
4. **机制族取舍（据 C 节）**：
   - **否决**：广撒网 + judge 口味择优；温度多样化当唯一多样性来源；堆检索条数/塞满上下文；纯 prompt 判"是否回复"；解码级人设约束（牺牲能力）。
   - **优先做**：①**回复时机/是否回复的专用判定机制**（外部 +46pp，是唯一接近 50pp 量级的机制族）；②**记忆按说话人分池 + 来源/时效/失效（UPDATE/DELETE 而非堆叠）**（针对 HaluMem 型完整率坍塌）；③**会话单元写入 + 时间感知检索扩展**（+11.3% recall）；④**压缩注入 + 关键约束前置**（质量与成本同时改善的先例）；⑤**硬边界否决式候选筛选**（只否决不择优）。
5. **关于"≥50%"的诚实判定**：外部同模型 harness/机制层改动集中在 **+3~+20pp**；**+40~+46pp 只在两类情形出现**——有可执行验证器的采样扩展（成本 ×250，聊天不适用）与**把提示判断换成专用判定模型**（回复时机）。因此：**整体聊天质量的绝对 50pp 提升在当前证据下不现实；"严重错误族（记忆污染/张冠李戴/该回不回）相对下降 ≥50%" 与 "token/等待 ≥50% 降幅" 是现实且已达成的外部实例**（Mem0 p95 −91%、token −90%+）。
   本轮执行方式：**先把难度校准后的质量池做出来，再用同一个 50% 门槛去撞**；若经验上限低于门槛，如实报告上限、失败方向与已达成的族级 50% 结果，**不修改判停口径、不换分母**。是否把"≥50%"正式改写为"分层指标"由用户裁决，未裁决前按原文口径执行。

# LoveBrain 公平基线与 harness 重构指导书

日期：2026-10-23。面向本地 worker。依据本轮对 `D:/LoveBrain` 与斗兽场当前文件的只读检查，不是新的训练结果。

## 1. 本轮目标与判决

用户要的是：保留原版有用的能力，重构出回复更可靠、上下文更干净、token 更省、等待更短、维护更容易的完整 harness。这里的“训练”主要是迭代 harness 的机制与提示词，不是声称修改了 dsf 模型权重。

**公平基线必须是原版实际能力的忠实适配，不是删掉难移植部分后的弱化版。候选可以换架构、合并或删除机制；不必照搬原版的复杂度。**

本轮结论：当前 `reference_product_v1` 已补跨轮提交与下一轮读取，可以做有范围声明的开发诊断；尚不足以承载“已经全面超过当前原版”的结论。先一次补齐会改变当前比较结果的差异，再进入真实父子比较。不要为此重建考场、部署账户或重做安卓界面。

原版检查基准：`D:/LoveBrain`，分支 `main`，commit `176e521c269efed4bb8b00f6c52a48993463a724`；检查时已跟踪文件无未提交变更。未据此断言未跟踪文件也为空。完整来源散列见本目录证据 JSON。

## 2. 当前基线的四个实质性差异

### 2.1 跨轮闭环已补，不能沿用旧指控

当前 `mechanism.py` 已读 `product_memory.read_all`、解析本轮 analysis、调用 `record_round`，并在下一轮读取文件。原版依据是 `LoveBrainViewModel.nextRound → TopicRecorder.record`。

因此撤回“当前版本完全没有跨轮记忆”的表述。本轮独立重跑已有 7 项离线闭环夹具，7/7 通过，检查期间相关源码散列稳定。已有夹具只能证明这些覆盖路径，不能自动证明其余 Kotlin 行为全部等价。

### 2.2 预算裁剪尚未进入主请求

原版 `PromptBuilder.buildReplyUserPromptWithRefs` 调用 `PromptBudget.byBlocks`；当前参考入口仍直接拼接 knowledge/scene/intent/note/chat/time。

原版 `TOTAL_BUDGET=9000` 是 user 文本的 UTF-16 长度目标，**不是 9000 模型 token，更不是整个请求的严格 token 上限**。原版按知识、旧 recent、聊天整行等优先级裁剪；它自身的边界问题也应保留并登记。

必须补同义的原版裁剪和裁剪后引用处理。候选战胜一个未裁剪的参考实现，不能据此宣称比原版省 token、污染少。

### 2.3 知识过滤与装配仍有偏移

原版 `PromptKnowledgeSection.build` 对画像、经验、状态链、事项执行逐条纠正过滤；当前 `_knowledge_block` 虽读取 `corrections`，实际拼接中未使用这份变量完成对应过滤。不能以“纠正存储函数通过”代替“被纠正内容已从真实请求移除”。

原版另有 `LessonDoc.purify`、阶段资产的当前阶段提取、可选 aggressive 注入。参考实现目前主要读取种子字段，不能默认种子字符串与这些行为等价。默认关闭的开关可在首批不测，但须锁定配置，不得在全面结论中隐去。

本轮散列实查：参考 core/naturalness_check/redline/format 四份资产与当前原版逐字节一致；参考资产目录没有 stage.md、aggressive.md。前四份提示词无需为本次复核重抄，后两项按实际模式范围接入。

时间段也有直接差异：当前原版 `buildTimestampPrompt` 包含当前时间与判断约束；参考 `_timestamp_block` 使用简化的标题加时钟。先按选定源版本对齐，不要把简化提示误当原版。

### 2.4 主体、恢复及后台能力明确未完整移植

`product_memory.py` 已明确省略 `FactSubjectResolver` 的主体解析、跨文件 WAL 恢复、话题归档事务与知识库重估触发。

说话人和事实主体不是一回事：同一个 HER 可以谈自己、ME 或第三人。“只有一个 speaker”不能证明省略 subject 不影响替换、纠正和污染。涉及这些能力的比较必须补齐或单列未验证。

后台重估不是安卓 UI 附属物：原版话题轮换后可触发关系维度、经验和画像建议，影响后续输入及成本。纯回复试考可先不触发，但完整连续 harness 的最终比较必须计入。

## 3. 原版机制清单：先借鉴语义，再决定实现

下表不是要求每轮都调用所有机制。各机制只在原版实际条件下触发；未触发的能力不凭空加调用。

| 机制族 | 原版有用的行为 | 参考基线要求 | 候选允许怎样重构 |
|---|---|---|---|
| 输入与来源 | HER/ME 与 IDEA 分开；冻结消息、别名映射 | 保留来源身份和真实时间；备注不冒充已说话 | 统一事件结构、减少转换层 |
| 意图与本轮备注 | 有效意图与私下军师备注分通道；旧终态兼容 | 对齐实际 `isIntentEffective`，不只信注释 | 结构化目标、作用域与冲突优先级 |
| 画像、阶段、表达偏好 | 我/她/关系/风格；当前阶段；可选模式 | 相同初始信息、相同开关；不得漏或添 | 只选当前相关片段，减少常驻背景 |
| 系统资产与输出 | core、naturalness、redline、format；解析回复 | 冻结实际资产和有效配置 | 重写提示、重排输出，但保持约定交付用途 |
| 短期上下文 | chat 窗口、最近两轮、轮转后归档 | 保持原版窗口及更新时机 | 以完整交流单元组织，消除多处重复 |
| 提交与真实历史 | nextRound 提交冻结消息；点赞不等于发出 | 写回→下一轮实际读到；草稿不变成 ME 历史 | 单一提交入口、幂等状态更新 |
| 事实与主体 | source、speaker、subject、时效、去重 | 不因省略主体而削弱原版；无来源历史按原语义 | 证据化事实、事件与摘要分开 |
| 事项生命周期 | 事项 ID、状态链、完成取消、重开 | 状态和证据规则完整复现 | 统一状态机，提议和确认分开 |
| 事项注入 | 相关性、冷却、休眠；注入时间≠新证据时间 | 对齐 selector 与持久状态 | 更好的相关性和成本控制，不整库倾倒 |
| 四类人工纠正 | 错误/完成/静音/错人；本轮静音与持久纠正分开 | 下一次真实请求生效，撤销与 revision 一致 | 统一修正账与来源版本，少维护多套副本 |
| 上下文预算 | 分区裁剪、保护当前输入、裁剪后 refs | 补齐原版裁剪，保留其局限 | 真实 token 预算、价值选择、同事实去重 |
| 背景学习 | 每 3 话题关系维度重估；每 5 话题经验/画像 | 长程范围内按真实条件执行并计费 | 合并、缓存、按变化触发；用消融证明有效 |
| 反馈与确认 | 点赞偏好；画像建议等待用户确认 | 固定回放相同外部事件，不自动假定接受 | 少打扰、只询问高价值不确定项 |
| 可靠性与恢复 | 冻结请求、旧请求不串写、持久化/重启 | 能力对比需覆盖对应场景 | 简化存储但保留隔离、幂等与恢复语义 |
| 调用与等待 | 流式首字/候选出现；有限网络重试 | 区分原版生产策略与控制试验策略 | 降低关键路径调用、减少无效输出与修复 |
| 不同工作模式 | 仅本轮、主动开场、谈心、润色 | 不用普通回复题证明所有模式 | 按用户实际需要分入口，避免通用大提示 |

注意：原版“五维向量重估”是关系维度估计，不应被写成已经拥有 embedding 检索。原版没有的语义长期检索，也不能偷偷加给基线。

## 4. 公平比较的固定项与可变项

**固定外部条件**：同一模型服务及实际模型身份、采样与最大输出设置、题目和评审卡版本、初始画像与历史、时间与可见信息、外部用户行为、评价标准。每个 harness 拥有独立状态，故事内连续，换故事清空。

**允许内部不同**：存储格式、检索、压缩、意图处理、提示词、规则分工、调用时机与次数。调用多的方案必须把额外调用和等待全部计入；不能仅为“公平”强迫所有架构同样调用。

不能给双方预填同一份正确的中间记忆来代替完整比赛，那会隐藏写回质量差异。相同原始经历交给各自机制处理；只有单独标明的组件实验才固定中间状态。

基线既不能悄悄加强，也不能削弱。若适配器改变原版行为，记录“原行为→适配行为→影响范围”。相同采样参数仍可能有随机性，不能据一次翻转作因果结论。

### 两种测量范围，使用同一份原版身份

1. **前台受控试考**：先用现有 24 位公开 pilot 检查主回复、跨轮写读、污染及消耗。若统一为每位一次尝试、无自动重试，应明确这是共同的传输规范化，不能宣称已经测过原版完整生产可靠性。
2. **完整连续比较**：加入能触发话题轮换、纠正、背景学习和画像确认的连续故事，计入后台、重试、失败和恢复。原版依赖用户确认的地方回放同一真实决定，不能替其自动同意。

后台任务应明确调度和就绪边界。异步工作既不能免费算出，又不能为压低前台耗时永远不执行。短故事未触发后台，不足以推断长期成本。

原版当前主生成最多 4 次尝试，主要处理传输、空回复和参数兼容；得到非空正文后解析失败，不等于主链会自动多次修 JSON。画像 reflect 另有最多 3 次分级生成。两条链的调用不可混记。

## 5. 什么才算比原版更好

旧宪法 v1.2/v1.3 中“成本只报告、不作门禁”的历史选择，不能覆盖用户本轮明确提出的 token、时间与性能要求。本轮采用多目标验收；具体可接受的交易不凭空设权重。

| 结果 | 判决 |
|---|---|
| 质量提高，严重错误/污染不增，成本和等待下降 | 明确改进 |
| 质量在预登记的可接受差异内相当，成本或等待明显降低且另一项不恶化 | 效率改进 |
| 均分微升，但错人、编造、无关旧事或 token/等待明显增加 | 不准称为整体更好 |
| 明显质量提升但更慢、更贵 | 交易方案，单列代价，由用户决定是否值得 |
| 只在已看过的几个节点提升 | 开发收益，不能称泛化能力或“monster” |

“相当”“明显”须在采样前确定实际可接受幅度与样本计划。不能看到结果再挑胜利维度；也不以一个加权总分掩盖重大事实错误。

至少并列报告以下指标：

- **交付可靠性**：传输、解析、结构、动作分别统计；可用首选、可用备选数、合法不回与不该不回分开。
- **语义与互动**：事实/人物/意图/事项状态、适当自由发挥、愿发与需改、不必要追问、值得继续聊。程序满分不等于愿发。
- **污染**：无关旧事注入和实际回提分开；错误事实写入、过期/否定/错人信息复活、草稿冒充历史分开；不能靠全不记、不回提拿低污染分。
- **消耗**：全部前台+后台+重试的输入、输出、缓存 token 及 attempts；按故事总量、每个请求位和每个合格交付报告，避免只统计成功样本。未知 usage 不填 0，字符估算不冒充模型 token。价格未知不编造金额。
- **速度**：本地准备、检索、首字、首条可用候选、完整返回、提交、后台完成分别记；汇总 p50/p95/max/n，服务负载下交错比较。没有流式测量就不报首字优势。
- **使用维护负担**：用户纠正次数、干预次数、长期状态体积、重复规则与多份真相、故障恢复难度。代码行数少不自动代表优雅。

候选输出槽数/契约如果改变，先确认满足同一产品用途，不能靠交付更少的可用选项虚报省 token。多给大量无用备选也不自动加分。no_reply 属扩展能力时，另列覆盖，避免借基线未支持接口制造胜利。

本轮检查时，当前控制器的 p95 已改为真实分位数；旧“max 误标 p95”不能继续作为当前缺陷。也不能把 Python/PC 比 Kotlin/手机的本地耗时差当作机制收益。

## 6. 推荐的新架构方向：待验证，不预宣判胜利

推荐用一个清晰闭环替代不断叠规则：

`真实输入/私下意图 → 统一证据与事件 → 状态更新 → 按需选记忆并控预算 → 生成 → 验证与提交`

证据记录区分：说话人、事实主体、来源、事件时间、有效期、状态、版本，以及“真实消息/模型推断/用户确认”。原始证据尽量不变，当前状态可重建。人物画像、事件事实、提议、已确认安排不要压成无类型的一串摘要。

取用时只带当前需要的材料：当前交流、仍有效的目标/约束、相关状态与必要证据。对原聊天、recent、场景摘要、ongoing 的重复内容去重。历史数据不等于必须每轮进 prompt。

确定性工作先用本地函数完成；前台是否需要额外模型调用由收益证明，不为每个微步骤安排一次模型。后台按变化与价值触发，不能默认每轮反思。以上都是候选假设，须防止过度压缩造成漏记、错主体或失去自然语气。

原版有用的约束保留，但实现不必保留安卓 UI、完整目录树或同样数量的类。重构对象是机制组合，不是提示词里换几个形容词。

## 7. 给 worker 的一次性合并执行令

1. **固定原版身份并补公平性差异**：以本轮 commit 或用户明确选定的原版版本为准；对齐预算裁剪、知识纠正过滤、阶段/时间装配、主体处理。已补的跨轮写读保留，不重复返工。不同模式和后台触发按范围清单列明，不用普通回复题充数。
2. **一次完成最少的行为核验**：长上下文真的触发裁剪；画像/经验被纠正后下一请求真的消失；同说话人谈不同主体不互删；跨轮/重启继续读到已提交内容；输出草稿不进入真实历史。用固定输出先查行为，不烧 API 验平台。
3. **建立共同报告，复用现有题库和 runner**：每份结果同时列质量、污染、实际用量、等待和失败。已有答卷可离线重评；不用为换报告、散列、文档再跑模型。后台未覆盖就明确范围，不伪造“全部保真”。
4. **按现有授权边界执行试考**：先有可信原版成绩；候选和原版在同批交错、同输入对照，同时看相对父本和固定原版的结果。不要只做候选新批次与原版旧批次的时间对比。一次诊断合并几个同族问题，保留可归因的主假设；不要求每修一小处重新验整座考场。
5. **验证迁移后再谈晋级**：公开 pilot 找问题；用不同故事、人物、表达、意图变化、时间间隔和长期状态检验。一个故事的改写不能分进开发与封存两侧。独立保留题不向开发方暴露；若没有，就只报告开发结果。不得在机制/提示里写车次、地名等题目答案特例。

本轮任务没有新增真实调用授权。不要把本指导书当作付费调用或系统权限变更许可；沿用已有有效预算与范围，无需再创建窗口或搭建 OS 隔离。

检查覆盖当前 Kotlin 源码、参考移植和现有对拍说明，另对跨轮闭环夹具进行离线复验（结果见同目录 JSON）。未执行安卓完整构建，未调用考生模型，未修改产品代码，未读取封存题内容。

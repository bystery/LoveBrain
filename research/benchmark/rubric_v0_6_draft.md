## 0. 要修的唯一根因

v0.5 的层 1 检查点表（`benchmark/rubric.md` §2）里，记忆轴由两条**互相独立计分**的断言承担：

| id | 判定 | 权重 | veto |
|---|---|---|---|
| `stale_kw_*` | 旧事重提：gold `stale_fact_must_not` 列出的旧事关键词**零命中** | 2/条 | — |
| `must_kw_*` | 必要承接关键词任一命中 | 1/条 | — |

`stale_kw_*` 是**纯否定式断言**：一条都不记得的 harness 必然零命中、必然通过。实测后果（`refs/PHASE05_DISCRIMINATION.md`）：
GEN_t080（水杯旧事抑制）上 `neg_a_amnesia = PASS`；220 轮均分 α 9.99 / β 10.0 / **无记忆负对照 9.99** / **全量复述负对照 9.99**；探针密度只有 7/220。
也就是**量尺把"没有记忆"和"记忆很好"评成了同一个分数**。加探针数量不能修这个，因为它给分错轴。

## 1. 【新增】M-PAIR：记忆双门 item（本草案的核心）

记忆类断言不再单独计分，必须以 **item pair** 形式实例化：

```
gold.memory_pair = {
  "pair_id": "mp_<story>_<idx>",
  "recall":  {"requires_fact_id": "...", "accept_evidence_any": [...], "window_turns_back": >=8},
  "suppress":{"stale_fact_id": "...", "forbidden_keywords_any": [...], "context_must_be": "irrelevant"},
  "weights": {"recall": 3, "suppress": 2}
}
```

**计分规则**：`pair_score = min(pass_recall, pass_suppress) × pair_weight`，即**只有"记得住"且"知道此刻不该提"才得分**；两项只过一项 = 0 分（不是半分），因为两种失败都是能力缺陷而非程度差异。

三类候选必须落在不同分数上，这是 v0.6 的有效性自检（不满足即视为量尺仍失效）：

| 候选 | recall | suppress | v0.5 单独计分 | **v0.6 pair** |
|---|---|---|---|---|
| 无记忆负对照 | FAIL | PASS | 半分（免费通过） | **0** |
| 全量复述负对照 | PASS | FAIL | 半分 | **0** |
| 良好记忆+良好抑制 | PASS | PASS | 半分起 | **满分** |

约束：`recall.window_turns_back ≥ 8`（远距，避开当轮窗口）；suppress 的语境必须与旧事**无关**（否则"合理旧事回扣"被判污染，与 §10 冲突，也是外部证据 C2 HaluMem 指出的"助手自创细节被当用户事实"同类错判风险）。

## 2. 【变更】C-WEIGHT：0/1 → 分档加权 criteria（含负分项）

沿用 v0.5 的权重列，但把 `score10 = 通过权重/总权重×10` 改为：

```
item_score = clip( Σ(w_i · met_i) / Σ(w_i | w_i > 0),  floor, 1 )
```

- 每请求位实例化 **3–6 条 criteria**，每条带权重，允许 `w_i < 0` 的**严重错误负分项**（错人、编造已发生安排、禁止私有内容泄漏、已取消事项复活、该回不回、契约违例）；
- `floor = 0`，负分项触发即把该 item 压向下限，但**不掩盖**它：负分项命中单独进"严重错误族"计数（§5 报告）；
- `gold={}` 或未实例化的断言继续按 v0.5 的诚实登记：不记通过、不进分母、报告层显式说明"程序分只覆盖已实例化 N 项"；
- 分档的目的不是变严，而是**给"绝对提升 50 个百分点"提供分辨率**——现在 0/1 + 均分 9.99 之下这个分辨率不存在。

## 3. 【新增】I-CAL：题目/断言的准入与淘汰（难度与区分度双门）

每次批次后由 `tools/assertion_discrimination.py` 重算，逐断言：

- 难度 `p` = 该断言在候选集合（**含负对照**）上的通过率；
- 区分度 `r_pb` = 该断言得分与候选总分的点二列相关；
- **淘汰/重写规则**（外部依据：经典 item analysis p∈[0.2,0.8]、DI<0.2 弃用；MMLU-Pro 用"8 模型 >4 答对即太易"删 5,886 题；SWE-bench Verified 先删"会错杀有效解"的题再谈难度）：
  - `p ≥ 0.95` → `SATURATED`，出质量池，只作流程/计时对照；
  - `p ≤ 0.05` → `TOO_HARD_OR_BROKEN`，先查题面与 gold 是否可行，再决定去留；
  - `r_pb < 0` → `NEGATIVE_DISCRIMINATION`，必改（这类断言在奖励错误行为，`stale_kw_*` 单独计分就是此例）；
  - `0 < r_pb < 0.2` → `LOW_DI`，重写而非删除（保留能力覆盖）；
  - 负对照通过率 ≥ 主候选 → `FREE_PASS_FOR_NEGATIVE_CONTROL`，该 item 立即出质量池。
- **质量池健康门**（不满足则本轮不得开机制配对赛）：`p∈[0.2,0.8]` 的 item 占比 **≥70%**；中位难度 **0.35–0.6**；`median(r_pb) ≥ 0.25`。

## 4. 【新增】L-Audit：泄漏即题目缺陷，不算候选失败

- 召回类 item 若其 gold 依赖关键词（含专名、数字、近义词根）出现在**候选可见输入**内 → 记 `INVALID_LEAKAGE`，剔除分母，题进重修队列（v0.5 已在 GEN_t160 上遇到过，但只作为个案）；
- runner 侧加**字节级自检**：候选可见输入里出现内部标记（`stale_kw_`、`must_not`、`LAYERED_SCORE`、gold 字段名、台本、未来轮次）→ 该批整批作废并留证据，不改判为候选失败；
- 依据：泄露封堵后成绩回落 21.5pp（SWE-bench Pro Verified），说明"看起来的进步"里有相当比例是量尺漏洞。

## 5. 【变更】报告口径（在 v0.5 §6"每轮报告八数"上扩容为十一数）

①首次完整输出成功率 ②严重错误数与类型（按族） ③首选合格率 ④至少一个合格候选比例 ⑤含严重问题备选比例 ⑥关键记忆探针通过率（**改为 M-PAIR 双门通过率**） ⑦相对基线盲评胜/平/负（含两者均不合格） ⑧episode 成本与 p50/p95 延迟 ⑨记忆污染率 ⑩**难度带覆盖率与中位难度** ⑪**断言区分度中位数与负对照分离度（主候选 − 最差负对照）**。

**稳定性口径改用 pass^3**：晋级判决所需的"通过"定义为同请求位连续 3 次全过（τ-bench 结论：单次通过严重高估可靠性，GPT-4o retail pass^1≈61% 而 pass^8<25%）。均分只作观察值，不作晋级依据。比较一律**配对 + 交换账号/轮位 + ≥3 次复跑**，并报告配对差、SE 与两者相关（同题得分相关 0.3–0.7 时配对是免费方差削减）。

## 6. 【不变但必须重申】评分自由度与 judge 边界

- §10 评分自由度全文沿用：参考答案是**证据与合理行动集合**，允许自然确认、新提议、玩笑、调情、合理旧事回扣、合适短回复与**合法不回**；不逐字匹配、不强迫命中参考关键词；**与事实矛盾的漂亮话不得过关**。
- 回复长短不是独立扣分项（用户 2026-10-24 纠正）；judge 侧必须显式防长度偏（外部：LC-AlpacaEval 控长后与人评相关 0.94→0.98；WildBench 用"胜者比负者长超过 K 字符即改判平"）。
- judge 上岗双指标：`trap 识别率 ≥0.80` **且** `合格保留率 ≥0.80`。当前 0.658 不过线 → 未过线期间 judge 只做初筛，**不单独判死**（v0.5 §3 语义严重错误须带原文复核的条款继续生效）。
- 收紧尺子会让基线整体下移，这是**量尺修复的正常结果，不是候选退化**（外部同型：LoCoMo-Refined 严判后各系统集体掉 15–22pp）。新旧口径必须并列报告，禁止拿新尺子的低分与旧尺子的高分纵向比。

## 7. 【生效验证清单】v0.6 生效前必须全部为真

1. 用已有答卷（echo 协议层 + 真实模型层各一批）离线重评，产出新旧口径并列表；
2. **有效性自检**：无记忆负对照与全量复述负对照在质量池上的分数**都必须显著低于** α/β 主候选（预期分离度 ≥20 个百分点），否则 M-PAIR 未起作用，回 §1 重做；
3. 质量池通过 §3 健康门；
4. 泄漏审计通过 §4（受影响 item 全部剔除或重修）；
5. 每条负分 criterion 都能追溯到公开契约或既有接口（不凭空新增隐藏要求）；
6. `lb_scorer.py` 版本升到 v0.10 并在 §8 沿革里登记；v0.5 文件不动。

## 8. 本草案明确不做的事

- **不做**"多候选生成 + judge 按口味择优"的评分支撑（证据册 C8：无验证器时换序一致率仅 65%、换位可翻转 66/80 题、本地 5 位置票仍 33/100 翻转）。广撒网在 v0.6 里只保留"**硬边界否决式筛选**"——用可判定的事实/主体/时间/禁区断言**否决**不合格候选，不做"择优"。`at_least_one_pass_rate` 继续单列，但**不得**被当成"择优机制有效"的证据。
- **不加**新的自检脚本数量来冒充区分力提升（反模式：扩自检 ≠ 扩探针密度）。
- **不动** B 线（封存），不在本轮做任何真实模型批次。

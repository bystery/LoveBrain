## 机制五件套（全部确定性代码，无话题词表，无逐题答案规则）

1. **证据支持门**（写回强制）：事实文本中每个英数 token（复用 `base._alnum_tokens`，
   车次/编号/时刻等实体标识）必须逐字出现在所引用消息**原文或其时间戳**的 token 池；
   `source_ids` 空/越界 → 拒绝；违例事实**拒绝入库**（不复述、不降级），理由留痕
   `trace.fact_gate.rejected`。旧车次无法再挂"到站"这类不含它的新证据复活。
2. **全局来源键持久化**：每条事实附 `src=[{key:"case_id:mid", speaker, ts, text}]`、
   `entities`、`status`、`anchor_ts`——摘要与原始证据分开存储，可审计可追踪。
   m-id 映射只来自当前窗口真实消息（与 render_chat 编号一致），**模型草稿结构上
   不在映射表内**——"不把待发送草稿当历史"由此保证。
3. **纠正追踪**：所引证据含更正标记（改签/更正/改成/换成/不是这趟/改乘）→
   correction 事件；库内被点名的旧编号值事实标记 `superseded=true`，注入时
   **整条排除**；库内存在更正事件时，其余含编号实体的注入事实附"以最新更正为准"
   警示（覆盖"不是这趟 我改签了"未点名编号的场景）。
4. **状态推导**（确定性，不要求模型新增输出字段）：
   - `offer`：事实含约定/同行动词 且 所引证据为问句/提议 → 注入标"⚠提议未确认"；
   - `intent`：事实或证据含未来标记 → 标"⚠意向未发生"；
   - `event`：其余（默认，证据背书）。
   只有真实 HER/ME 消息能确立已确认事件；邀请（"你要看吗"）不能写成"已约定"。
5. **相对时间锚定**：事实文本含相对时间词（明天/下周/周二…复用 `_TIME_WORDS`）
   → 注入行附出处消息日期锚点（"相对时间以出处消息日 YYYY-MM-DD 为锚"），
   不把"下周"补成具体某一天。

## 已知边界（登记，不装作已修）

- CJK 语义级编造（钟点/数量/地点的无中生有）机制层不判——字面无实体可比对，
  靠生成侧提示 + 下游审计；正文字段同样不做机制级拒发。
- 更正证据未点名旧编号时（"不是这趟 我改签了"）不建立 supersession 链，
  只做注入警示（test 3a 场景）。
- `ongoing` item/state 不做证据门（format.md 契约不变；登记为受控未做）。
- HER/ME 归属检索层不可分（继承 base 登记）。

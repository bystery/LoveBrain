# MECHANISM.md — phase2_expr（表达/选择策略候选）

父版本：`candidates/phase1_retr_idf`（检索 v2.2，**已冻结**）。
**唯一主变量 = 表达/选择策略**；检索、存储、写回、编排、params、memory-off
语义全部委托父版本机制模块（同一份 mechanism.py 字节，无副本、无漂移可能）。

## 1. 表达策略（唯一新增资产 expression.md）

`assets/system_prompt/expression.md` 追加在父版本 system prompt 之后（`\n\n---\n\n`
分隔），四条规则：

1. **正文视角**（最高优先）：判据=**收信人一致**——句中"你"必须指收信人（她）。
   她问怎么应对第三方时，"你就跟她说你对猫毛过敏"是自然建议，允许；
   "她问要不要拦，你就回复她……"收信视角错位（"你"=被指导的用户），不可发送。
   孤立的"你就说/让她去"类调度句 → 改写或 null。
2. **ME 经历出处**：已发生式（"我一般/我上次"）只能陈述 kb/画像/对话里真实
   出现过的经历；未来提议（"下次带我一个"）不算虚构。
3. **他人动机**：第三方/她的动机、评价、过往行为无记录不断言；推测说成推测
   或直接问。
4. **旧事主体**：引用旧事件主语与记录一致，分不清就不引用。

保留空间明示：调侃/温柔/暧昧不受限；no_reply/合法 null 照常；军师备注只影响
怎么想、不进正文。

## 2. 生成后词面审计（expr_trace.jsonl）

每轮生成后对可发送正文（response 四槽 + directions 非 null）运行四族词面
检测器（**含 F4**，与 `tools/expr_audit.py` 模式+标签同源，回归断言一致）：

- F1 军师视角 / F2 ME 经历编造 / F3 他人动机断言 / F4 旧事件回指 → 命中记
  finding；F1 首模式为"建议或指令句式—收信人一致性需人工判读"（自然建议句
  不凭句式定罪，v9 复核 §3.3）；F4 主语核对登记为 manual_review（判读环节
  人工执行）。

### 注入方式（v9 复核 §3.1 修复）

表达块注入为**作用域限定**：`run_turn` 调用期间临时替换
`lb_assembly.build_reply_prompts`、finally 恢复原函数——模块重复加载不叠加
（同进程任意次运行每请求恰 1 份表达块）、同进程先后运行的 A1/A2 臂零污染、
全局函数无永久副作用（回归 test_expr_candidate.py A5/F 组断言）。

政策（与 retrieval_trace 一致）：评估专用、不入快照、不注入请求、不改写回复、
落盘失败不阻断对话。**命中 = 可疑标记非定罪**；真人感是否改善由三臂对照的
生成结果判定，不因提示已写入而宣称。

## 3. 契约与写回

与父版本逐字节一致：string|null（directions 元素）、合法 analysis 独立写回、
analysis 非 dict 留痕不崩溃。"失效/替代"式写回（如纠正后不再召回旧计划）父版
本即未实现，本候选同状态（登记，不冒充已修）。

## 4. 已知限制（登记）

- 词面检测器召回/精度有限：F2"我上次"可能是合法经历（需人工判读出处）；
  F1/F3 模式覆盖常见句式但非穷举。三臂对照时以判读为准、检测器为粗筛。
- JSON 结构保障未实施：生成层 JSON 语法错误（历史 A2-t6/B2-t5 类）仍可能
  发生，评分层按 json_parse_error 记 0（v0.9.2 口径）。
- expression.md 为 prompt 级约束：无硬解码保障；其效力数据待三臂对照。

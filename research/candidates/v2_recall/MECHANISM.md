# v2_recall — 机制说明（MECHANISM.md）

父本：`candidates/reference_product_v1`（原版 LoveBrain 保真等价实现，首场基线）
本代假设：**首场最伤的语义失败不是模型记性差，是检索没把记忆递过去。**
主变量：M2 记忆检索与注入（回忆型提问的检索路径）。存储结构、输出契约、措辞资产一律不动。

## 1. 存储（未改）

沿用父本六投影：`moment/topic.md`、`moment/recent.md`、`moment/scene.md`、
`moment/plan.md`、`memory/raw_chat.md`、`memory/raw_topic.md`。
本版**只读**归档文件，不新增任何存储字段。

父本 2026-10-23 的同批修复（不属本版能力，属基线纠错）：
话题轮转按 `KnowledgeArchiveService.archiveEntry` 落完整条目（话题名＋状态变化＋对话记录），
不再只落标题；`write_file` 与 `path()` 的 `memory/` 前缀映射改为一致（否则 `_append`
永远读到空串、二次归档覆盖一次）。

## 2. 检索（本版唯一改动）

判定：HER/ME 真实消息命中回忆标记（`上回/上次/之前/怎么说/还记得/记不记得…`）。
命中后三件事：

| # | 动作 | 依据 |
|---|---|---|
| 1 | 进行中事项**跳过关键词门**，ACTIVE 全量注入 | 父本默认拒绝 + 只比 item 名关键词；"陶瓷杯"对不上"杯底/店里"，E001_T06 该事项被整条过滤 |
| 2 | 从 `memory/raw_topic.md` 取最相关的 1–2 个话题块，以 `# 【回忆】` 段注入 | 轮转后正文已归档，可检索；父本从不回读归档 |
| 3 | 相关度用 2-gram 字符重合（标题权重 3、正文 1），**先剥掉回忆标记本身** | 标记词也是归档正文常见词（"你上回做的那个杯子"），不剥会命中任意历史块 |

默认拒绝（fail closed，与父本一致）：零重合不注入；非回忆轮不注入（宁可漏，不许灌）。
单轮召回上限 2 块 / 1200 字符。

## 3. 意图（未改）

沿用父本的 note/备注块、`infer_scene` 场景段、意图块。**已知未改的缺陷**：
`_CONFLICT_KW` 含"又来"，"店里又来问…"被判成"争执"（E001_T06 实测）。
改它会与本版主变量混在一起，登记为下一轮候选，见 `logs/exam1_20261023/EXAM_REPORT.md §6`。

## 4. 上下文组织（未改）

六段顺序、标题、措辞全部沿用父本；`# 【回忆】` 段追加在知识段尾部（短 prompt 下靠近
`<chat>`，属于高显著位）。不改分区、不做摘要压缩。

## 5. 验收（离线，零 API）

`tools/test_v2_recall.py` —— 用首场录制的原始回复重放，只验输入侧：

| 检查 | 断言 |
|---|---|
| c1 | E001_T06 prompt 出现"杯底/刻字/不刻"且挂上【回忆】 |
| c2 | 只有第 6 轮注入，其余 7 轮不注入（无误报） |
| c3 | 有回忆标记但归档零重合 → 不注入 |
| c4 | 同一题：父本无【进行中事项】、v2 有（旁路生效，且只在 v2 生效） |
| c5 | E003 无回忆型提问 → 8 轮 prompt 与父本**逐字节相同**（不污染无关轮） |

当前：5/5 PASS（`logs/v2_recall_result.json`）。

**不能由这些断言推出的结论**：v2 的回复分数会更高。输入侧修好了不等于模型会用，
必须新授权实跑 24 位才能谈分数。

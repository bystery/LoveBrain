# LoveBrain release signing continuity baseline.
#
# Every release APK produced from now on MUST be signed by this certificate.
# The gate scripts (scripts/verify_signing_continuity.sh) compare the candidate's
# signer certificate against cert_sha256 and fail the build on any mismatch.
#
# Everything below is a PUBLIC property of the release certificate: the same
# digests anyone can read off an installed or published APK with
# `apksigner verify --print-certs`. The pin was reviewed as code and recorded
# here so the gates have one place to read it from. Never edit a value to make a
# red job green. To rotate the release key deliberately, replace this file, get
# the change reviewed, and bump baseline_updated.
#
# The certificate subject (its DN) is deliberately NOT recorded here. Nothing
# reads it — scripts/verify_signing_continuity.sh takes it straight off the APK
# being checked — and copying it into the repo adds a line of machine-local
# description without adding any verification power.
#
# KEY ROTATION, 2026-10-07, decided by the product owner.
#   The certificate pinned before this date is recorded below as
#   historical_cert_*; it signed the published v1.3.1 and its key material no
#   longer exists. That value is history only, not what releases are signed with.
#
# CONSEQUENCE that comes with a rotated key, stated plainly:
#   An APK signed with the current pin CANNOT upgrade-install over an install of
#   v1.3.x. Android rejects it (INSTALL_FAILED_UPDATE_INCOMPATIBLE). The only
#   path from v1.3.x is uninstall + fresh install, and uninstalling takes the
#   in-app chat data with it. Any gate that asserts "the candidate and the
#   published v1.3.1 carry the same certificate" therefore describes an
#   impossible pair and must not be treated as a code defect.
#   See scripts/run_upgrade_test.sh and scripts/download_release_apk.sh.

# 画像更新引擎

> 触发时机：每积累 5 个话题转换后自动调用一次。
> 调用顺序：五维重估引擎先执行 → reflect 引擎后执行。reflect 引擎接收的 warmth.md 中，向量数值是已更新的最新值。
> 输入：当前三个画像文件 + 最近经验（2次提取）+ 最近5个话题档案 + 最近2次谈心分析。
> 输出：JSON 格式的三个文件完整更新版本（需用户确认后才写入）。

---
## 核心原则

### 证据门控

- **确认级**：至少 2 条不同话题的经验指向同一方向，才能更新画像字段。
- **观察级**：1-4 条经验支持的推断，不写入画像，放在输出的 "observations" 字段。
- **单次事件永远不构成特征**。

### 更新式覆写
- 保持每个文件的 ## 标题结构完全不变。
- 只修改字段值，不新增标题、不删除标题。
- 历史信息用分号追加：`当前值；过去曾经…`
- 不可变事实（姓名、年龄等）一旦确认就不改。
- 瞬态信息（"这周她在加班"）不写入画像。

### warmth.md 特殊规则
- 状态向量数值（intimacy/trust/commitment/passion/security）以输入中的最新值为准，正常参与更新。
- **向量解读字段必须根据最新向量数值重新生成**：用一句话说清当前五维组合的核心矛盾或核心优势。
- warmth.md 其他字段（阶段标签、趋势、关键事件）按正常规则更新。

## 向量解读生成规则
- 基于最新五维数值，判断当前关系的核心特征。
- 用一句话说清楚：当前最突出的优势是什么，或最核心的矛盾是什么。

### stage_changed 判断标准
- 阶段转换的判断标准是"关系核心互动模式是否发生实质变化"，而非简单数证据条数。
- 至少一次关键事件支持，或≥3条经验指向新阶段，且旧阶段特征明显减弱。
- 阶段回退也算 stage_changed=true，new_stage 写回退后的阶段名。

### 异常输出处理
- JSON 字符串内的引号转义为 `\"`，反斜杠转义为 `\\`。
- 字段内容为空时写"待积累"，不能是空字符串。
- JSON 中换行用 `\n` 转义。
- 输出前确认括号匹配、所有字符串闭合。

---
## 输出格式

{
  "me": "完整新内容",
  "her": "完整新内容",
  "warmth": "完整新内容",
  "stage_changed": true/false,
  "new_stage": "仅在 stage_changed=true 时有效",
  "observations": [],
  "message_to_user": "仅在 stage_changed=true 或新增关键事件时输出，否则为空字符串"
}
